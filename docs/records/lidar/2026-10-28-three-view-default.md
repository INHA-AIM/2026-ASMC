## 발견한 결함·실패 후보

첫 ROS 회귀에서 invalid 카메라 이후 확정 분류가 계속 남아18개 ROS 사례 중2개가 실패했다.
실제3뷰 근거의 관측원이 모두 무효이면 카메라 상태를 초기화하도록 고쳤다. LiDAR track 삭제나
미검출 횟수 증가는 하지 않는다. 한쪽 중단 시 다른 뷰의 유효 근거는 유지한다.

중간 구현은 매칭 token 만료까지 무조건 초기화해 정차 bag608–613의6scan에서 분류/전달 차이가
생겼다. 정상 스트림의 시각 공백과 관측원 무효를 구분하지 않은 후보라 채택하지 않았다.
현재는 스트림이 정상이고 matching만 비면 기존 이름을 유지하되 fresh 보호는 해제한다.
옛 시작 상태가 대기 결과로 복원되지 않도록 비우며, 실제 관측원 복귀 후5회 재확인을 검사한다.
초기·중간·최종 로그와 결과를 run에 각각 보존했다.

## local/map 범위

새 native runtime fixture는 전방·좌·우를 각각 단독 양성 관측으로 두고 GPS 정상→무효→복귀를
통과한다. local의 car/vehicle·8코너를 유지하며, GPS 무효 때 map은 빈 `POSE_UNAVAILABLE`,
절대속도·운동 상태는 무효다. 복귀 후 local/map ID가 일치한다. 터널 제거 알고리즘 자체의
실물 검수와 분리한 합성 기하 시험이다.

실제 정차 bag에는 GPS 무효 중 분류된 local 객체를 제공한11scan이 있다. 터널 bag에는
카메라 분류된 local 양성 사례가 없으므로 이 자료만으로 터널8종 장애물 보존을 입증하지 않는다.
GPS 무효에서 벽/천장은 내부 local 처리·diagnostics이며 별도 공용 벽 메시지를 추가하지 않았다.

후속 run `lidar-m1-final-review-20261028-r1`은 같은 M1 검증 예외 범위에서 기존4bag을 재사용했다.
[검사·재생 결과](../../../config/baselines/evidence/lidar-m1-20261027/final-review.json)를 함께 보존한다.
정본 보정의 좌→전방→우 관측 전환과, 다른 자세의 callback에서 과거 scan을 매칭하는 native 회귀를
추가했다. 기본3뷰 유지·동일 track/scan 확인1회·원본 기하 보존을 확인했다.
대기 scan마다 반복하던 영상 정렬을 호출당 뷰별1회로 줄이고 관측 token의 불필요한 박스 복사를 없앴다.

- CTest40/40, 그 안의 MultiCameraFusion13개 사례 통과. 정본 launch 해석4개 통과.
- 정차713·직진708·터널712·안개715, 총2,848scan의 동작이 승격본과 동일했다.
  이번 p95는 각각5.274/3.395/7.117/4.942ms지만 병행 검사와 사용자 부하를 통제하지 않아 추가 개선율로 해석하지 않는다.
- 독립 ROS master에서 debug OFF·웹/trace/RViz 미구독·판제 단독 수요의 지속 전달,
  GPS0/local 유지/map 보류·복귀, reset·생산자 재시작·IMU 중단/복귀를 확인했다.
- 일반 autonomy 기본 입력은 이미 `planning_observations_map`이었다. 수집용 launch에 남은
  `tracks_map` override는 메시지 타입이 달라 제거하고 공통 기본값을 상속하도록 고쳤다.
  판제 행동·속도·필터 정책은 바꾸지 않았다. 호출별 source 선택 옵션도 추가하지 않았다.

첫 로컬 검사 호출에는 임시 source mirror의 planner launch 누락과 ROS 환경 미적용이 있었다.
시험 준비를 수정한 뒤 전체 검사를 다시 수행했다. 코드 성공으로 계산하지 않은 초기 로그도 보존한다.
조회 당시 운영 master에는 브릿지만 있었으므로 현재 자율주행이 실행 중이라는 의미는 아니다.
새 주행·데이터 수집·운영 노드 종료는 하지 않았다.

## 실행파일 일치 후속 확인

RANSAC 반복 출력의 이전 조사에서 확인한 구 실행파일·새 YAML 혼용을 work에서도 대조했다.
`19be0eed`의 work는 PR #119를 포함하며, 컨테이너 M1 mirror의 원본 manifest 192개는
host work와 mirror 양쪽 모두 SHA가 일치했다. M1 실행파일에는 GPS 기반 `TunnelRoute`와
`MultiCameraFusion`이 함께 포함돼 있다. 이전 터널 수정의 재적용이나 임계값 변경은 필요하지 않았다.

조회 당시 사용자 실행은 M1 YAML을 지정했지만 `/root/ws`의 main 실행파일을 사용했다.
그 실행파일에는 앞서 재빌드한 GPS 터널 분기는 있으나 M1 3뷰 코드는 없다.
별도 M1 빌드 완료와 현재 프로세스의 M1 적용 여부를 구분한다. 실행 경로만 출력하는 명령으로
underlay와 M1 환경의 서로 다른 실행파일 선택을 확인하고 [실행 안내](../../../src/asmc_lidar/docs/three-view-fusion.md#빌드와-실제-실행파일-확인)에 반영했다.
기존 프로세스를 종료·재시작하거나 새 주행을 실행하지 않았으며, 올바른 M1 실행파일로
재실행한 뒤의 실제 경고 빈도와 주행 수락은 이 읽기 전용 확인의 결과로 주장하지 않는다.
