## 발견한 결함·실패 후보

첫 ROS 회귀에서 invalid 카메라 이후 확정 분류가 계속 남아18개 ROS 사례 중2개가 실패했다.
실제3뷰 근거의 관측원이 모두 무효이면 카메라 상태를 초기화하도록 고쳤다. LiDAR track 삭제나
미검출 횟수 증가는 하지 않는다. 한쪽 중단 시 다른 뷰의 유효 근거는 유지한다.

중간 구현은 매칭 token 만료까지 무조건 초기화해 정차 bag608–613의6scan에서 분류/전달 차이가
생겼다. 정상 스트림의 시각 공백과 관측원 무효를 구분하지 않은 후보라 채택하지 않았다.
현재는 스트림이 정상이고 matching만 비면 기존 이름을 유지하되 fresh 보호는 해제한다.
옛 시작 상태가 대기 결과로 복원되지 않도록 비우며, 실제 관측원 복귀 후5회 재확인을 검사한다.
초기·중간·최종 로그와 결과를 run에 각각 보존했다.

## local/map 범위

새 native runtime fixture는 전방·좌·우를 각각 단독 양성 관측으로 두고 GPS 정상→무효→복귀를
통과한다. local의 car/vehicle·8코너를 유지하며, GPS 무효 때 map은 빈 `POSE_UNAVAILABLE`,
절대속도·운동 상태는 무효다. 복귀 후 local/map ID가 일치한다. 터널 제거 알고리즘 자체의
실물 검수와 분리한 합성 기하 시험이다.

실제 정차 bag에는 GPS 무효 중 분류된 local 객체를 제공한11scan이 있다. 터널 bag에는
카메라 분류된 local 양성 사례가 없으므로 이 자료만으로 터널8종 장애물 보존을 입증하지 않는다.
GPS 무효에서 벽/천장은 내부 local 처리·diagnostics이며 별도 공용 벽 메시지를 추가하지 않았다.

## 남은 제한과 배포

F1 공급473.47ms 실패·초기 입력 공백·얇은 barricade 소실·전 클래스 실제 보존 검수는 남는다.
이번 PR은3뷰 확장·연산·연결 계약까지다. 미연결2D 기반3D 복구, 벽 폭 사전정보는 별도 PR로 검증한다.

사용자 컨테이너의 `/root/asmc-m1` LiDAR overlay를 갱신해 기존 `lidar.launch` 기본 명령이3뷰를
선택하도록 준비한다. host 편집 정본은 `2026-ASMC-work`, underlay `/root/ws` 마운트는 유지한다.
이미 실행 중인 사용자 노드는 중단하지 않는다. 실행 중 바이너리는 사용자가 재시작해야 새 설정/코드를 쓴다.
컨테이너 재생성 시 overlay 재구성이 필요하고, 병합 후에는 main 빌드로 통일한다.
