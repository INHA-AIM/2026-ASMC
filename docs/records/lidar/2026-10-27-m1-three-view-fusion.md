## 구현과 수정한 결함

1. 현재 실제 제외와 예측 track의 마지막 관측 제외를 구분했다. 예측 표시·선택 강조·배경 지도 SHA가
   생산자의 제외 판정을 우회하지 않는다. 이력은 살아 있는 track만 유지한다.
2. 점의 도로 위치와 객체의 전달 사유를 분리했다. 도로 밖 보호 객체의 점도 회색이며,
   지도·pose 무효는 노랑이다. 터널 제거점을 RANSAC 보기에서 무조건 초록으로 반환하지 않는다.
3. 카메라별 독립 선택·투영과 track+scan 단위 분류 갱신을 구현했다. 늦은 뷰는 같은 단위의
   시작 상태에서 재집계하며, 새 scan 이후 과거 결과가 현재 분류를 덮어쓰지 못한다.
4. 서로 다른 그룹의 충돌·원본 이름 충돌·양성/빈 결과를 구분한다. 빈 측방 영상의 더 최근 stamp로
   전방 양성 근거의 freshness를 연장하던 후보 결함을 회귀 검사와 함께 수정했다.
5. 터널 후보의 투영을 기존 공용 optical 변환에 연결했다. 초기 구현에서 전방 전용 가용성 필드가
   false로 남아 모든 점을 camera-unavailable로 처리하던 결함을 수정했다.
   가용한 뷰의 실제 coverage와 미수신 뷰의 ambiguity를 점별로 구분한다.
6. 정적 보조는 MotionClassifier 한 곳에서 수행한다. KF·OBB·원시 속도는 바꾸지 않고,
   기하 입력 수집과 fusion 후 최종 판단을 나누어 이력을 scan당 한 번만 갱신한다.
   낮은 속도의 실제 이동도 양쪽 면·방향·누적 변위로 보조를 해제한다.

2026-10-27 사용자 화면의 예측 `미실행` 표시와 도로 밖 초록 점을 실제8091 HTTP snapshot과

또한 실행 중 LiDAR의 `/proc/<pid>/exe`는 `(deleted)` 상태였다. SHA는
`743be7a0784fadfcb6e9d35959973e4bec41d131d0feb92f4bee59acedf45a71`, 디스크 실행파일은
`0a2d083df099129f8a5ffe62d4ca42ad6f19cefa0a9c933261ac0809239a727f`로 달랐다.
같은 snapshot의 `map.valid=true`, `tunnel.ran=true`는 최신 소스의 pose 무효 선택 조건과
일치하지 않는다. 이 실행을 최신 코드 검증으로 간주하지 않으며 기존 운영 프로세스는 종료하지 않았다.

이번 후속 변경은 웹·회귀·설명만 포함한다.

- 전달 필터 사용 중 예측 판정 이력이 없으면 활성 제외 숨김을 우회하지 않는다.
  모든 숨김을 해제하면 미확정 예측을 검수할 수 있다. 관측 객체의 무효/보류를 새로 제외하지 않는다.
- 명시된 실제 제외는 사유가 미지원이어도 숨김을 따른다. 배경 지도 SHA 불일치도 이를 되살리지 않는다.
- 예측 표시/숨김 수를 별도로 표시하고 구 진단 필드 누락을 경고한다.
- 구조물 제거점과 RANSAC 비지면의 의미를 구분한다. 기존 초록 우회 분기는 제거된 M1 경로를 유지한다.
- Node 표시 회귀72개와 Chromium 실제 canvas/체크박스33항목을 검사한다. 기존 브라우저 검사의
  구 요약 문구와 객체 사유 색상 가정을 현재 UI에 맞추고, 예측 이력·구 생산자·재관측·점 색상 검사를 추가했다.

터널 비용은 기존 `matrix-r2/tunnel-0-{front,three}`를 읽어 추가로 대조했다. 두 실행의
voxel 점 수 p95는 모두9,215였고, 최종 cluster input p95는 전방21점/3뷰31점이었다.
따라서 최종 발행 객체가 대량 증가한 것으로 비용을 설명할 수 없다.
3뷰712scan 중422scan에는 `camera_unavailable_ambiguous`가 있으며, 표본 residual OBB에는
길이 약47–51m의 벽 형태 군집이 포함돼 있었다.

`RemoveResidualWalls`는 남은 점을 군집화하고 L-shape OBB를 계산한 뒤 카메라 보호/ambiguity를
판단하며, 이후 `ClusterAndFilter`에서도 객체를 구성한다. 올바른 optical 시야와 미도착 관측의
보수적 처리로 중간 단계에 남은 벽 점이 이 경로의 비용을 늘리는 근거다. 현재 trace의 바깥
`cluster/detection` 시간만으로 내부 군집·OBB별 비용을 분해할 수는 없다.
따라서 다음 후보는 **3뷰 후단 분류 연결과 전처리 보호 확대를 분리해 측정하고, 내부 군집·OBB의
