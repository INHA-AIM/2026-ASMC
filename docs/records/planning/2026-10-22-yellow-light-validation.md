# 노란불 정책 구현·통제 시험 기록

요청 구간의 구현과 통제 검증을 완료했다. 독립 물리 평가상 무위반 완주 18회,
정지 불가능 조건의 실패 대응 2회를 확인했다. 기본 설정은 독립 관측 모드이며,
상시 운영 적용 완료를 뜻하지 않는다. 회차·측정·소스 근거는 [결과 JSON](2026-10-22-yellow-light-validation.json)에 있다.

## 변경과 기준

브랜치는 `feature/yuntae-yellow-light-policy`, 기준 HEAD는
`19bc76978a499bddacf13f5aaf0bb6d713785657`이다. 변경은 미커밋 상태다.
기존 시계 점검과 정책 변경은 별도 계약·기록으로 관리했다.

기존 ROS 메시지 정의를 바꾸지 않고 [명령–궤적 연결](../../contracts/control-binding-v1.md)을
구현했다. Controller 세대·명령 revision·Planner 세대·계획 sequence와 실제 수락 결과를
원자적 명령/궤적 사본으로 확인한다. 최신 시각의 이전 명령 궤적만으로 제동을 풀지 않는다.

[정책 계약](../../contracts/yellow-signal-policy.md)의 25km/h 접근 명령 상한,
실측 속도·가속도 판단, 정지선 전 의도적 황색 진입 금지, 서로 다른 초록 원본 3프레임을
유지한다. 물리선/후륜축 목표·버퍼·revision, 원인별 중재, 첫 비상 출력, 기동 STOP 인계,
실제 응답 감시와 내부 복구 이탈을 연결했다. HOLD 목표가 바뀌어도 목표를 향해 다시 전진하지 않는다.

일반 STOP의 기존 감속 유지와 최대제동 강화의 추가 반응을 공통 검출 함수로 구분했다.
황색/정지 관측 전환은 journal 잠금 해제 후 같은 정책을 즉시 재평가한다. 원본 초록의
촬영 시각 위치로 먼저 입증한 정상 통과는 이후 적색과 같은 batch에 들어와도 유지한다.
통과 입증 전의 철회, 위치 이력 공백, 이미 기록된 불확실·초과는 나중 초록으로 정상화하지 않는다.

## 통제 시험 범위와 결과

설치본은 MORAI `v.S4.251001.MolitComp03`, 지도는 K-city 2025, 차량은 IONIQ 5다.
공식 출발점부터 경로 s=800m까지 평가했다. 회전교차로 시작 약 s=858.5m는 종료점 밖이다.
새 신호 정책 대상은 C1256W000077/091/016/052 네 곳이고 마지막은 보호 좌회전이다.
비보호 우회전은 기존 규칙을 유지하며 새 보호 신호 정책의 합격 범위에 포함하지 않는다.

| 주행 검증 | 결과 |
|---|---|
| 네 신호의 통과·황색 정지·복구 및 추가 확인 | 독립 물리 평가상 무위반 완주 18회 |
| 출발점→800m 연속 주행 | 같은 판제·제어 빌드로 2회 완주, 네 신호 실제 적법 통과·충돌·도로 이탈 없음 |
| 6m 황색 전환 2건 | 실제 전륜 통과 전 최대제동·초과/불확실 보존. 무위반 성공으로 집계하지 않음 |
| 이탈 경로 차단 | SDK 정지 유지 중 실제 정적 물체로 차단한 사전 확인 57표본. 해제 후 실제 적색 복구 이탈 완료 |
| 현재 명령 궤적의 실제 추종 | 곡선 구간 773표본, 실제 후륜축–현재 궤적 최대 거리 0.068m |

차단 시험은 **Ego를 SDK로 정지 유지한 준비 구간의 차단 확인과 이후 실제 이탈**이다.
주행 중 돌발 장애물 재현으로 표현하지 않는다. 추종 수치는 현재 Controller token·Planner 세대·
sequence로 연결된 궤적만 사용한 기하학적 거리이며 시간 추종 오차나 모든 조건의 보장값이 아니다.

정지 불가능 2건에는 실제 황색 통과가 있었다. 한 건은 이후 끝점까지 이탈했고, 다른 한 건은
신규 진입 허가가 없어 실제 최대제동 정지를 유지했다. 원본 result의 `passed=false`는 유지했다.
실패 대응 수락은 이 기록의 별도 평가이며 무위반 주행 성공으로 바꾸지 않았다.

무위반 완주에도 불확실/목표 초과 기록이 있다. 초기 위치를 이미 교차로 안에 둔 복구 시험,
통과 시점을 원본 관측으로 확정하지 못한 보호 좌회전 등이 포함된다. 첫 연속 주행에서는
경로 실패 요구의 확인·복구도 있었다. 실제 적법 완주가 모든 진입의 NORMAL 확정이나 정지
목표 정밀 달성을 뜻하지 않는다. 해당 사건·실패 bitmask는 JSON에 회차별로 남겼다.

실제 신호는 SetTrafficLightState로 바꾸고 GetTrafficLightInfo로 재조회했다. 그 평가값을
운영 정책에 넣지 않았다. 독립 평가는 실제 전륜·3차원 차체 투영·접촉과 설치 지도 번들의
물리 도로 삼각형을 사용했다. 도로 표면 확대·구멍 메우기 없이 실제 차체와 이동 sweep을 검사했다.

적색 복구는 정책 EXITED와 실제 차체의 이탈 경계 통과 여유 0.5m를 둘 다 확인한 뒤 신호를
복원하고 추가 15m도 주행했다. 앞선 회차의 끝점까지 적색을 유지한 더 강한 원본도 같은 기준으로
재평가했다. 두 도구 파일의 SHA 차이를 별도로 기록했고, 나머지 소스와 모든 판제·제어 바이너리는
동일함을 확인했다. 과거 실패·미완료 result는 고쳐 쓰거나 삭제하지 않았다.

## 기준값과 실측

차량 앞/뒤 범위는 후륜축 기준 3.845/0.79m, 휠베이스 3.0m, 전륜 반윤거 0.814m다.
사양 폭 1.892m와 실제 물리 외곽 폭 약 2.161m를 구분했다. 시험 프로필의 차체 오차는 0.7m,
검증된 측정 속도 범위의 원본 전륜 관측은 별도 0.5m다. SDK 위치·IMU yaw의 ENU→지도 변환도 구분했다.

정적 카메라 대조 36조건 중 15m/6m의 24조건은 기록한 프레임 모두 실제 색상과 일치했다.
30m에서는 8조건이 미검출이었다. 미확인 입력을 초록으로 대신하지 않는다.

| 실측 항목 | 유한 표본 결과/적용 |
|---|---|
| 신규/강화 제동의 실제 응답 확인 | 20구간, tD→검출 상한 최대 0.232초 |
| 이미 적용 중인 일반 감속 확인 | 2구간, 신규 응답 시작과 구분 |

| 실제 최대제동 관측 | pedal≥0.99가 0.2초 이상 지속되고 속도≥1m/s인 82표본. 감속 8.84~10.94m/s², 중앙값 9.81m/s² |
| 원본 상태–실제 차체 대조 | 19,364표본, 전 구간 최대 0.620m / 신호 활성 범위 0.393m |

실제 응답 시점은 RPC 표본으로 검출한 상한이며 정확한 onset 순간을 뜻하지 않는다.
8.9m/s²는 공통 명목 예측값으로 유지하며 실측 감속의 보장 하한으로 쓰지 않는다.
위 수치는 이 설치본·설정·표본의 결과이고 모든 속도·곡률·환경의 절대 경계가 아니다.

## 근거와 종료 상태

[결과 JSON](2026-10-22-yellow-light-validation.json)에 494개 소스 및 15개 바이너리의
검증 정보, 회차별 원본/설정/시계 SHA, 도구 두 버전, 실제 도로·차량 번들 근거를 남겼다.
공통 소스/바이너리 검증 hash는 `f2c8a8470bbda664c6913e3051fc266a8724b10cca674c9dfef21adcfdcf1ccd`다.
원본 대용량 로그·rosbag·기존 실패 회차는 Git 제외 `tools/scen_runner/.runtime/yellow/`에 보존했다.

종료 시 Ego를 공식 출발점에서 SDK 정지·일시정지, 실제 속도 0으로 확인했다. 정적 물체 2번은
최초 snapshot으로 복원했고 기존 Ego/정적 2/보행자 3은 유지했다. 신호는 각 회차의 원래 단계로
복원했다(단계 elapsed는 다시 시작). 시험 binding·active 정책 파라미터를 제거하고 소유한 판제·
제어·기록 프로세스와 추적 probe만 정리했다. 기존 Bridge·카메라·Main·대시보드는 유지했다.
커밋·푸시는 하지 않았다.

WSL 시계 tick/frequency는 종료 시 10000µs/0ppm이었다. 그러나 숨은 chronyd의 배율 재발을
영구 해결한 것은 아니다. 시계 배율 재발의 환경 제약은 별도 시계 작업으로 남아 있다.
기본은 관측 모드이며 이 기록만으로 상시 운영 활성화를 허용하지 않는다.
