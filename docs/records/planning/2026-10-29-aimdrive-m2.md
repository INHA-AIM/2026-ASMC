# AIMDrive main 리베이스와 M2 재개

> 2026-10-29 통합: 링크만 현재 localization 이관 경로로 연결했다. 아래 실험 날짜·SHA·과거 명칭은 유지한다.

현재 단계는 M2 무장애 위치 추종이다. M3 실제 정적 회피·복귀와 동적 객체 수락은
아직 진행하지 않았다. [구조·M0~M6](../../../src/asmc_planner/src/shadow_localization/README.md)를 따른다.

## 보존과 새 기준

- 원본 `597e7150`을 `archive/aimdrive-pre-main-20261029-597e7150`과 검증한 bundle로 보존했다.
- 원격 main `be20138a` 위에 `--rebase-merges`로 기존 111개 이력을 보존했다.
  [커밋 대응표·충돌 근거](2026-10-29-aimdrive-main-rebase.json)에 전체 대응을 기록했다.
- 리베이스 후 계약 보정과 시험을 마친 기준은 `e7fc3185`
  (`aimdrive-m2-base-20261029`)다. main 병합·강제 push는 하지 않았다.
- 기본 E3 작업과 독립 LOCAL 작업의 소스·브랜치·노드는 변경하지 않았다.

R1은 CPU 2개·6GiB, network none 환경의 새 build/devel에서 검증했다.
선택 planner 시험 10개, tunnel filter/route 72개, 기존 음영 ROS 통합 51개,
문서·CLI 등 Python 29개와 과거 contact fixture/probe가 통과했다.
초기 병렬 빌드 중 시간 예산 실패와 누락 타깃은 별도 로그로 남기고 유휴 재검증했다.
공유 입력 5종의 ROS MD5도 대조했다. 이 결과는 새 실제 주행의 성능 수락이 아니다.

Docker가 직접 AIMDrive bind를 옛 repro 경로로 보고해, 실행 전에 거부했다.
워크스페이스 부모를 읽기 전용으로 마운트하고 `/root/ws`를
`/workspace/2026-ASMC-aimdrive`로 연결해 실제 Source·파일 SHA를 확인했다.
전용 `/build`, `/devel`, `/install`은 다른 작업의 overlay와 분리했다.
복구 이미지의 과거 `/tmp` 실행본은 사용하지 않았다.

## M2 변경과 오프라인 근거

- 상대 odometry 적분기는 하나다. 소비자는 시각 정렬과 map anchor만 계산한다.
- 1초·10개 유효 정렬 GPS 표본 전에는 경로를 유효하게 만들지 않는다.
- GPS 소실 후 복구는 DR 대비 25cm·2도 한도에서 1초 검증하고 1초 연결한다.
  한도 초과·producer/config/epoch 변경 시 무효화하며, 정지 후 재초기화한다.
- raw IMU roll/pitch로 body OBB를 scan당 한 번 변환한다. yaw-only odometry의
  quaternion을 tilt로 쓰지 않는다. 중복 scan은 재변환하지 않는다.
- 무효/예측 객체, 오래된 producer, 시각 역행, 미래 scan을 별도로 거부·기록한다.
- 출발은 준비 상태로 결정하며 10초 실패 시 복구한다. 실제 주행 중 속도 한도를
  넘으면 중단한다. 종방향 후보는 실험 전용 `shadow_position.yaml`에 둔다.
  acceleration 1.0m/s²·jerk 2.0m/s³는 실측 수락 전의 후보이며 기존 pedal 보정은 유지한다.
- ROS 메시지·LocalTrajectory·LiDAR GPS validity·터널 전처리는 바꾸지 않았다.

새 anchor/alignment 핵심 시험, LOCAL·static core 회귀, 실제 ROS 메시지 기반
경계 점검 18개, 평가/출발 정책 Python 시험 8개가 통과했다.
이 18개 ROS 경계 시험은 전용 master와 synthetic 입력만 사용하며 차량 제어 노드는 실행하지 않는다.
최초 시험의 subscription 준비 시간 부족은 fixture 준비 확인으로 수정했다.
로그는 새 등록 run `aimdrive-m2-20261029-r01`에 이전 실패와 함께 보존한다.

## 과거 기준선 재평가

동결 r01~r06은 변경하지 않았다. 실제 native 위치를 보존된 map·고정 Frenet 참조에
독립 투영하고, 무효·누락·정지 시각도 분모에 포함했다. 수신 시각의 근접 대응은
센서 시계 보정이나 ground-truth 정확도 보장이 아니다.

[갤러리](http://localhost:8000/aimdrive-m2-20261029-r01/historical-r3/index.html)는
실제·추정·참조 경로, 횡오차, GPS/DR·무효 상태, 속도·조향·독립 제어 수신 간격을 보여준다.
각 입력 로그·map·설정·평가 실행 파일 SHA 및 bag 수신 대조를 첨부했다.
기존 갤러리 고유 번호는 유지한다. 중간 분석 출력도 보존한다.

r06은 독립 횡오차 p95 약 12.2cm, 최대 약 13.6cm, 방향 p95 약 0.80도다.
그러나 목표 속도 초과가 1.11km/h이고 새 복구 정책 증거가 없어 M2 전체 미통과다.
r01은 native 주행 표본이 없어 측정 실패로 남긴다. 이전 결과를 새 소스 수락으로 대체하지 않는다.

## 실제 주행 수락

사용자는 다른 시뮬 시험 예정이 없다고 확인했다. 실제 실행 전 동일 물리 공용 lease와
endpoint, 제어 producer, 실행 소스·입력 상태를 다시 검사한다. 준비 순서는
5km/h 1회 → 10km/h 3회 → 15km/h 3회 → ±0.2m/±2도 각 1회다.
새 run별 수락을 기록하며, 실패 또는 점유 충돌이 있으면 이후 단계는 미완료로 유지한다.
현재 이 문서 작성 시점에는 새 live 시험 전이며 M3 진입은 허용하지 않는다.

## 공통 11311 연결과 전체 판제 옵션

후속 요청에 따라 공용 `asmc-ros-noetic`의 master·bridge를 공유하는
`asmc-aimdrive-live-20261029`를 확인했다. host network, `ROS_MASTER_URI=http://127.0.0.1:11311`,
`ROS_HOSTNAME=127.0.0.1`, ROS_IP 미지정이다. `/root/ws`는 이 worktree를 가리키며
전용 `/devel`을 읽는다. 개인 `/root/aimdrive-env.sh`를 `.bashrc`에서도 적용했다.
다른 컨테이너·기존 세션의 환경은 바꾸지 않았다.

`shadow_planner:=aimdrive`를 통합 launch에 추가했다. 기본 `main`은 기존 BBox 방식이다.
일반 구간에서 anchor는 준비하되 연구 경로·MPC 계산은 멈추고, 음영에서는 NORMAL MPC를
멈춘다. 기존 BBox 노드 세 개와 AIMDrive 세 개는 택일하며 최종 selector는 하나다.
복귀는 검증된 anchor와 새 NORMAL 경로 두 개가 모두 필요하다. 실행 명령과 연구 범위는
[운영 안내](../../operations/planning-control.md#localization-음영-위치-추종-연구-옵션)에 기록했다.

검증 근거는 다음과 같이 구분한다.

- 컨테이너 간 TCPROS 왕복 10회 성공. 별도 roscore·bridge를 만들지 않았다.
- 사용자 재시작 이후 공용 브릿지의 8개 입력을 8초 관찰했다. GPS 5Hz, IMU 약42Hz,
  Ego 약39Hz, LiDAR 약12Hz, 전/좌/우 카메라 20Hz와 extra 10Hz를 받았다.
  수신 메시지 MD5와 컨테이너 타입 MD5가 모두 일치했다. 이 수치는 성능 보장이 아니다.
- `shared-pipeline-r1`에서 필수 노드·토픽 연결은 통과했지만 GPS anchor가 계속 warming인
  문제를 발견했다. 실제 5Hz GPS를 1초 버퍼로 제한하면서 10개를 요구하던 결함이다.
  초기/정지 재초기화 때 최소 10개를 보관하도록 수정했다. GPS 복구 검증은 1초를 유지한다.
- 5Hz 초기 준비·복구·정지 재초기화 회귀 7개를 추가했다. `shared-pipeline-r2`의 실제 입력
  22초 점검에서는 약2초 뒤 anchor가 준비됐고 trace 390개 중352개가 gps_anchored였다.
  odometry 909개, LiDAR 관측252개와 관찰용 최종 제어436개를 받았다.
- 공통 입력 시험은 최종 `/ctrl_cmd`를 관찰용 토픽으로 remap했다. 차를 움직이거나
  실제 GPS blackout·복구를 만들지 않았다. 일반 NORMAL에서의 연결 확인이며 M2 주행 수락은 아니다.
  카메라 추론은 재실행하지 않았고, 임시 LiDAR는 `fusion:=false` 기하 경로를 사용했다.
- 격리 synthetic 시험은 실제 MPC/selector로 NORMAL→JAMMING→NORMAL 및 중복 제어
  거부 10항목을 확인했다. 복귀 gate1, 기존 GPS mode4, selector3 ROS 회귀도 통과했다.
  두 옵션의 전체 launch graph와 잘못된 옵션 거부, 문서·입력 launch 검사도 통과했다.

공통 입력 기록은 등록 run `aimdrive-m2-live-20261029-r01`의 `shared-inputs-r2.json`과
`shared-pipeline-r1/r2`에 패치·빌드 출처와 함께 보존했다. 최초 입력 요약기의 callback
동시 접근/직렬화 오류는 분석 도구 오류였으며 수정된 r2 기록을 사용한다.
시험 종료 시 이번 launch만 종료하고, 조건부로 이번에 설정한 ROS param만 복구했다.
사용자 master·bridge는 유지했고, 실제 이동·접촉·GPS 전환 수락과 M3는 미완료다.
