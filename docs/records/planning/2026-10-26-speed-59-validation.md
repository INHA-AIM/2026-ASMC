# 59 km/h 이하 속도 개선 시험

**결론: 속도 상향은 채택하지 않았다.** 직선 속도 상승은 확인했지만 전체 평균 개선과
완주 안정성을 확인하지 못해 두 운영 YAML을 기준 커밋 값으로 복구했다.
따라서 이 작업으로 기본 주행 속도가 올라간 상태는 아니다.

## 목표와 조건

- 사용자가 목표를 **최고 59 km/h 이하, 전체 평균은 가능한 만큼 개선**으로 조정했다.
- 평균은 정차·신호 대기·회전교차로·재밍을 포함한 거리/시간이다. 움직이는 동안의 평균으로 바꾸지 않는다.
- 기준 커밋: `bda91d7a`. 브랜치: `feature/yuntae-speed-59-validation`.
- 기존 `lidar+sensorfusion` 패키지 보존. 커밋·푸시·PR 수행 안 함.
- 실제 실행 경로는 `autonomy_no_bridges_v2.launch lidar_source_policy:=asmc_lidar`.
  별도 황색 신호 실험용 정책/clock profile을 운영 경로에 덮어쓰지 않는다.
- MORAI 자연 신호 주기, seed 42의 장애물·체크포인트 환경 변경 사용.
  기존에 놓여 있던 정적 물체 ID `2`도 보존한 상태다. 따라서 순수한 seed 42 신규 물체만 있는 장면과는 다르다.
- 각 시험은 자신의 planner/recorder/생성 물체만 정리하고 차량을 정지시킨다.

## 측정 방법

- gRPC 차량 실제 상태는 **평가에만** 사용한다. ROS planner 입력에 실제 좌표/신호를 주입하지 않는다.
- 속도를 시간 간격에 따라 적분한다. 관측 공백, 미완주를 성공으로 처리하지 않는다.
- 독립 도로 mesh와 실제 차량 전체 형상으로 도로 이탈 및 이동 사이의 궤적을 확인한다.
- 실제 충돌 목록, 신호등 상태와 앞바퀴 정지선 통과를 확인한다.
- 실선 접촉은 별도 `audit_solid_paint_contact.py`의 기하학적 바퀴 추정으로 검사한다.
  실제 바퀴 접촉 센서/심판 판정을 대체하지 않는다.
- CP14 통과 후 출발점 복귀만 완주로 인정한다. CP14를 놓친 채 출발점으로 돌아오면 중단한다.
- 운영 경로 시험에서 실제 속도가 59 km/h를 넘으면 중단한다.

## 변경 전 측정

저장 위치: `/data/derived/speed-59-validation/baseline-seed42-01/`.

- 최고 **57.303 km/h**.
- 기준 경로를 따라 출발점 반경 3m로 처음 돌아온 관측 구간: 336.541초,
  속도 적분 거리 2203.998m, 평균 **23.576 km/h**, 0.36 km/h 미만 정지 약 **69.247초**.
- 이것은 **공식 완주 평균이 아니다**. CP14 중심까지 최소 거리가 약 3.493m로,
  판정 반경 3m에 들어오지 못했다(샘플 사이 선분 최소거리 3.491m).
  최초 시험은 이를 발견한 후 두 번째 바퀴 초입에서 수동 중단했다.
- 전체 기록: 도로 이탈 0, 충돌 0, 관측 공백 0, 확인된 정지선 통과 4건 모두 허용 신호.
- 전체 기록의 바퀴 실선 접촉 추정 최장 0.841초. 차체 실선 접촉 최장 4.410초이므로
  이를 "실선 접촉 없음"이라고 보고하지 않는다.
- 원본 bag 약 2.28GB, `result.json`에 토픽 개수와 SHA-256 보존.

## 속도 후보

- 행동 최대 속도 57.5 → 58.5 km/h.
- 일반 직선 목표/상한 58 → 58.5 km/h.
- Frenet 기본 목표 16.1111 → 16.25 m/s.
- 곡률, 횡가속도, 신호 접근, 정지거리, 충돌 여유, 장애물 회피 속도, 재밍 속도는 유지.
- 58.5는 요청값이다. 실제 59 이하 여부는 실측으로 판정한다.

첫 후보 시험 `candidate58_5-seed42-01`은 C091 뒤의 정적 장애물 회피 중 정지해 중단했다.
피드백은 `committed avoid path blocked by collision`, 목표 횡방향 위치 -3.5m,
유효 후보 0개였다. 이 시험은 실패로 남기며, 속도 설정만으로 생긴 회귀라고 단정하지 않는다.
원본 bag과 `avoid-stall-inputs.json`에 입력/피드백 9806건을 보존했다.

재시험 `candidate58_5-seed42-02`는 장애물 구간을 통과해 출발점으로 복귀했지만,
CP14 최소거리 3.493m로 완주 판정에 다시 실패했다.

| 측정값 | 기준 설정, 최초 복귀 구간 | 58.5 후보 재시험 |
| --- | ---: | ---: |
| 최고속도 | 57.303 km/h | 58.296 km/h |
| 1400~1500m 직선 구간 시간 가중 평균 | 56.894 km/h | 58.169 km/h |
| 정차 포함 관측 구간 평균 | 23.576 km/h | 16.508 km/h |
| 관측 시간 | 336.541초 | 480.458초 |
| 0.36 km/h 미만 정지 | 69.247초 | 208.450초 |
| CP14 후 완주 | 실패 | 실패 |

신호 주기의 시작 시각과 진입 대기가 같지 않다. 따라서 후보 평균이 낮아진 것을
속도 상향만의 효과로 단정하지 않으며, 반대로 전체 평균이 개선됐다고도 주장하지 않는다.
두 구간 모두 공식 완주 평균은 아니다. 전체 비교 수치는 `comparison.json`에 저장했다.

재시험의 독립 관측에서는 충돌/도로 이탈/59 초과/관측 공백 0건,
정지선 통과 4건 모두 허용 신호였다. 기하학적 바퀴 실선 접촉 추정 최장은 1.018초,
차체 접촉 최장은 4.337초였다. 이는 모든 상황에서의 차선 유지·안전을 보장하는 결과가 아니다.

시험한 YAML 원본은 `/data/derived/speed-59-validation/candidate-config/`에 보존했다.
저장소의 기본 설정은 원복했다. 검증 도구·측정 테스트·이 기록만 변경으로 남긴다.

## 남은 문제와 다음 검증

1. C091 장애물 회피 중 정지 재현: 동일 장애물/신호 조건의 기준 설정과 비교해야 한다.
   기존 물체 ID 2와 새 시나리오 물체가 함께 있다는 점을 입력 조건으로 보존해야 한다.
   충돌 여유나 안전 제동을 해제해서 통과시키지 않는다.
2. 재밍 출구 CP14 누락: 기준·후보 모두 약 0.49m 모자랐다.
   전역 기준 경로 자체는 CP14 중심을 지난다. 카메라 주행 경로와 정상 모드 복귀 시점을
   분석해야 하며, 검증 반경을 넓혀 통과로 바꾸지 않는다.
3. 위 문제를 해결한 뒤 정상 완주한 여러 회차의 정차 포함 평균을 비교하고 속도 상향을 채택한다.

## 재현 명령

아래 명령은 **현재 체크아웃의 설정**을 시험한다. 지금은 원복된 기준 속도다.
브릿지와 `run_perception.sh`가 실행 중이고 다른 planner가 없는 컨테이너에서:

```bash
source /opt/ros/noetic/setup.bash
source /root/ws/devel/setup.bash
cd /root/ws/tools/scen_runner
python3 run_yellow_signal_trial.py \
  --production-stack --host host.docker.internal \
  --physical-road .runtime/clock-fix-20261022/full-route-road-oracle.json \
  --output /data/derived/speed-59-validation/새로운시험이름 \
  --case corridor --full-route --natural-signals --scenario-seed 42 \
  --record-bag --deadline 650
python3 analyze_speed_trial.py /data/derived/speed-59-validation/새로운시험이름
```

도로 mesh 파일은 현재 지도와 경로에 맞는 로컬 검증 자료가 필요하다.
원본 bag, 모델, local.yaml, runtime 자료는 Git에 넣지 않는다.
