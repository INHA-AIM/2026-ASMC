## 기본 실행

통합 `autonomy_no_bridges_v2.launch`와 전체 스택 `autonomy.launch` 모두 localization + LOCAL recovery가 기본이다. localization MPC 하나가 native 경로 또는 검증된 LOCAL 대체 경로를 추종한다. LOCAL 제어기는 별도로 시작하지 않는다. 일반 NORMAL MPC, LiDAR 터널 범위, 로터리 및 일반 회피 설정은 유지했다.

현재 비교 컨테이너의 master11373·bridge·camera·LiDAR·웹을 사용하는 명령:

```bash
roslaunch asmc_planner autonomy_no_bridges_v2.launch dashboard:=false
```

새 판제 웹도 함께 시작하는 일반 실행은 `roslaunch asmc_planner autonomy_no_bridges_v2.launch`다. 기본 웹8088과 현재 비교 웹8089를 혼용하지 않는다. 기존 방식 복귀:

```bash
roslaunch asmc_planner autonomy_no_bridges_v2.launch \
  jamming_planner:=camera localization_local_recovery:=false dashboard:=false
```

판제 http://localhost:8089/web/index_v2.html · LiDAR http://localhost:8097/ . 시험 autonomy는 종료하고 차량은 pause/P로 보존했다. 브릿지·카메라·LiDAR·두 웹·master는 유지한다. 수동 재개 시 autonomy를 한 번 실행하고 시뮬 pause 해제/D 전환이 필요하다.

## 남은 문제와 다음 작업

사용자가 확인한 steel barricade는 localization 입력에서 놓쳐 장애물 가까이까지 native 경로가 진행한 뒤 LOCAL 노면 경로로 복구했다. **LiDAR 누락 시 native의 조기 회피 근거 부족**과 **근접 LOCAL 곡률/짧은 경로 때문에 생기는 저속**을 구분해 개선해야 한다. 이번에는 속도만 올리거나 실제 충돌 검사를 제거하지 않았다. 전체 객체의 dynamic/pending 수에 따른 복구 차단을 선택 경로 위험으로 좁히는 작업도 남았다. 진입 최저3km/h 수준 감속은 개선 여지가 있다.

윤태의 새 로터리 패치는 마감 시점 원격 통합 브랜치에서 확인되지 않았다. 기존 로터리 패치를 보존했고 이번에 동일 코드를 수정하지 않았다. 로터리 진입 후 정지/후방 접촉은 미해결 항목이며 이번 터널 시험으로 수락하지 않는다.
