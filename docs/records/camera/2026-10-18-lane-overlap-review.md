# 3뷰 차선 겹침 근거 통합 검토

## 현재 구조

실제 family 경로는 `model-grid pixel → 카메라 보정/평면 투영 → 연속 base_link(x,y) 근거
→ 동일 종류·전방0.25m 구간의 노드 → track 연결 → shared B-spline family`다.
색칠한 BEV raster를 만든 뒤 거기서 선을 다시 추출하는 경로가 아니다.
같은 물리 위치의 여러 카메라 근거는 이미 함께 사용하며 source bit도 OR로 보존한다.

Confidence·기하 품질·영상 가장자리 taper·거리 감쇠를 적용한다. Shared family의 track별
가중치는 평균으로 정규화해 픽셀이 많은 역할 하나가 전체 family를 지배하지 않도록 한다.
다만 같은 역할/노드 안의 위치 평균에는 카메라별 픽셀 밀도가 영향을 줄 여지가 있다.
해상도를 같게 해도 카메라 FOV·시야각·지면당 픽셀 밀도와 원본 촬영 시각까지 같아지는 것은 아니다.

## 고정 자료와 후보

기존 Large FP32 semantic 연속216묶음(SUNNY/FOGGY×11/13/15시, 진입/내부/출구)을 재사용했다.
전방544×960·측방480×640, 명목 평면-0.36m, confidence0.50·동일 피팅/지지 조건을 고정했다.
가중치·운영 보정·source stamp·모델 추론을 변경하지 않았다.

- 현재3뷰 통합.
- 전방 단독 ablation: 측방 근거의 기여 확인용이며 운영 후보로 선정하지 않는다.
- 밀도 보정 후보: 기존 같은 클래스/구간/횡방향 cluster 안에서 카메라별 픽셀 수를 정규화한다.
  Confidence/기하 품질은 유지하고, 한 카메라만 보는 노드는 기존과 동일하게 둔다.
  서로 다른 클래스·분리된 선을 강제로 합치거나 양 카메라 검출을 두 번의 독립 확인으로 세지 않는다.

## 결과와 판단

| 구성 | family 유효 | 두 차로 띠 지지 비율 중앙값 0–5m | 5–10m | 자체 semantic 재투영 p95의 중앙값 |
|---|---:|---:|---:|---:|
| 현재3뷰 | 216/216 | 100% | 100% | 7.45px |
| 전방 단독 | 216/216 | 0% | 96.6% | 3.20px |
| 밀도 보정3뷰 | 216/216 | 100% | 100% | 8.00px |

family 전체 유효와 거리별 지지는 다르다. 전방 단독은 유효 family를 만들었어도 근거리 양쪽
차로 띠를 지원하지 못했다. 현재3뷰의0–5m 두 띠가 완전히 연속인 묶음은150/216, 후보149/216,
전방 단독0/216이었다. 측방은 이미 근거리 근거 보강에 크게 기여한다.

두 카메라 이상이 겹친22,187개 노드에서 카메라별 횡방향 중심 차이는 p50=2.91cm·p95=9.59cm였다.
지배 카메라의 픽셀 비율은 p50=67.1%·p95=93.1%였다. 밀도 보정 후 공통 유효 구간의
family 곡선 차이는 p50=0.43cm·p95=1.46cm였다. 이것은 독립 GT 오차가 아닌 후보간 변화량이다.
픽셀 밀도 보정은 자체 재투영도 개선하지 않았고 오프라인 계산 p50은34.3→62.4ms로 늘었다.
이 Python 후보는 별도 실시간 최적화가 안 된 상태이며 TRT forward 속도와 비교하지 않는다.

**운영 family는 현재3뷰 통합을 유지한다.** 단순히 두 카메라를 더 강하게 섞거나 threshold를
낮추는 방식의 개선은 입증되지 않았다. 카메라별 중심 차이가 모두 보정 오차라는 인과관계도 확정하지 않는다.

## 다음 확인 순서

1. 새 bridge timing과 원 RGB·IMU를 함께 기록해 실제 source 시각으로 대응한다.
   과거 bag의 header는 receive 시각이므로 raw source를 소급 복구하지 않는다.
2. 정차/저속 직선에서 같은 실제 차선의 카메라별 재투영·장착/평면 보정을 확인한다.
   독립 RGB/거리 GT와 지원 범위를 함께 보며 한 카메라 semantic에 맞추려고 보정을 왜곡하지 않는다.
3. 원본 clock·자세가 유효한 움직이는 구간만 source-time SLERP·뷰간 상대 이동 정렬을 대조한다.
   터널의 GPS 무효 VehicleState를 이동 보정에 재사용하거나 개발 Ego pose를 운영 입력으로 넣지 않는다.
4. 남은 불일치가 실제 겹침 결합 문제이면 신뢰도·불일치 거리 기반 후보 하나를 대조한다.
   근거리 지원·역할·유효 공백·freshness와 계산 비용을 함께 확인한 뒤 채택한다.

독립 지면 GT가 없는 자기 semantic 일치 지표라 정확도 순위나 전방 단독 우월로 해석하지 않는다.
