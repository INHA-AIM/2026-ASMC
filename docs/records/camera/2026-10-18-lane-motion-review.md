# 음영 차선 운동 보정·피팅·시각화 분석

## 판단

후속 [정차·표시 주기 대조](2026-10-18-lane-display-and-rest-calibration.md)에서 M1-rest의
정차 기준이 검증된 보정이 아님을 재확인했다. 아래는 최초 분석 당시의 판단이며 운영 적용은 보류한다.

**다음 구현 후보는 정차 기준 자세를 확인한 IMU 상대 roll/pitch 지면 투영(M1-rest)이다.**
터널 내부의 시간적 곡선 변화는 줄었지만 진입부와 지원 범위의 회귀가 있어 운영 적용은 보류한다.
현재 Large v7 E8 TensorRT·shared B-spline·보정·계약·기본 설정은 변경하지 않았다.
새 네트워크, 대체 곡선 탐색, 과거 결과 재발행, freshness 완화도 적용하지 않았다.

Ego motion 시간 누적은 우선하지 않는다. 개발용 Ego 위치를 사용해도 추가 이득에 비해
계산량이 늘며, 대회용 터널 속도/odometry 입력은 아직 확인되지 않았다.
시각화는 축 표시와 최신 프레임 스케줄링을 다음 소규모 개선 대상으로 남긴다.

  내부 끝과 출구 시작을 우선하며 결과를 보고 영상을 고르지 않았다. 원본 카메라는 약20Hz이므로

## 좌우·시각·운동 입력

정본의 좌우 반전은 재현되지 않았다. `base_link`의+x는 화면 위, +y는 화면 왼쪽이다.
비대칭 지점(10,+3)m은 BEV(50,100)px, 전방 원본 u≈404px로 왼쪽에 놓인다.
왼쪽/오른쪽 카메라 yaw는+70°/−70°다. 여섯 조건×세 구간18개 대표 RGB에 실제 family를
재투영해 황색선·양쪽 경계의 방향을 검토했다. 좌우·전방 재투영도 갤러리에 남겼다.
이 검토는 수동 픽셀 GT 주석이나 전 범위의 기하 정확도 보장이 아니다.
검사 당시 공개 ROS master에는 실행 중인 시각화 노드/rqt가 없었으므로 사용자가 보았던
화면의 토픽·시점까지 동일하게 재현했다고 표시하지 않는다. 화면을 뒤집는 수정은 하지 않았다.

현재 bridge와 여섯 bag의 기존 diagnostics 모두 `timestamp_mode=receive`다.
보간에 쓴 header stamp는 센서 촬영 시각의 증거가 아니다. bag 기록 시각은 별도로 보존했다.
대표/연속360묶음의 뷰 간 수신 stamp skew p50≈1.45ms, p95≈15.74ms, 최대≈21.53ms다.
이 값이 실제 노출 시각 차이와 같다고 단정하지 않는다. IMU/Ego 보간은 최대100ms의 bracket만
사용하고 외삽·잘못된 quaternion/pose·시간 역행은 허용하지 않는다.

여섯 bag에서 IMU roll은 약−1.01~+2.65°, pitch는 약−0.59~+2.13°로 변한다.
Ego heading과 IMU yaw의 차이 p95는 조건별0.09~0.17°였다.
센서셋의 IMU 장착 회전은0이다. 카메라의 고정 장착 pitch는 그대로 유지했다.
정차 기준을 제거하는 후보는 per-run 정차 표본이5개 이상일 때 첫 유효 quaternion을 사용한
민감도 대조다. 이것이 곧 교정된 도로 법선이라는 뜻은 아니다.

기록에는 `/imu`, `/Ego_topic`, `/gps`가 있지만 odometry/공용 VehicleState는 없다.
여섯 bag의 GPS124/107/93/87/91/94개에는 위도/경도0 표본이 없어서 GPS 음영 중 가용성을
검증할 수 없다. 현재 bridge의 GPS/IMU VehicleState는 GPS 무효 시 무효가 된다.
개발용 Ego 위치를 대회용 입력으로 승격하거나 과거 GPS를 재사용하지 않는다.

[앞선 연속성 기록](2026-10-18-twinlite-large-deployment.md)에 그대로 남겼으며 해결로 표시하지 않는다.

시간적 변화량은 Ego SE(2)로 이전 곡선을 현재 차량 좌표에 옮긴 후 측정했다.
모든 후보·두 프레임에서 공통으로 유효한 역할과 x[0.5,14.5]m의0.25m 고정 지점만 사용한다.
서로 다른 샘플 수나 줄어든 지원 범위 때문에 유리해지지 않도록 별도 검증했다.
표는 **프레임 쌍별 횡방향 변화 p95의 분포 p95**이며 GT 위치 오차가 아니다.
구간별66쌍, 총198쌍의 짧은 연속 관측으로 독립 장면198개를 의미하지 않는다.

|---|---:|---:|---:|
| 진입 | 2.35cm | 9.61cm | 2.98cm |
| A126 내부 | 21.63cm | 6.37cm | 8.05cm |

M1-rest의 내부 변화량 감소는 다음 후보로 삼을 근거다. 다만 진입부는 악화되고,
0–15m 소비 범위가1cm 넘게 줄어든 프레임도23/216개이며 최대 감소는 약0.211m다.
15–20m 가용 길이 중앙값도 M0약4.83m에서 M1-rest약4.32m로 줄었다.
보간 범위를 줄인 결과나 매끄러운 화면만으로 정확도 향상을 선언하지 않는다.
M2-history는198프레임에서 과거 근거를 썼지만 전체 공통지점 지표가 M2-align8.53cm에서
8.26cm로 변한 정도라 연산 증가와 미검증 속도 입력을 감수할 근거가 부족하다.

이번 M1은 픽셀 선정·geometric quality를 M0와 고정한 기하 민감도 대조다.
IMU만으로 차체 높이·도로 경사를 동시에 알 수 없으며 고정 높이를 유지했다.
M2와 시간 지표는 SE(2)이고 roll/pitch/heave를 포함한 전체 SE(3) 보정은 검증하지 않았다.
원본 노출 시각, 정차 기준/도로 법선, 독립 GT가 확보되지 않아 어떤 후보도 자동 승격하지 않는다.
2,356묶음 전체의 새 운동 보정 재평가와 MORAI10분 수락은 이번에 수행하지 않았다.
사용 중인 GPU·현재 카메라를 유지했으며 미수행을 통과로 표시하지 않는다.

LaneCPP는 B-spline·평행성·곡률 등 물리 제약의 참고 자료다. 논문의 학습 구조를 현재 피팅에
그대로 적용하거나 ego motion 모듈로 취급하지 않았다.

## 시각화 비용

독립 master11364에서 저장 family를15Hz로 공급하고 각 후보12초씩 대조했다.
GPU·rqt·공개 제어를 사용하지 않았고 종료 후 독립 master를 정리했다.
프로토타입은 probe 안에서만 배경 격자 재사용·잠금 밖 렌더링·발행 전 세대/유효성 확인을 수행했다.

| 항목 p95 | 현재 | probe 프로토타입 |
|---|---:|---:|
| 수신 callback | 0.96ms | 0.94ms |
| 렌더링 timer 전체 | 4.35ms | 3.39ms |
| JPEG 인코딩 | 0.23ms | 0.21ms |
| 입력 발행→JPEG 소비 | 64.90ms | 66.55ms |

렌더링은 줄었지만 전체 지연은 줄지 않았다. 현재 family10Hz timer의 대기 영향이 더 크다.
가벼운 JPEG 인코딩을 전체 Large 지연의 원인으로 확정하지 않는다.
배경 재사용은300개 interleaved 대조에서 JPEG 인코딩 전 픽셀이 같았고 배경 원본도 보존됐다.
구독 해제 후 실제 입력 구독이 해제되는 것도 확인했다.
구독자 수신과 rqt 화면 표시 시각은 다르며 실제 화면 표시 지연은 측정하지 않았다.

별도로 semantic visualizer의 callback100ms 제한은15Hz 입력에서 이상적인 시각에도
약7.5Hz만 선택하는 구조다. 이전 실측7.15~7.70Hz와 일치하지만 이것만으로 모든 실제
지연 원인을 설명하지 않는다. 정확히 대응한 최신 프레임을10Hz timer에서 선택하는 후보를 권고한다.
시각화를 위한 재피팅, 좌표 반전, 원본 header 변경은 필요하지 않다.

## 검증·후속

새 수학/시각/현재 근거 우선·200ms 경계·무효 입력·공통 지점16개 CPU 시험을 추가했다.
호스트에서 기존 family·dropout·문서를 포함한59개, 실제 Noetic 생성 메시지 환경에서
시각화4개로 총63개를 통과했다. 생산 경로144개 parity, 문서 이전/실행 검사,
Python3.8 구문, 갤러리 링크 검사도 통과했다. 호스트에는 ROS 생성 메시지가 없어
시각화 serialization 검사는 Noetic 컨테이너에서 수행했다.
Hosted CI와 실시간 전체 스택 수락은 별도로 남긴다.

후속은 다음 순서다.

1. 시각화에 Ego 방향·LEFT/RIGHT·미터 범위를 명시하고 최신 프레임 스케줄러를 소규모 대조한다.
2. **M1-rest 하나**에 대해 정차 기준·IMU 장착·도로 법선과 영상 시각을 확정한 뒤 기하와
   quality 계산을 함께 구현한다. 진입부와0–15m 가용 범위 회귀를 해결하고 다시 비교한다.
3. 위 후보가 정확도/지원 범위를 보존할 때만 전체 자료와 MORAI 최대10분으로 확대한다.
   새 출력≥10Hz·공백≤250ms·freshness350ms를 유지한다.
4. 대회용 터널 상대 이동 입력이 검증되고 남은 문제가 확인될 때 M2를 재검토한다.

재현 진입점은 `tools/perception/collect_family_motion_inputs.py`,
`cache_family_motion_grids.py`, `review_family_motion.py`, `summarize_family_motion.py`다.
ROS parity는 `check_family_motion_parity.py`, 시각화 독립 대조는 `probe_family_view.py`를 사용한다.
각 도구의 `--help`로 입력을 확인하며 새 output 경로로 실행한다. 운영 launch는 변경하지 않았다.
