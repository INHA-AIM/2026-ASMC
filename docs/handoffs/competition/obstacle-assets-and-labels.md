| 102개 집계의 조건 | 출제 제외 반영 후 | Effect 1개를 별도 평가로 분리한 나머지 |

이는 조건부 산술이며 나머지 전부가 물리적으로 충돌 가능한 객체라는 검증은 아니다.

목록을 확정할 때 대회 SIM 버전, F2 전체 메뉴, 에셋 이름·별칭·중복, 제외 공지를 함께 기록한다.
일반 MORAI/AIM 버전의 카탈로그나 저장소 시나리오의 whitelist를 대회 전체 목록으로 대체하지 않는다.

## 에셋·학습 클래스·소비 그룹·운동 상태의 구분

| 층 | 역할 | 예시 |
|---|---|---|
| MORAI 에셋 | 외형·크기·애니메이션·기준점을 가진 개별 모델 | Man 계열, Dog1, Deer1, 차량 모델 |
| 검출 학습 클래스 | 영상에서 구분하도록 실제 학습한 범주 | person, dog, car, deer, stroller 등 |
| 소비 그룹 | 판제가 관측 종류를 묶어 다루는 분류 | 제안: person / animal / vehicle / obstacle |
| 운동·관측 상태 | 추적에서 별도로 검증하는 속도·정적/동적·age·불확실성 | 정차 vehicle, 이동 vehicle, 속도 unknown |

102개 에셋이 모두 별도 학습 클래스일 필요는 없다. `source_class_name`에는 모델이 실제로
반환한 원본 라벨을 보존한다. 그룹 매핑을 추가하는 것만으로 미학습 객체를 검출할 수는 없다.

**팀의 다음 설계 후보는 `person / animal / vehicle / obstacle`이다.** 이번 대회에는
pedestrian·VRU를 새 학습 클래스나 다섯 번째 그룹으로 추가하지 않는 방향을 권한다.
원본 person을 사람 전체로 유지하고 자전거·킥보드의 탑승자도 별도 person 관측으로 다룬다.

현재 운영 기본은 `person / vehicle / obstacle` 세 그룹이며 bicycle은 person에 포함된다.
PR #74의 실험 설정은 네 그룹을 지원하고 bicycle을 vehicle로 분리한다.
다음 후보에서 bicycle→vehicle과 animal 분리는 **소비 의미의 변경**이다. YAML 수정만으로
끝내지 않고 `detection/classes.py`, 그룹 설정·검사, 메시지 의미 문서·후보 계약과 소비자 시험을
함께 검토해야 한다. 이 문서에서는 그룹·기본 허용 클래스·메시지 MD5를 바꾸지 않는다.
LiDAR의 `/YOLO/BBox` 호환 경로는 bus/truck/person/car·confidence 0.7 정책을 유지한다.

| 에셋 또는 외형 | 학습 클래스 후보 | 소비 그룹 후보 | 검수 사항 |
|---|---|---|---|
| Man/Woman/Boy/Girl·경찰·작업자·NCAP 사람 | person | person | 성인/어린이/복장별 클래스 분할보다 거리·가림별 검출률을 우선 평가 |

| Deer1 | 신규 deer | animal | COCO에 deer 클래스는 없음 |
| 승용차/SUV·트럭·버스 | car / truck / bus | vehicle | 해당 외형을 기존 세부 라벨로 학습 |
| Bicycle/Bike·Bicycle_Female1 | bicycle 및 보이는 탑승자 person | vehicle / person | Bike의 실제 외형 확인. 복합 에셋과 영상 인스턴스 수를 구분 |
| 오토바이·Scooter1/2 | motorcycle 또는 신규 electric_scooter | vehicle | 오토바이와 전동 킥보드를 외형으로 구분 |
| 유모차와 미는 사람 | 신규 stroller + person | obstacle / person | 보이는 각각의 인스턴스를 라벨링하고 동일 actor 연계를 별도 보관 |
| 바리케이드·박스·드럼통·콘 | 소수의 구별 가능한 신규 세부 클래스 또는 road_obstacle | obstacle | 서로 다른 형태를 하나로 합친 경우와 분리한 경우를 에셋별 recall로 비교 |
| 나무 | 신규 tree 등 | obstacle 또는 별도 구조물 정책 | 수목·배경 전체를 회피 객체로 만드는 기준을 고정하지 않음 |
| 과속방지턱·맨홀 | 별도 노면 요소 | 별도 소비 정책 | 일반 장애물 박스와 같은 회피 규칙을 자동 적용하지 않음 |
| 표지판·신호등·화재 효과 | 별도 관측/위험 클래스 검토 | 별도 소비 정책 | 신호등 박스는 ResNet 색상 판단을 대신하지 않음 |

COCO에는 person, bicycle/car/motorcycle/bus/truck/train과 10종 동물 등 정해진
80종이 있다. deer·stroller·electric_scooter·cone·범용 road_obstacle은 그 이름의
기존 클래스가 아니다. [공식 COCO 목록](https://docs.ultralytics.com/datasets/detect/coco/)을 기준으로
새 라벨과 기존 라벨을 대조하고 '비슷한 모양이라 검출될 것'을 지원 범위로 계산하지 않는다.

train·bench·toothbrush·hair drier 등은 **대회 F2 목록·실제 검출 결과에 따라 운영 후보에서
제외할 수 있다.** PR #73에서는 건물→train, 가드레일→bench 오검출을 확인했다.
해당 라벨만 제외해도 모델이 car 등 다른 라벨로 오검출할 수 있으므로 허용 목록 축소는
검출률·오검출을 함께 평가한다. 이 문서에서 허용 목록을 변경하지 않는다.
신호등·표지판 같은 인프라도 관측 지원 여부와 충돌 회피 대상으로 사용할지를 분리한다.
네 그룹의 obstacle에 속했다는 이유만으로 회피를 지시하지 않으며 판제가 원본 라벨·기하·상태를 소비한다.

## 학습 전략 검토

**세부 학습 라벨을 보존하고 네 그룹으로 매핑하는 방향은 적절하다. 다만 COCO 80개
출력 전체를 유지하는 전략이 대회에 항상 최선이라고 확정하지 않는다.**

| 비교 후보 | 장점 | 필요한 검증 |
|---|---|---|
| A: COCO 80 + 필요한 MORAI 신규 라벨 | 기존 세부 종류와 범용 관측 유지 | 기존 80종의 주석·리플레이/검증 자료와 신규 자료를 함께 관리. 망각·오검출·head 이전 확인 |
| B: 대회용 네 그룹을 직접 학습 | 출력·주석 체계가 간단함 | 이질적인 obstacle 내부의 에셋별 누락·부분 가림 평가. 세부 정보 소실 확인 |
| C: 필요한 세부 COCO 라벨 + MORAI 신규 라벨 | 대회 범위에 맞춘 세부 정보와 라벨 관리 | 동일한 대회 검증 자료로 A/B와 비교. 원본 COCO ID와 새 모델 ID 대응표 보관 |

C도 COCO 사전학습 weight에서 시작할 수 있다. 출력에서 불필요한 클래스를 제거하는 것과
사전학습 특징을 활용하지 않는 것은 다르다. 현재 실험이 전체 80종이라는 이유만으로
후속 모델의 학습 출력도 80종을 강제하지 않는다. A를 선택하면 COCO 0–79와 신규 ID를
일관되게 관리하고, C/B를 선택하면 모델별 ID→원본 의미 대응과 버전을 고정한다.

2026-10-08 격리 검증 컨테이너의 **Ultralytics 8.4.150** 설치 코드를 읽어 확인했다.
`ultralytics.nn.tasks.BaseModel.load/_remap_cls_by_names`는 이름이 맞는 분류 출력 행을
이전하려고 하며, 이름 정보와 텐서 shape가 맞아야 한다. 분류 conv의 입력 폭이 다르면
weight 행을 복사할 수 없고 bias만 맞을 수 있다. 나머지는 shape가 일치하는 파라미터를
`intersect_dicts`로 이전한다. **COCO 클래스 ID를 그대로 두는 것만으로 전체 head나 기존
정확도가 보존되지는 않는다.** 실제 학습 실행에서 버전·코드 SHA·names·head shape·이전 로그를
기록하고 평가한다. 이번에는 코드를 읽었으며 학습·이전 성능을 시험한 것은 아니다.
읽은 설치 파일의 SHA-256은 `tasks.py`가
`c3896877977a1dca2ffaa1f4ad755ebd57342cae0ec80c78fa45edaa67f5823e`,
`torch_utils.py`가 `33bbd774f10bb8151b612a80aced680a2411e6b7d951596e65d2b9d0698263d5`다.
[Ultralytics fine-tuning 설명](https://docs.ultralytics.com/guides/finetuning-guide)은 참고이며
후속 버전의 동작을 현재 고정 환경의 보장으로 대신 쓰지 않는다.

신규 데이터만 학습하면 이전 클래스 성능이 저하될 수 있다.
[객체 검출의 증분 학습·망각 연구](https://arxiv.org/abs/1708.06977)를 참고해 다음을 고정한다.

1. 선택한 클래스의 **영상 내 모든 대상**을 주석 처리한다. 신규 deer만 라벨링하고 보이는
   person/car를 빠뜨린 학습 자료를 완전 주석 데이터처럼 사용하지 않는다.
2. 거리·각도·음영·조도·가림·부분 화면·복합 탑승자/유모차 사례를 포함하고, bbox의 가시 영역/
   전체 형상 기준을 일관되게 정한다. asset/actor ID와 영상 인스턴스 ID를 연결한다.
3. 이전 클래스 자료와 신규 자료를 함께 학습·평가한다. 필요하면 리플레이·증류를 독립 후보로
   비교하며 적용했다는 이유만으로 기존 성능 유지로 판정하지 않는다.
4. 인접 프레임을 무작위로 train/val에 섞지 않고 시나리오·actor·경로 단위로 분리한다.
   규칙 조정용과 최종 평가용 시나리오도 분리한다.
5. 그룹 평균뿐 아니라 에셋별 recall·오검출, 근거리·가림·음영 성능, 지연을 제출한다.
   미지원 물체를 obstacle로 묶었다는 사실을 검출 성공으로 세지 않는다.

출제 가능한 에셋은 우선 **검증 커버리지**이며 자동으로 102개 학습 클래스가 아니다.
정적/동적 여부는 실제 움직임의 추적 근거로 관리한다. 검증되지 않은 속도를 0이나 static으로
대체하지 않는다. MORAI GT와 gRPC는 개발용이며 본선 입력으로 사용하지 않는다.

## 시나리오 높이와 속도 GT

시나리오는 F2에서 지면에 배치하고 저장한 에셋별 위치·waypoint 높이를 사용한다.
후륜축·에셋 원점·바닥·BBOX 중심의 z가 같다고 가정해 일괄 설정하지 않는다.
외부 생성 시나리오는 F2 저장본과 원점/높이·지면 접촉을 비교한 뒤 데이터에 포함한다.
화재 효과와 충돌 형상, 정적 에셋과 이동 가능한 actor를 별도로 검사한다.

### LiDAR 속도 검증에 연결할 기준

운영진의 답변은 **순간 후륜축 속도 GT**의 기준을 제공한다. 부분 점군 평균의 위치 미분이나
추정 OBB 중심 속도와 동일한 기준점이라는 뜻은 아니다.

- 현재 [`morai_udp_bridge.py`](../../../src/asmc_bridge/scripts/morai_udp_bridge.py)의
  `handle_obj`는 `/Object_topic`의 `ObjectStatus.velocity`를 **km/h 그대로** 전달한다.
  이 경로의 GT는 각 성분을 **3.6으로 나누어 m/s**로 평가한다. Ego velocity는 이미
  m/s로 변환하는 다른 경로이므로 다시 나누지 않는다. 다른 수집 경로의 단위는 별도로 확인한다.
- 후륜축 GT와 비교할 추정값의 기준점·좌표·시간·자차 보상 여부를 먼저 맞춘다.
  local 상대속도를 map 절대속도 GT와 바로 비교하지 않는다. 패킷 관측 시간과 callback
  도착 시간을 구분하고 시뮬의 일시정지·속도 조정도 기록한다.
- 실제 BBOX 기하 중심 P의 속도가 필요하면 같은 관측의 후륜축 R에서 P로의 offset과
  각속도를 사용한다. 같은 좌표계에서 `v_P = v_R + omega × r_RP`다.
  평면 선회에서는 `omega = (0, 0, yaw_rate)`이고 yaw_rate는 rad/s다.
  객체 제원과 자세로 만든 offset을 사용하며 부분 군집 평균을 실제 P라고 가정하지 않는다.
- 현재 `ObjectStatus.msg`에는 객체 yaw rate가 없다. **Ego의 IMU yaw rate를 NPC의
  각속도로 대신 쓰지 않는다.** 독립 객체 각속도·제원·기준점이 확보되지 않으면
  BBOX 중심 변환 GT는 미확보로 남기고 후륜축 GT 평가와 구분한다.
  yaw-only 식을 roll/pitch가 있는 완전한 3D 기준점 변환의 보장으로 확대하지 않는다.
- Object Info·Semantic/Instance GT는 개발 데이터/평가에만 사용한다. 본선 운영에서는
  해당 입력과 gRPC를 끈다 ([본선 입력 경계](../../competition/README.md)).

현재 공개 속도·동정적 validity는 false다. Q&A만으로 이를 true로 승격하지 않는다.
재호의 후속 순서는 [위치·속도 관측 과제](../../packages/asmc_lidar/b1a-improvement-tasks.md)에 연결한다.

5. **학습·성능 수락:** A/B/C를 데이터 여건에 맞춰 비교하고, 선정 모델의 동시 부하·카메라 수·
   주기·FP16/batch/공유 처리·TensorRT·4070 SUPER를 각각 검증한다.

카메라는 관측·원본 라벨·준비 상태를 제공한다. LiDAR는 local 객체·연관·fusion·속도
유효성을 검증한다. 판제는 구간 활성화·회피 대상·주행 정책을 결정하며 차선 피팅은
음영구간에서만 소비한다. 기존 jamming 어댑터와 21% crop 기본 파라미터는 유지한다.

현재 결과와 직접 실행은 [COCO 확대 실험](../perception/camera-coco-class-expansion.md),
전체 개발 순서는 [카메라 런타임 계획](../perception/camera-runtime-plan.md)에서 확인한다.

## 2026-10-08 승인된 COCO 교집합 비교

사용자는 확인된 종류의 `person, bicycle, car, motorcycle, bus, truck, dog` 7종 비교를
승인했다. COCO 원래 ID는 `[0,1,2,3,5,7,16]`이다. train·bench·생활용품은 이 프로필에서
제외하며 신호등·정지표지판은 별도 인프라 관측으로 둔다. 102개 F2 전체 이름을 검수한
완결 목록은 아니며 신규 에셋 확인 시 정책 버전을 갱신한다. deer·나무 상자·콘 등은
COCO 교집합 밖의 신규 학습 과제다. 7종만으로 obstacle 그룹을 검출할 수 있다고 안내하지 않는다.

[7종 비교와 다음 학습 설계](../perception/camera-seg-model-selection.md#7종-미션-출력-비교와-학습-설계)는
기존 80종 실험과 분리된 opt-in 설정이다. 원본 세부 라벨을 보존하고 소비 그룹은
`person / animal / vehicle / obstacle`로 유지한다. LiDAR 네 클래스 호환 경로는 유지한다.
