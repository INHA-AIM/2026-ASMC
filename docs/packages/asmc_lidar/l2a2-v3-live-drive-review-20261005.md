# L2-A2-V3 새 터널·횡경사 연속주행 검증 (2026-10-05)

## 결론

**실제 도로 안에서 터널 진입·내부·복귀와 횡경사 램프를 다시 주행했다.**
초기 native cruise가 터널 밖으로 이탈한 기록은 제외했다. 재수집은 지도 경로
직접 추종과 1 m 이탈 중단 조건을 사용했고 전방 영상으로 도로 안 주행을 확인했다.

- 재호 일반도로 RANSAC의 터널 평면 선택 급변이 실제 입력에서도 확인됐다.
- 현재 Patchwork++와 linefit 설정 모두 램프에서 지면 잔여가 크게 증가했다.
- **기존 linefit 연구 선택을 전 구간 주력·운영 선택으로 승격하지 않는다.**
  평지 객체 보존 장점은 이전 GT 근거로 남지만 경사 한계를 새로 기록한다.
- 이번에는 지면 파라미터, 군집화, 운영 연결을 수정하지 않았다. 세 방법 중
  하나가 모든 조건을 통과했다고 선언하지 않으며 기존 운영 기준선을 유지한다.

이 문서는 [앞선 V3 비교](./l2a2-v3-attitude-tunnel-selection-20261005.md)의
실주행 미완료 항목을 보완한다. 과거 점수와 당시 미검증 사실은 덮어쓰지 않는다.

## 수집·정합 계약

현재 branch 시작 revision은 `23c5f329`, 알고리즘 설정은
`ground_v3/roll_pitch_all.yaml` (SHA `cbd04490…`) 그대로다.
센서 설정 파일 SHA는 `6af452d0…`다. 사용자가 GT 센서셋을 로드했다고 확인했고
세 점군 XYZ가 일치함을 검사했지만, RPC로 장착 위치를 다시 읽어 검증한 것은 아니다.
브릿지의 receive stamp를 광선 측정 시각으로 취급하지 않는다.

각 장면 시작 전 한 번 이동한 뒤 실제 차량 물리로 연속 주행했다.
측정 중에는 순간이동하지 않았다. 기존 NPC·보행자·장애물은 생성·이동·삭제하지 않았다.
속도 요청은 평지/터널 8 km/h, 램프 12 km/h이며 속도 달성 여부는 RPC 상태로 남겼다.
램프는 경쟁 전역경로 밖의 보조 강건성 시험 도로 A1203→A1184다.

램프의 |roll|≥2° 노출은 57.9 s다. 이는 벽시계 시간이며 simulator time으로
환산하지 않았다. roll은 현가 거동도 포함하는 차량 자세다. 도로·영상과 함께
검토했지만 횡경사 각도 자체의 정답이라고 부르지 않는다. 실주행 ±5° roll은 미검증이다.

semantic/instance는 **동일 순서의 유한 XYZ 전체 SHA가 정확히 같은 경우만**
연결했다. 라벨 스캔은 한 번만 사용하며 수신 시각 차이는 최대 250 ms다.
실제 라벨 수신 차이 p99는 터널 약 4.7 ms, 램프 약 6.1 ms였다.
GT는 채점용이므로 나중에 도착한 라벨을 연결할 수 있지만, 알고리즘 자세는 scan
도착 전에 수신됐고 관측 stamp 이하인 IMU만 사용했다. 간격 상한은 100 ms다.
선택 구간의 IMU 부적합 제외는 일반 5 / 터널 5 / 램프 13스캔이었다.
유효 입력에서 XYZ 대응 실패는 0건이다.

**세 새 주행 모두 ROI에서 차량·보행자·배치 장애물 instance 평가 관측이 없었다.**
따라서 추가 소실 0이라는 빈 통계를 객체 안전성 통과로 사용하지 않는다.
객체 보존은 이전 raw·동기 GT 결과가 근거이고, 이번 자료는 도로/구조물·자세/시간의
추가 시험이다. 온전한 벽·천장 전용 GT도 없다.

### 터널의 재호 평면 선택

A126 내부 901스캔에서:

- 지면 평면 선택 실패 1회.
- 선택 평면의 센서 원점 높이 > -1 m: 30회, 그중 > 0 m: 8회.
- 0.3 s 이내 인접 유효 관측에서 선택 높이 차이 > 0.5 m: 82회.

대표 `drive_001235`는 선택 높이 +1.102 m, 지지점 1,198개다.
법선 조건은 통과했지만 높이 gate가 없는 기존 일반도로 경로의 결과다.
양의 높이 선택은 의심 신호이며 **실제 천장 선택 8회라는 정답 판정은 아니다.**
상세 평면·구간·시각은 `tunnel_details.json`, 같은 프레임 BEV/측면은
`tunnel_positive_plane.png`에 있다. 실제 물리적 관측 변화와 동일 입력의
비결정성도 구분한다.

### 램프의 두 후보

- Patchwork++ 잔여 아스팔트 816,335점 중 746,871점(91.49%)은

  지면 평면 거리만 조절해야 한다는 결론이 아니다.
- linefit 잔여 아스팔트 1,559,221점 중 1,549,950점(99.41%)은

진단 메시지 수는 누락 scan 수와 같지 않다. sensor missing 시 화면을 지우는
동작은 평면 선택 급변과 별도다. live와 bag GT는 서로 다른 수신 시각으로
구간을 자르므로 같은 집계가 아니다. 터널 valid 수에 차이 1이 있으며 이를
숨기거나 정확한 상태 재현이라고 하지 않는다.
오프라인은 첫 채점 scan에서 적응 상태를 초기화했고 live는 측정 전 예열이 있었다.
램프의 작은 ROI 점 수, 시뮬레이터 속도 및 일부 보조 자료 읽기 부하가 다르므로
위 표로 알고리즘 단독 속도 순위를 정하지 않는다. 세 방법 동시 실행의 관측값이다.
15 Hz 설정이 실제 15 Hz 수신을 보증한 것은 아니며 통합 15 Hz 수락은 여전히 남는다.

C++ 코어 5시험, 기존 지표 6시험, 신규 GT/재생 격리 5시험을 통과했다.
램프 754스캔과 터널 2,360스캔의 반복 마스크·계보·stamp는 일치했다.
관측·GT·결과 해시는
[실주행 manifest](../../../config/baselines/lidar_l2a2_v3_drive_20261005.yaml)에 있다.

## 제외한 시험과 복원

`tunnel_all`은 native cruise가 경로 밖으로 나가 중단했고,
`banked_path_all`은 simulator 속도 명령이 오르막에서 후진해 1 m
이탈 조건으로 중단했다. 둘 다 `complete=false`로 보존하고 채점에서 제외했다.
`general_all`, `curve_path_check`는 초기 탐색 기록으로 주 비교에 합치지 않았다.

최종 collector는 경로 직접 추종, 후진 중단, 램프용 분리 PI 종방향 제어를
지원한다. 이는 simulator 시험용이며 판제 코드가 아니다. 복원 과정에서
`SetTransform` 왕복 yaw가 약 +1.34° 달라지고 gear가 D로 초기화되는
현상도 발견했다. 제한된 readback 보정 직후 기어를 다시 지정하도록 보강했다.
첫 복원 검증 실패도 보존했다. 최종 `final_restore_verified.json`은 최초 위치
오차 약 2.5 mm, yaw 오차 -0.0036°, P단·키보드·정지 상태를 확인했다.
bridge는 계속 실행 중이고 시험 review/recorder/replay 노드는 모두 종료했다.

## 확인 방법과 다음 판단

[재실행 안내](../../../tools/lidar/ground_v3/README.md)의 실시간/기록 재생
명령을 사용한다. 기존 RViz의 세 방법 그룹을 하나씩 켜고 `Ground plane fits`와
`ground_live/status`를 같이 본다. 기록 전용 launch는 candidate 출력만
발행하므로 bridge를 끄지 않아도 되지만 live 비교 노드와 동시에 실행하지 않는다.

현재 결론은 **전 구간 단일 지면 제거기 확정 보류, 운영 기준선 유지**다.
linefit의 평지 객체 보존 근거와 새 램프 실패를 함께 보고 사용자가 검토한다.
새 객체 배치/검출 정확도 수락, ±5° 실제 roll, 단독/전체 통합 15 Hz,
GT 없는 대회 버전과 전 미션은 남아 있다. 군집화나 운영 입력을 자동으로 교체하지 않는다.
