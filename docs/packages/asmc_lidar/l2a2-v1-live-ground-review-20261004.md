# 실시간 지면 비교와 잔여점 구조 평가

2026-10-04 L2-A2-V1. **비교·측정 기반 구현이며 지면 알고리즘 채택이 아니다.**
재호의 지면 제거가 더 강한 대신 관측된 장애물 하부까지 제거하는 사례와,
linefit/Patchwork++가 객체를 더 보존하면서 바닥 조각도 남기는 현상을 별도로 측정했다.
기존 군집·OBB 점수로 지면 방법의 합격 여부를 정하지 않는다.

## 구현과 고정 조건

실행은 [비교 시각화 안내](ground-method-comparison-visualization.md)와
[패키지 README](../../../src/asmc_lidar/README.md)를 따른다.
새 오프라인·실시간 경로는 같은 `GroundComparison` 코어를 사용한다.

공통 유한 ROI → 10cm voxel → pitch 수평화까지 scan당 한 번 계산한다.
각 backend의 상태는 독립이고 시퀀스 경계에서 초기화한다.
원본 ROI 인덱스에 분류를 복원하므로 관측 intensity와 stamp를 그대로 보존한다.
출력 XYZ는 역수평화 후 장착 변환과 동등한 원본점 장착 변환으로
rear-axle `base_link`에 놓는다. 내부 센서 원점 수평 좌표를 base_link로 속이지 않는다.

| 방법 | 동결 조건 |
|---|---|
| 재호 | `6435af1` 일반도로 소스 단계, pitch만 보정, 기존 RANSAC 설정. 지면 탐색의 수직 평면 제거는 별도 마스크 |
| Patchwork++ | `3e6903a1…`, H1 singleton 보류·고정 높이 1.80m, RNR OFF, 1~60m. 기본 `guard25`, `fixed_height`로 높이 보호 전 결과 선택 |
| linefit | `e6b9418…`, VLP16 90sector×60bin, height1.78m, gap2m, 거리 오차5cm, 기존 4thread fit/assignment. 삽입만 순차 처리 |

linefit 기준 논문은 Himmelsbach 등의 **Fast Segmentation of 3D Point Clouds for
Ground Vehicles**, IEEE IV 2010이다. 최신 SOTA라는 주장이 아니라 비교 가능한
고전 기준선이다. 출처·라이선스·변경 내역은
[vendor 기록](../../../src/asmc_lidar/vendor/linefit/PROVENANCE.md)에 있다.
개인 workspace의 `docs/papers/`에 보관한 PDF는 팀 runtime 의존성이 아니다.

## GT와 평가 분모

raw 4,048프레임과 동기 1,439프레임의 **같은 공통 ROI에서 실제 관측된 점**을
전수 평가했다. 독립 객체 수가 아니라 반복된 객체 관측을 포함한다.
source manifest와 snapshot은 기존 `20261004_gt_dual_ground`에서 그대로 사용한다.
raw의 기존 입력 승인·제외 정책을 바꾸지 않았다.

[MORAI 26R1 센서 문서](https://help-morai-sim.scrollhelp.site/ko/morai-sim-drive/26.R1/-33)는
instance ID를 차량·보행자·배치 장애물에 부여하고 다른 객체에는 할당하지 않는다고
설명한다. 실제 ROI의 아스팔트127·보도129·건물153·StandingOBJ109·ETC10은
모두 instance0이었다. 반사 intensity는 종류/개체 GT가 아니다.
StandingOBJ·Building을 벽 정답으로 치환하지 않았다.

객체는 semantic+nonzero instance별로, 배경은 semantic별 2m 수평화 센서원점
XYZ cube와 공간 이웃 관계로 계산한다. instance0은 객체로 묶지 않는다.
하부·중부·상부는 **관측점 z 범위의 3등분**이며 검증되지 않은 전체 객체 box
높이가 아니다. 10점 미만 관측은 별도 표로 저장한다.

연결 관계는 삭제 전 GT 그룹의 점으로 고정하고 0.2/0.4/0.8m에서 같은 그래프에
각 방법의 마스크만 적용한다. 원래 희소 관측의 분리와 필터가 추가한 분리를
구분한다. 0/100% 보존을 무조건 일관성이 좋다는 뜻으로 해석하지 않는다.
미분류는 지면 삭제와 구분한다. 시간적 재관측 대응 검증이 없어 **시간 안정성
점수는 미산출**이며 단순 점 수 변화로 불안정성을 주장하지 않는다.

## 객체 보존 결과

10점 이상 관측만의 point-weighted 보존율이다. 괄호는 완전 지면 삭제 관측 수다.
지면 단계 결과이지 최종 검출 recall이나 차량 제어 성능이 아니다.

| 자료 | 클래스와 관측 수 | 재호 | Patchwork++ guard25 | linefit |
|---|---|---:|---:|---:|
| 동기 | 차량 1,027 | 93.85% (0) | 98.25% (0) | 99.52% (0) |
| 동기 | 보행자 482 | 82.37% (0) | 92.57% (0) | 95.32% (0) |
| 동기 | 장애물 870 | 71.32% (88) | 87.64% (25) | 94.13% (2) |
| raw | 차량 249 | 95.12% (2) | 98.14% (0) | 99.63% (0) |
| raw | 보행자 456 | 91.91% (0) | 97.49% (0) | 98.45% (0) |
| raw | 장애물 577 | 82.79% (26) | 91.28% (5) | 96.73% (1) |

동기 장애물의 **관측 하부 점 보존율**은 재호28.32%, Patchwork++65.55%,
linefit82.50%다. 이는 “아스팔트 100% 제거”만으로 객체 보존을 승인하면 안 된다는
실제 입력 근거다. 전체 객체 하부 형상을 안다는 의미는 아니다.

## 배경 잔여와 조각화 결과

아래는 동기 자료다. 괄호는 입력점10개 이상인 2m 구역 중 일부만 남은 구역 비율이다.
이 값이 높아도 경계·경사 때문에 합리적으로 나뉜 경우가 있으므로 실패율로 부르지 않는다.

| 클래스 | 재호 잔여율 | Patchwork++ 잔여율 | linefit 잔여율 |
|---|---:|---:|---:|
| 아스팔트 | 0.00% (0.00%) | 4.17% (8.33%) | 1.80% (3.80%) |
| 보도 | 0.01% (0.00%) | 39.60% (48.23%) | 62.35% (75.61%) |
| 건물 | 91.79% (33.09%) | 96.06% (18.63%) | 98.93% (7.59%) |
| StandingOBJ | 90.75% (46.90%) | 96.61% (21.16%) | 98.12% (15.12%) |

같은 0.4m 이웃 그래프에서 동기 보도의 추가 분리 조각 수 합은 재호0,
Patchwork++272, linefit3,643이다. 반면 아스팔트는 0 / 2,733 / 834다.
raw 보도는 0 / 2,955 / 9,841이고 아스팔트는 0 / 5,585 / 1,370이다.
서로 다른 표면에서 잘림 양상이 다르므로 잔여점 총량 하나로 후단 난이도를
단정할 수 없다. 재호의 0은 대부분 전부 삭제했기 때문이지 객체 온전함의 우위가 아니다.

건물·StandingOBJ의 높은 보존은 그 자체로 오검출이 아니다. 온전한 구조물인지,
지면 경계의 조각인지 점 분포를 함께 봐야 한다. 후단 제거 용이성은 아직 가설이며
각 backend에 적합한 구조물·군집 처리로 별도 검증한다.

## 재현성 수정과 검증

기존 재호/PP 결과는 raw4,048 + 동기1,439 모두 exact parity다.
linefit의 원래 병렬 bin 삽입은 최소 z와 해당 range를 별개 atomic에 저장하므로
동일 바이너리 반복에서도 일부 마스크가 달랐다. 원본 checkout은 수정하지 않고
SHA 검사 후 build 사본에서 **삽입만 입력 순서대로** 바꿨다.

수정 후 동기는 기존1,439프레임 모두 일치하고 raw는
`raw_000578`의 원본 인덱스649 한 점만 기존 고정 결과와 다르다.
수정한 raw4,048프레임 반복에서는 마스크·원본 계보·stamp가 전부 일치했다.
이를 허용 오차로 숨기지 않고 별도 parity JSON에 기록했다.
upstream 90sector/4thread의 정수 나눗셈 tail 문제는 이번에 바꾸지 않았다.
이 후속 수정은 튜닝과도 분리해 비교해야 한다.

Noetic Release 빌드, 기존 코어/좌표/IMU와 새 backend CTest4개,
지표 합성시험5개가 통과했다. 독립 ROS master에서 12개 실제 scan의
live/offline 분류·원본 인덱스·intensity·base_link·나노초 stamp를 비교했고,
영점/중복/역행·IMU stale/누락·NaN/빈 점군·중단 화면 삭제를 검사했다.
100 scan burst에서도 공통 대기열 누락 진단을 확인했다. 반복 ROS 시험 전에는
명시적인 시간 역행과 새 IMU 수신으로 시퀀스를 초기화한다.
군집화 없이 온전한 잔여와 같은 수의 흩어진 잔여, 하부 삭제, 완전 소실,
원래 희소 관측, instance0/미분류를 구분하는 시험이다.

## 실시간 계측과 남은 수락 범위

기존 bridge·GT 설정을 건드리지 않고 세 방법과 RViz를 실행했다.
실행 중 bridge는 실제 `source` stamp였으며 진단에서 이를 확인했다.
첫65초 구간은 입력9.50Hz, 처리9.43Hz, 내부 queue drop0, IMU stale5건이었다.
관측 callback 이후 발행까지 p50/p95/p99는 18.24/28.90/36.77ms였다.
이는 송수신·광선 생성 지연을 포함하는 센서 전체 지연이 아니다.

| 첫65초 비용 ms | p50 | p95 | p99 |
|---|---:|---:|---:|
| 공통 ROI voxel 수평화 | 15.85 | 25.00 | 30.94 |
| 재호 지면 단계 | 0.455 | 0.582 | 0.950 |
| Patchwork++ 분할 | 0.419 | 0.716 | 1.146 |
| linefit 분할 | 0.655 | 1.136 | 2.116 |
| 전체 계산 | 17.60 | 27.67 | 35.83 |
| 대기 | 0.026 | 0.046 | 0.102 |
| 발행 | 0.547 | 1.036 | 1.471 |

두 번째65초는 입력9.03Hz, 처리8.99Hz, queue drop0, IMU stale3건,
sensor_missing 진단3회였다. 끊김에서 화면을 지우며 누락을 정상 관측으로 숨기지 않았다.
동시 오프라인 평가·RViz 부하가 있으므로 위 수치로 알고리즘 단독 속도 우열을
승인하지 않는다. 현재 입력이 15Hz였다고 주장하지도 않는다.

**정차 live 확인까지 완료했으며 사람이 직접 운전하는 연속 RViz 수락은 남았다.**
gRPC 이동 검사는 전방 가까운 배치 객체 때문에 사전 검사에서 중단했고 차량·객체
배치를 변경하지 않았다. 기록 이름 `live_motion_monitor`와 `live_bounded_monitor`는
이동 시도 당시의 파일 이름이며 두 구간 모두 정차였다. 준비된 launch로 수동주행하며
확인할 수 있다. 재생·정차 검증을 전 미션 주행 수락으로 확대하지 않는다.

다음은 사용자 화면 검토 후 **Patchwork++와 linefit을 각각 독립적으로 환경 조정**한다.
linefit의 미처리 tail·보도 조각, Patchwork++의 높이 보호와 지역 평면 오류를
혼합하지 않고 하나씩 비교한다. 설정 동결 후 객체 온전함/표면 조각/시간 안정성/비용을
다시 평가하고, 그 다음 각 출력에 적합한 구조물·군집화로 진행한다.
재호 1.5m Euclidean+OBB는 기존 결합 특성 참고이며 지면 합격 기준은 아니다.
