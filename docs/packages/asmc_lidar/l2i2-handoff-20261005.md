# L2-I2 — `asmc_lidar` 후보 추적·좌표·메시지 인계

> **상태: 개발·검토 후보, 판제 운영 입력 미교체.** 기준은 [manifest](../../../config/baselines/lidar_l2i2_20261005.yaml),
> [토픽·MD5 계약](../../../config/contracts/lidar_candidate_topic_contract_v1.yaml)이다.
> 원본 `lidar+sensorfusion`와 `/last_lidar`, `/lidar_nogps`, `/perception/objects`는 그대로 남겼다.
> 별도 `Msg` workspace를 source하지 않아도 기본 경로가 빌드·실행된다.

> **2026-10-05 후속 이전 결정:** 최종 패키지는 `asmc_camera`와 `asmc_lidar`이며,
> 카메라 분류 fusion은 LiDAR 내부에 둔다. 손재호가 원본 기능을 보존하며 개선사항을
> 반영·이전한다. [상세 이전·수락 계획](../../architecture/consolidation-roadmap.md)의
> 「카메라 이름 변경과 손재호 LiDAR 이전 상세 계획」을 따른다. 아래 후보 CV tracker를
> 원본 CA tracker와 동등한 이식본으로 인계하지 않으며 운영 입력은 아직 교체하지 않는다.

## 공유 브랜치와 실험 이력

사용자가 만든 LiDAR 작업의 공유 브랜치는 `feat/asmc-lidar-integration` 하나로 정리한다.
merge `0d34226`은 통합본 `32456b8`의 파일 tree를 그대로 유지하면서 실험 끝점
`744e272`를 두 번째 부모로 연결했다. 따라서 초기 `feat/lidar-l1a-assessment`,
`feat/lidar-l1b4-geometry`, `feat/asmc-lidar-runtime`의 커밋 이력도 이 브랜치에 포함된다.
재호의 `feature/lidar-*` 원격 브랜치는 별개이며 변경하지 않았다.

이후 사용자 요청에 따라 미커밋 50개 파일(GT 센서/bridge/수집기와 연구 도구)을
`f1dfb84`로 보존했다. `74f03d7`에서 그 전체 스냅샷을 같은 원격 integration 이력에
먼저 push하고, `523a63b`에서 원래 `a39b28d` 파일 tree로 정확히 복원해 push했다.
강제 push는 하지 않았다. **GT 변경은 이력에 보존됐지만 복원된 실행본에 자동 적용된 것은 아니다.**
`asmc-lidar-l2a2` worktree와 로컬 runtime 브랜치는 제거했으며 비Git 산출물/컨테이너 로그는
`$ASMC_DATA/lidar_assessment/worktree_archives/l2a2-closeout-20261005.kgT2t5/README.md`에
복구 방법과 함께 보관했다. 같은 소스가 필요하면 `f1dfb84`에서 새 worktree로 복구한다.

Patchwork++와 linefit의 연구 자료·설정·비교 도구도 보존한다. `unified.launch`는 재호 지면만
계산하지만 연구 backend가 공통 빌드·회귀시험에 연결돼 있으므로 삭제하려면 먼저
운영 target과 연구 target을 분리해야 한다. 이번 이력 통합에서는 삭제하지 않는다.

## 이식한 것과 의도적으로 다른 것

| 단계 | 원본 근거 | 현재 후보 | 차이·인계 경계 |
|---|---|---|---|
| ROI/voxel·지면 | 재호 `6435af1`, V4 보완 `jaeho_support` | `ground_live.cpp`, `unified.cpp`; 전 구간 동일 설정 | 과거 일반/터널 분기는 연구용 launch에만 남음. 기존 V4 지면 parity는 회귀로 유지 |
| 군집·OBB | 원본 `Clustering.cpp`, L-shape | 1.5m Euclidean, `unified.cpp` | 프레임별 기하 기준선. 분할/누락·큰 OBB는 해결하지 않음 |
| tracker | 원본 `Tracking.cpp`, `HungarianAlg`, `Kalman`, `MotionClassifier` | 독립 `tracking.cpp`: 거리+IoU Hungarian, age/miss, yaw 안정화, 속도 상태 | **정확한 수치 parity 아님**: 원본 CA 필터·동정적 히스테리시스 대신 후보 CV 필터/단순 10km/h 기준. GPS 모드 재설정 제거. 손재호가 정확도 회귀 후 개선할 지점 |
| 카메라 분류 | 원본 `FusionCamera.cpp`, `FusionClassPolicy`, YOLO11m | 선택 입력 `/perception/camera/objects`; Camera-1 box 투영, 초기 5회·변경 3회 확인 | YOLO 실행기·weight 이동 없음. 레거시 `Msg` relay는 명시적으로 켤 때만 필요. 미수신/빈/지연은 미확정이지 객체 없음 아님 |
| 좌표·속도 | 원본 map/`velodyne` 혼재 | 수평화 역변환→v3 장착 변환→후륜축 `base_link`; 별도 관측시점 map 어댑터 | GPS는 local tracker reset 조건 아님. 상대속도와 자차 twist를 분리; twist 없으면 절대속도 invalid |
| 구조물 | 기존 지면 탐색 평면 | 구조물 근거 점군·품질 후보 | 자동 억제 OFF. 벽/가드레일·차량 측면 분리는 손재호 후속 수락항목 |

원본 추적의 연관·생애주기와 선택적 분류 **기능 경로**는 연결했지만, 원본 tracker의
수치 결과가 그대로 재현됐다는 뜻은 아니다. 이 차이를 숨기고 운영으로 승격하지 않는다.
재호 최신 `8dde9b6`의 GPS 분기·크기만으로 천장/큰 OBB를 삭제하는 패치는 자동 이식하지 않았다.

## 실행과 확인

기존 ROS 컨테이너가 다른 worktree를 마운트했다면 실행 중인 노드를 종료한 후에만
`scripts/docker_ros_up.sh up`으로 전환한다. bridge는 **별도 터미널**에서 유지한다.

```bash
cd /root/ws
source /opt/ros/noetic/setup.bash
catkin_make --only-pkg-with-deps asmc_lidar -j2
source devel/setup.bash
./scripts/udp_bridge.sh
# 다른 터미널, 같은 환경:
roslaunch asmc_lidar unified.launch
```

기본 RViz는 `base_link` 점군·구조물 근거·관측(초록)/예측(주황) OBB·ID·유효 속도를
표시한다. 연구용 과거 프레임 OBB도 토글 가능하다. 별도 map 창은 다음과 같다.

```bash
rviz -d /root/ws/src/asmc_lidar/rviz/map_tracks.rviz
rostopic echo /perception/lidar/objects_local/status
rostopic echo /perception/lidar/objects_map/status
rostopic echo /perception/lidar/map_status
rostopic hz /velodyne_points
```

입력 중단/무효 pose 때 marker는 지워진다. map 창에 아무것도 안 보일 때 local이
중단됐다고 판단하지 말고 `POSE_UNAVAILABLE`와 진단 이유를 확인한다.
`legacy_yolo_bridge:=true`는 nested `Msg` overlay가 준비됐을 때만 켠다.
장래 `asmc_camera`(현재 `asmc_perception`)의 YOLO 생산자가 같은 공통 카메라 계약을
직접 발행하도록 이전한다. 이름 변경과 생산자 이전은 아직 실행하지 않았다.

| 후보 출력 | 의미 |
|---|---|
| `/perception/lidar/objects_local` | rear-axle `base_link` 관측/예측·ID·분류/속도 유효성. LiDAR+IMU로 계속 실행 |
| `/perception/lidar/objects_map` | **동일 객체**를 관측시점 pose로만 변환. pose 부재는 상태 4 `POSE_UNAVAILABLE`, 정상 빈 관측은 상태 2 `OBSERVED_EMPTY` |
| `/perception/lidar/tracked_objects` | 옛 `asmc_msgs/TrackedObjectArray`가 표현 가능한 **관측 프레임만** 발행. 예측·unknown 필드 보존용 아님 |
| `/perception/objects_lidar_candidate` | 옛 `asmc_msgs/DetectedObjectArray`로 격리된 Frenet converter 시험용. 기본 planner 토픽과 다름 |
| `/lidar_candidate/unified/{nonground,structure_evidence,tracks,map_tracks}` | 디버그 시각화. 구조물 근거는 자동 삭제·벽 GT가 아님 |

배열 stamp는 scan의 bridge 수신 시각을 보존한다. 이는 개별 광선 발사 시각이 아니다.
카메라 box는 Camera-1 원본 픽셀 좌표·stamp를 보존한다. unknown 속도·동정적 상태는
0 또는 static으로 위장하지 않는다. 기존 호환 타입에 담을 수 없는 관측 프레임은
무발행하고 상태형 원본은 남긴다. 기존 `Msg` 타입은 오직 선택 relay 경계에만 있다.

## 검증, 제한, 되돌리기

- Noetic 독립 컨테이너 빌드·`build/asmc_lidar`의 CTest 9개, 새/기존 메시지 직렬화가 통과했다. 새 타입만 추가했고 기존 `DetectedObject*`, `TrackedObject*` MD5는 그대로다.
- 연속 bag은 normal→tunnel→recovery가 들어 있는 manifest의 동일 입력을 격리 ROS master에서 재생한다. `rosbag play -r 1.5`는 **도착률 부하 시험**이며 센서 실제 15Hz 동작을 보증하지 않는다.
- 전체 bag 2,409 scan의 1.5배 재생은 약 16.14 scan/s 도착했다. headless 최적화 전/후 queue drop은 **111→57**, 계산 p99는 **88.48→75.29ms**였다. 구독자가 없는 5종 지면 점군의 중복 생성만 줄인 결과이며, 여전히 **지속 15Hz 처리 합격이 아니다**. 실제 센서 15Hz·카메라 동시 실행·RViz 켠 상태는 별도 검증해야 한다.
- 최적화 후 local은 관측 2,048 / 정상 빈 299 / 입력 무효 8프레임, map은 pose 불가 769프레임이었다. map 불가 중 678건은 GPS fix가 scan 시각에 stale/missing, 84건은 Ego 표본 간격 100ms 초과였다. map을 일반 빈 배열로 만들지 않았다. 최대 40개 객체가 나온 프레임이 있어 검출 품질은 미승인이다.
- 실제 main Frenet `ConvertDetectedObjects`를 수정하지 않고 격리 후보에 연결한 20초 시험은 167메시지/537객체 모두 OK였다. 이는 Behavior·MPC 전체 승인이 아니다.
- 현재 main의 Behavior는 GT 경로를 사용한다. 서준 `8b3f0b1`의 `DetectedObjectArray` MD5는 main과 달라 그대로 병렬 연결할 수 없다. 강태 음영 소비 코드는 이번 기본 launch에 붙이지 않았다.
- live 26R1에서는 source LiDAR 약 9.5Hz, Ego 약 18.9Hz, GPS 약 2.4Hz가 관찰됐다. Ego stamp 간격 150개 중 68개가 100ms 초과여서 엄격한 map 보간은 상당수 보류됐다. local tracker는 계속 동작했다. map 가용성과 실제 센서 15Hz는 **운영 승격 미통과**다.
- 다른 25초 live 관찰에서는 LiDAR 약 12.8Hz, local 320프레임 모두 관측, map 263프레임 관측/57프레임 보류, 누적 queue drop 0, 계산 p50/p95/p99 = 19.90/23.97/25.65ms였다. 이는 시뮬 상태·입력률이 달라진 별도 실행이지 앞의 16Hz 상당 연속 재생 실패를 지우지 않는다.
- 제한 8m/14초·원상복구가 있는 gRPC 저속 smoke는 시작 당시 Ego가 이미 움직여 **이동 전 안전 검사에서 중단**했다. 새로운 수동 주행이나 동적 actor 배치는 수행하지 않았고, 연속 구간 평가는 저장된 실제 주행 bag을 재생했다.
- 기존 지면 하부 삭제·군집 분할, 장면에 따라 잘못된 큰 OBB, CV/동정적 수치 parity 미검증이 남는다. 카메라 동시 부하·이동 객체 ID/속도 GT 수락도 남는다.

재실행: 기존 bridge·운영 노드를 끄지 말고 **격리 master**에서
`roslaunch asmc_lidar unified.launch rviz:=false`와 bag을 시작한 뒤
`python3 -B tools/lidar/l2i2/replay_probe.py --seconds 30`으로 상태를 본다.
Frenet 격리 시험 코드는 `tools/lidar/l2i2/frenet_candidate_probe.cpp`다.
원본 source와 메트릭을 같은 manifest와 묶는다. rollback은 이 후보 launch만 종료한다.

손재호에게 넘길 다음 작업은 우선 원본 tracker/분류 기능의 이식과 후보 차이 검증,
좌표·시간/단일 처리 경로/공용 메시지 연결의 마무리다. 이후 구조물 억제의 객체 보존 회귀, 군집 분할/합침,
tracker ID·속도·동정적 안정성, camera 매칭 정확도다. 15Hz 통합 부하와
map pose 가용성이 통과하고 판제 MD5/소비 계약을 함께 맞추기 전에는
`/perception/objects` remap이나 구 패키지 삭제를 하지 않는다.
