# 황색 위치·정지 가능성 정책 구현 상태

기준: `feature/yuntae-yellow-light-policy`, `19bc76978a499bddacf13f5aaf0bb6d713785657`.
관련 시계 점검 도구·기록은 별도 작업이다. 기존 ROS 메시지는 변경하지 않는다.

## 실행 경계와 연결

기본 `signal_policy/mode=shadow`는 운영 출력 이후 독립 인스턴스·관측 journal·위치
이력·ID·타이머로 계산한다. `off`도 지원한다. `active`는 명시적으로 선택하며,
`/control_binding/enabled`, 검토된 지도, 실제 윤거, 원본 시계 캘리브레이션이
없으면 시작을 거부한다. 기존 ROS msg 정의는 그대로다. 추가 전송의 producer와
consumer는 [명령–궤적 연결 v1](control-binding-v1.md)을 함께 활성화한다.

운영 인스턴스만 Controller의 연결·경로·실행 증명을 받는다. 관측의 가상 ID와
판단은 운영 상태를 변경하지 않으며 실제 제동 성공으로 집계하지 않는다.
`/planning/signal_policy`와 `/planning/signal_policy_shadow`를 구분한다.

| 연결 | 구현 계약 |
|---|---|
| 원본 신호 | JPEG 원본 header·wire sequence와 SensorFrameTiming을 결합. ROS1 classifier가 바꾼 header.seq를 원본 ID로 사용하지 않음 |
| 초록 | 동일 K/시계 세대의 서로 다른 유효 원본 3프레임. 원본/수신 신선도·연속 공백 각각 0.3초 초기값 |
| 중간 정지 사건 | callback journal 128건, 황색·적색·invalid/stale 보존. 같은 원본 무효 tombstone 우선. overflow/미연결 원본은 UNKNOWN |
| 좌표 | 물리선 불변, 최종 후륜축 목표와 Frenet 기준점 분리. 입력에 +0.5m 후 Frenet에서 -0.5m 한 번 적용 |
| 목표 revision | 상위 명령과 native STOP에 명시 전달. BRAKING 유지, HOLD는 저장 목표 갱신·이전 완료 폐기·현재 위치 유지 |
| 원인 중재 | SIGNAL(K), 충돌, 보행자, 입력 무효, 실행 실패 독립. 초록은 다른 원인을 해제하지 않음 |
| 실제 제동 | 최초 tD 기준 watchdog, 응답 미검출 시 최대제동. heartbeat/revision은 deadline을 다시 시작하지 않음 |
| 첫 비상 출력 | 조향 이력·유효 경로 snapshot 보존, brake=1을 먼저 발행. 조향 최적화는 비동기이며 실패해도 제동을 지연시키지 않음 |
| 재출발 | 현재 C 사본·수락·실제 T의 원자적 전송과 Controller 검증 후 해제. 최신 시각의 이전 C 경로는 거부 |
| 기동 인계 | 명시적인 신호 STOP은 진행 중 AVOID/LANE_CHANGE/MERGE 잠금을 선점. 안전 경로가 없으면 비상제동 |

원본 촬영과 차량 이력으로 정상/불확실/초과를 기록하고 현재 행동과 분리한다.
추론 지연으로 통과를 포함하는 다음 초록 원본이 아직 도착하지 않은 동안에는
`ENTRY_PENDING_CLEAR`로 증명을 기다린다. 초록 허가와 연속 위치 이력 아래,
다른 정지 요구나 진행 중인 제동 없이 전륜이 물리선을 통과하면
`GREEN_CROSSING_CLEAR`를 고정한다. 그 뒤 카메라 시야 상실이나 새 적색으로
허가가 끊겨도 해당 SIGNAL(K)을 재적용하지 않고 교차로를 빠져나간다.
원본 순서로 정상 진입을 증명하지 못하면 `ENTRY_UNCERTAIN`은 기록한다.
이미 기록된 불확실/초과를 정상 진입으로 바꾸거나 삭제하지 않는다.
초록 원본 시각의 위치 이력을 직접 보간하여 오차를 포함한 전륜 통과가 확인되면
그 원본 시각을 통과 상한으로 사용한다. 더 늦은 최신 차량 상태 시각까지 추가
영상을 요구하지 않는다. 같은 원본 시각·연속 위치 이력·유효 허가의 확인 없이
이를 적용하지 않으며, 중간 정지·무효 사건이 먼저 반영되면 정상 진입으로 확정하지 않는다.
원본은 수신 순서대로 처리한다. 연속 허가와 위치 이력이 먼저 정상 통과를 입증한
초록 뒤에 적색이 같은 batch로 들어오면, 이미 입증된 정상 진입은 유지한다.
반대로 통과 입증 전에 정지 사건이 끼거나 이미 불확실·초과를 기록했으면 이후
초록으로 정상 진입을 만들어내지 않는다. 통과 창 전체의 위치 이력에서 가장 큰
측정 속도·양의 가속도 여유를 적용하여 중간 상태의 관측 오차를 줄이지 않는다.
활성 신호 구간에서 황색·적색·미검출/무효 관측으로 바뀌는 callback은 journal 잠금을 푼 뒤 같은
정책을 즉시 재평가한다. 다음 10Hz timer를 기다리지 않는다. 정상 진입 면제·
위치/위험 검사·원인별 중재·C–T 해제 검사는 그대로 적용한다. 반복 적색 원본마다
FSM을 추가 실행하지 않으며, 독립 관측 인스턴스에는 이 운영 wakeup을 연결하지 않는다.

초록 허가 아래 이미 물리선을 통과한 `GREEN_CROSSING_CLEAR`를 제외한
영역 밖의 불확실/초과는 제동한다. 위치·위험 정보가 무효가 되거나 다른
정지 원인이 생기면 그 원인의 제동을 유지한다. 제동 뒤 재개에는 현재
명령에 연결된 안전한 이탈 경로를 요구한다. 영역 안 복구는 위치·위험 정보와 이탈 경로,
다른 원인 해제·현재 C–T 연결을 요구한다. 적색/UNKNOWN에서도 해당 SIGNAL(K)만
제외할 수 있으며, 검증된 내부 복구에 초록 3프레임·완전 정지를 강제하지 않는다.
일반 비상제동 재출발은 정지 확인과 초록 3프레임을 요구한다.
정지선 초과 후 충돌 영역 전 정지에서는 새 초록 3원본과 완전 정지, 다른 원인
해제 및 현재 명령의 전체 이탈 경로가 확인되어야 재진입한다. 이미 실패한
정지 목표를 복원했다고 판단하지 않는다. 초록 허가와 연결·위치 연속성·전체
경로가 유지되면 출발 후 영역 안에 도달할 때까지 진행할 수 있다. 물리선
통과 전 신호 허가가 철회되면 제동한다. 통과 뒤에는 위의 초록 진입 계속
규칙을 적용한다. 내부 복구의 적색 예외와 구분한다.
이미 현재 K에서 경로·연결이 검증된 복구 이탈은 출구의 위치 오차 경계에서도
계속할 수 있다. 위치 이력이 연속되고 현재 검증된 이탈 구간에 있으며 현재
이탈 경로·위험 조건을 만족해야 한다. 충돌 영역 끝과 최종 출구 사이에서도
기존 복구를 유지한다. 차체 뒤끝과 오차까지 완전히
벗어난 뒤 완료한다. 경계 구간에서 새 복구를 시작하거나, 위치 이력 공백·재배치
후 이 허가를 재사용하지 않는다. 다른 정지 원인은 이 경계에서도 우선한다.
복구 허가를 새 명령의 경로로 인계할 때는 동일 K의 제한된 조건부 대기를
사용한다. 새 위험은 즉시 철회하고 Controller는 현재 명령의 전체 이탈 경로가
연결되기 전 제동을 유지한다. heartbeat로 대기 기한을 연장하지 않는다.

아직 제동을 시작하지 않은 이동 차량은 신호 UNKNOWN에서도 정지 가능한 목표로
APPROACH할 수 있다. 공통 정지거리+3m 초기 여유 전에 BRAKING으로 전환한다.
이는 선을 넘는 허가가 아니다. BRAKING/HOLD 시작 후 목표가 멀어져도 재접근·
재가속하지 않는다. 이미 안전하게 정지한 HOLD의 목표 미달성과 정지 유지는 양립한다.

## 검토된 지도 입력

`signal_policy/geometry_path`에 `config/behavior/signal_policy_geometry.yaml` 형식의
검토된 파일을 지정한다. 기본 목록은 비어 있으며, K-city 2025의 별도 시험
파일 `signal_policy_geometry_kcity2025.yaml`에는 실제 설치본의 도색·신호·경로 연결과
15m/6m 정지 카메라 색상 대조 결과를 반영했다. 30m 일부 미검출은 허가로 승격하지 않는다. 정지 노드 위치를 실제 정지선
형상이나 충돌 영역으로 자동 승격하지 않는다. `half_track_m`도 임의로 채우지 않는다.
`source_clock_verified`는 기본 false다. 값이 없으면 진입 허가를 만들지 않는다.

충돌 영역은 교차로 전체 외곽이 아니라 실제 횡단·합류 차로 corridor와 자차
진행로가 겹치는 영역으로 만든다. 동일 진입 차로의 대안 경로는 제외한다.
정지선 직후 대기 공간을 충돌 영역으로 잘못 포함하여 적색 이탈을 허가하지 않는다.
출구는 해당 진행 connector의 끝이며 차체 뒤끝·오차까지 벗어나야 완료다.
`freshness_s`, `observation_gap_s`, `position_error_m`, `front_clearance_m`은 실측
검증 후 조정할 초기값이다. 공백 상한은 신선도 상한보다 클 수 없다. 위치 오차에는
지도·추종·자세 오차가 차체 앞 모서리에 만드는 위치 오차까지 보수적으로 포함한다.
diagnostics의 `physical_line_band`는 ±0.5m 위치 구간이며 출발 허가를 만들지 않는다.

원본 촬영 시각의 위치 이력으로 정지선·진행 방향을 연결한다. 현재 위치의 다음
정지선만 원본에 붙이지 않는다. 이동 후에도 현재 사건 K는 검증된 이탈까지 유지한다.
전역 경로 초기화, 시각 역행 또는 명백한 재배치는 허가를 무효화한다. 재배치 탐지의
초기 여유는 `위치 오차의 2배 + 속도 × 경과시간`이며 현장 오차 검증 대상이다.

## 수치와 시각

- 접근 상한 25km/h 유지. 정지 계산은 실제 측정 속도·가속도를 사용한다.
- 기본 최종 목표 약 5.5m. 직선·무오차 늦은 목표는 `3.845 + 0.5 = 4.345m`.
  실제 늦은 목표는 경로 자세·앞 모서리·위치 오차로 다시 검사한다.
- 통과 사건은 물리선 거리 0에서 기록한다. ±0.5m 확정 여유는 진입 허가가 아니다.
- 판단 tD → 실제 제동 응답 tR 예산은 `max(0.5s, 실측 최대 + 0.1s)`.
  차량 상태 나이는 한 번 보정하고, 영상 나이를 이동거리에 다시 더하지 않는다.
- 초기 응답 검출은 기준 가속도보다 0.2m/s² 이상 감속 증가(최소 -0.2m/s²)와
  속도 0.02m/s 이상 감소를 새 상태에서 함께 요구한다. 실측 검증 전 운영 보장값이 아니다.
  일반 제동의 기존 감속만으로 최대제동 강화 응답을 인정하지 않는다.
- 예산 초과는 실패다. 뒤늦은 감속으로 실패를 지우지 않는다. 최대제동 미응답은
  최대제동 유지와 실패 기록으로 처리한다.
- 이미 정지한 HOLD에는 감속 시작 검출을 요구하지 않는다. 이후 움직이는 제동
  요청은 새로 감시한다. 실행 실패 해제는 초록이 아닌 실행 owner의 명시적 안전
  확인과 신선한 정지·연결 증명으로만 허용하며, 과거 사건 기록은 유지한다.
- 일반 제동 모델 한계 초기값은 4m/s², 4.8m/s³. 최대제동 명목 8.9m/s²는
  현재 MORAI의 실측 하한이 아니다. partial-pedal LUT를 brake=1까지 외삽하지 않는다.
  STOP 경계 가속도 정규화 함수도 공유한다. 정책은 실측 원본과 정규화한 경계의
  정지거리 중 큰 값을 사용하여 정규화로 생기는 낙관적 판단을 막는다.
- 일반 비상제동 재출발 정지 확인은 0.15m/s 이하 0.2초 유지 초기값이다.
- 내부 복구 목표는 `recovery_speed_mps=2.0m/s` 초기값이다. 실제 측정 가속도와
  응답 지연을 반영한 Controller 상한도 적용한다. 위치 이력의 출구 오차 구간과
  충돌 영역 이후의 검증된 이탈 구간까지 현재 복구를 유지한다.
- 시험 차량의 앞/뒤 범위는 후륜축 기준 3.845/0.79m, 실제 전륜 반윤거는
  0.814m다. 사양 폭 1.892m와 설치본 외곽 물리 collider 폭 약 2.161m를
  구분한다. 신호 차체 여유에는 더 큰 외곽 폭을 적용한다.
- 위치 오차 0.5m는 최초 관측 기본값이다. 이 설치본의 통제 시험 프로필은
  고속 접근의 차체 위치 대조 약 0.521m를 반영하여 **0.7m**를 사용한다.
  전체 구간에서는 정책 범위 밖 고속 주행에서 약 0.663m도 관측했다. 이 수치는
  RPC 구간과 원본 상태 보간으로 대조한 표본이며 모든 환경의 절대 오차 상한을
  보장하지 않는다. 0.7m 프로필로 좌표·정지·이탈 판단을 함께 재검증한다.
- 전륜 통과 시각의 관측 오차와 차체 정지·이탈 여유는 별도 계약이다. 이 설치본은
  원본 상태의 측정 속도·판단 시각 보정 속도 및 양의 가속도 여유가 **7.0m/s 이하**인
  관측에만 전륜 0.5m를 사용한다. 이는 센서 관측의 실측 범위이며 접근 명령 상한은
  계속 25km/h다. 범위 밖 또는 미검증 계약(`entry_observation_error_m=-1`)은 전체
  차체 오차로 판정한다. 한 번 시작한 통과 불확실성 구간의 오차는 이후 감속으로
  줄이지 않는다. 0.5m를 정지 목표·충돌 영역·차체 이탈 판정에 적용하지 않는다.

## Controller 연결과 운영 차단 조건

기존 Trajectory에는 command ID가 없으므로 독립 수락 피드백·시각 비교만으로
소속을 증명하지 않는다. 추가 원자적 전송과 세대·revision·sequence 검사는
[연결 계약](control-binding-v1.md)대로 구현한다. 기존 토픽 mirror로 이를 우회하지 않는다.
전송의 구체적 수단은 더 이상 미확정 사항이 아니다.

실측·통합·실제 주행 수락은 별도다. 기본 설정을 active로 바꾸지 않으며,
MORAI 시험 실패·미완료 회차를 운영 적용 합격으로 바꾸지 않는다.

## 검증 단계

1. 관측: 운영과 독립된 계산·기록. 제어 연결·실제 발행·이탈 경로 증명을
   관측기가 확보하지 못한 경우 diagnostics에 미평가로 표시한다.
2. 오프라인/통합: 원본 중복·공백·중간 정지 사건, 불확실/초과 분기, 원인별
   유지, 1.155m BRAKING/HOLD 변경, 응답 실패, 첫 callback 제동·조향을 시험한다.
3. 실제 연결: 추가 전송과 기동 제동 인계를 함께 활성화하고, 역순·늦은 이전 결과와
   Controller 해제 회귀를 통과한 빌드를 통제된 시험에 사용한다.
4. 통제된 MORAI: 지연·감속·윤거·위치/추종 오차를 실측하고, 독립적인 실제 신호·
   차량 위치·차체 외곽으로 평가한다. 평가용 실제 신호는 정책 입력으로 쓰지 않는다.

실패 대응 합격은 불가능 조건의 최대제동·위험 대응·초과/불확실 기록 정확성이다.
무위반 주행 합격은 실제 신호 위반·충돌·도로 이탈 없이 정지 또는 정상 이탈을
달성한 경우다. 계획 경로 도로 검사와 실제 차량 도로 이탈 평가는 별도다.
실제 도로 평가는 설치된 지도 번들의 물리 pavement MeshCollider 삼각형으로
만든 독립 표면에서 MORAI의 실제 3차원 차체 투영과 이동 중 sweep을 검사한다.
표면의 구멍을 채우거나 오차 버퍼로 넓히지 않는다. 판제의 curated drivable
polygon을 실제 도로 정답으로 재사용하지 않는다.

실행 가능한 오프라인 시험:

```bash
docker exec asmc-ros-noetic bash -lc '
  source /opt/ros/noetic/setup.bash
  source /root/ws/devel/setup.bash
  cd /root/ws/build
  ctest -R "(signal_policy|command_stop_plan|spatial_stop_speed|braking_steering|rostest.*controller_failsafe_verification)" --output-on-failure
'
```

이 설치본의 통제 실측·회차별 결과는
[구현·검증 기록](../records/planning/2026-10-22-yellow-light-validation.md)과
[C052 초록 진입 계속 검증](../records/planning/2026-10-25-c052-green-cross-continuation.md)에 있다.
불확실·초과·경로 실패 기록과 독립 물리 평가의 무위반 완주를 구분하며,
기본 관측 모드와 상시 운영 전 시계 환경 조건은 유지한다.
