# 고주로 LANE_CHANGE 첫 구현과 오프라인 검증

> 2026-10-26 main 통합: 현재 실행은 [통합 안내](main-integration-20261026.md)를 따른다.
> 아래 날짜별 Main/nested workspace 기록과 구 입력 전환 옵션은 당시 검증 이력이다.
> 현행 입력은 asmc_lidar의 typed observation이며 별도 MORAI 변환기를 시작하지 않는다.


## 동작 범위

기존 Behavior → Frenet → Execution → MPC 경계를 유지한다. 별도 판단/제어 노드나
정상 KEEP 중 상시 차선변경 후보 생성은 추가하지 않는다. `highway_merge:=true`와
`planner.highway_merge.lane_change.enabled: true`에서 고주로의 인접 한 차로만 변경한다.
상한 70 km/h, 기존 예측 정책, 센서/지도 원본, 일반 STOP/AVOID/회전교차로는 유지한다.

Behavior는 현재 차로에서 실제 선행차로 선택된 객체의 속도와 곡률·교통 제약을 적용한
자유 주행 속도를 비교한다. 10 km/h 이상 차이가 1초의 서로 다른 객체 관측에서 유지되고,
목표 차로의 설정 관측 창이 신선하고 가려지지 않았으며, 동일 후속 지점까지 추정 이득이
1초 이상일 때 PREPARE를 요청한다. 주행 중 가속/감속 시간을 포함한 추정이며 변경 중
진행 거리를 다시 시간 손실로 빼지 않는다. 이 이득은 판단용 추정이지 승인 증거가 아니다.

확인은 동일 ID의 안정된 앞차에 한정한다. 새 관측이 아닌 timer 반복으로 확인 시간을
늘리지 않는다. 입력 공백/역행, 앞차 변경, 참조선 변경은 재확인한다. 실제 실행 후에는
8초 cooldown을 둔다. 실행 전 준비 취소에는 재확인을 적용한다.
STOP/AVOID/필수 합류와 중복 요청하지 않는다.

변경 후 원래 차로로 돌아오는 동작은 넣지 않는다. 새 차로에서 KEEP/FOLLOW하고,
남은 변경·안정화·제동 여유가 부족하면 선택적 변경을 시작하지 않는다.

## 공유 실행과 계약

`PlanHighwayMerge`와 새 요청형 `PlanHighwayTransition`은 같은 내부 생성/재시간화/
안전검사/선택 구현을 사용한다. source/target 경로와 마지막 허용 위치만 요청 사실이다.
선택적 PREPARE의 유지 경로는 기존 KEEP/FOLLOW다. 선택 후보 실패만으로 램프의
정지점을 향해 제동하지 않는다. 현재 차로 자체가 위험한 경우에는 기존 제동/실패 정책이다.

목표는 명시된 HD-map 연결 목록으로 준비한다. 임의의 첫 successor를 선택하지 않는다.
첫 버전 경로는 오른쪽 `409→420→408→445→153`, 가운데 `410→430→434→422→153`,
왼쪽 `418→431→435→423→153`이다. 후속 연결이 없는 432는 대상이 아니다.
도색·차체 전체 도로 포함·곡률·횡가속도·jerk 검사를 유지한다.

외부 BehaviorCommand/FrenetFeedback의 타입·필드·MD5는 변경하지 않는다. source/target
link, 방향, target pose, 속도는 요청 기간 고정한다. target pose는 목표 차로의 위치·방향을
검증하는 표식이고, 실제 연결 완료 station은 현재 ego와 남은 합법 구간으로 선택한다.
옛 목표점 때문에 늦어진 변경을 강제로 짧게 만들지 않는다.

READY/EXECUTE 시 최신 입력으로 실제 후보의 진입/완료와 완료 후 2초를 재검사한다.
객체가 새로 나타났거나 관측 창이 가려지면 PREPARE를 취소/대기하고 source 주행을 유지한다.
COMMIT 후에는 공간 연결을 유지하면서 속도를 재계획한다. 진입 판단을 다시 시작하거나
원래 차로의 대기점으로 돌아가지 않는다. 기존 MERGE의 추종 오차 회복·충돌 대안을 공유한다.

차체 포함·횡위치·헤딩·횡속도 안정화, 경로 연속성, 입력 신선도를 확인한 뒤 목표 core,
참조선, ego/객체 투영, 선행차 판단, 다음 궤적과 COMPLETED를 함께 인계한다. Behavior의
이전 참조선 FOLLOW 유예 ID도 epoch 변경 시 제거한다. 주행 station은 새 차로, 미션 진행도는
공식 경로에 유지한다. 새 차로 ID에는 같은 고주로 속도/객체 예측 정책이 적용된다.

마지막 감소 구간에서는 채택한 차로의 source chain과 공통 153의 교통을 검사한다.
이미 가운데/왼쪽 차로를 달리는 차에 445 출발 합류를 다시 실행시키지 않는다.
공통 차로 도달도 같은 인계 인증을 거친다. 공식 경로 복귀는 그 공통 차로에서만 가능하다.

## 관측 범위와 남은 제약

설정 관측 창은 전방 45 m/후방 30 m이며 현재 LiDAR ROI 안으로 제한한다. 모든 분류의
보고된 OBB 점유와 그 OBB가 창을 가리는지 확인한다. ROS 수신만 신선하고 원래 source
stamp가 없거나 오래되면 승인 근거로 사용하지 않는다.

보고된 상자 기반 가림 검사는 인지 재현율, 센서 건강, 미검출 가림을 보증하지 않는다.
관측 밖 후행차에 대해서는 `unseen_speed_mps` 운용 가정과 **실제 선택 후보 완료 시각과
진행 거리**로 접근 가능 거리를 확인한다. 이 조건은 Frenet의 각 진입 후보에 적용해
관측 범위 안에서 실행 가능한 다른 속도 후보도 계속 탐색한다. COMMIT 뒤에는 진입 승인용
관측 범위 조건을 다시 적용해 진행 중인 차량을 정지시키지 않는다. 최초 설정은 70 km/h이며, 주변차의 실제 상한을
검증한 값이라는 주장은 아니다. 더 빠른 미관측 뒤차가 가능한 시나리오는 이 운용 가정을
높여 승인 거절/감속 영향을 확인해야 한다. 상한을 높일 때 ROI만으로 안전하다고 간주하지 않는다.

옆 차로 유지 차량을 침범으로 외삽해 불필요하게 감속하는 기존 예측 과제는 남아 있다.
이번 변경에서 횡속도를 0으로 만들거나 충돌 검사를 끄지 않는다. 빠른 뒤차·실제 끼어들기·
가림·미검출·입력 중단, MPC 실제 추종과 조향 연속성은 MORAI 수락 시험 대상이다.

## 실행과 재현

호스트에서 현재 feature 브랜치를 pull한 뒤 컨테이너 `/root/ws`에서 전체 planner와 어댑터를
함께 다시 빌드한다. C++ core 레이아웃이 바뀌었으므로 일부 실행 파일만 빌드하지 않는다.

```bash
./scripts/build_ws.sh --force-cmake -DCATKIN_WHITELIST_PACKAGES="" -j4 -l4
source devel/setup.bash
python3 tools/planning/check_highway_merge.py --native /root/ws/devel/lib/asmc_planner/highway_merge_preflight
roslaunch asmc_planner autonomy_no_bridges_v2.launch highway_merge:=true
```

브릿지·카메라·asmc_lidar 실행은 현재 main 실행 안내를 따른다. 일반 launch의 highway 기본 false는 유지한다.
별도 LC launch/controller는 없다. 기능을 끄려면 `planner.highway_merge.lane_change.enabled`
파라미터를 false로 바꾸고 planner를 재시작한다.

```bash
./devel/lib/asmc_planner/highway_lane_change_execution_test
./devel/lib/asmc_planner/highway_lane_change_policy_test
```

## 검증 증거와 해석

- 실제 지도에서 세 참조선과 공통 153을 시작 전 준비·검증한다. 잘못된 인접/후속 차로를 거절한다.
- 이상적 궤적 추종으로 기존 진입 MERGE → 오른쪽/가운데/왼쪽 변경 → 변경 후 KEEP → 채택한
  차로의 마지막 필수 합류를 검사한다. 목표 점유 시 source 유지, 옛 READY epoch 거절과 원자적 인계도 확인한다.
- Behavior 시험은 느린 앞차 지속, 중복 관측, 목표 점유·가림·신선도 부족, COMMIT 후 소유권,
  완료 후 새 차로 KEEP, 마지막 필수 합류 우선순위를 확인한다.
- 기존 정상 주행 bag 두 개의 고정 입력 920/977 프레임에서 실패 수는 각각 42/10으로
  변경 전과 같고 새 실패는 없다. 기존 실패를 해결했다고 해석하지 않는다.
- 일반 STOP 14개, 회전교차로 210개, AVOID 168개의 비교 궤적 snapshot이 변경 전과 같다.
- 실제 V2 cycle, 명령 인코더·실행 관리자·입력/출력 변환·참조선 인계 코드를 메모리 메시지와
  주입 시계에 연결한 검사에서 진입 MERGE → LANE_CHANGE → KEEP → 마지막 MERGE가 통과했다.
  최신 목표 점유의 승인 거절과 두 번째 준비 취소 후 현재 참조선 유지도 확인했다.
  이는 ROS 전송·타이머·MPC 시험이 아니다.
- 인계 소유자와 실행 클래스의 AddressSanitizer 계측에서 취소와 COMMIT 후 진행을 포함한 수명 검사를 통과했다.
  메모리 수명 검사에서는 계측 오버헤드를 위해 시험용 계산 제한만 500 ms로 완화했다.
  production의 30 ms는 변경하지 않았다. 환경에서 LeakSanitizer의 proc 접근이 불가능해
  leak 검사는 끄고 address 오류를 검사했다. 성능·누수 전체 검증을 의미하지 않는다.
- 메시지 registry 및 지도 식별자 계약은 유지한다. CI에 새 native 시험을 추가한다.
  Python asset gate 11개 사례에서 누락 차로/잘못된 공통 successor의 사전 거절도 확인한다.

고정 입력 재생은 새 차선변경을 실행한 차량/주변차 반응을 검증하지 않는다. 이상적 추종은
MPC의 한계나 MORAI 물리 충돌을 검증하지 않는다. ROS 전체 빌드/통신과 MORAI 주행은
사용 환경에서 이어서 확인해야 한다. 평가용 개인 포트폴리오 문서는 이 기록에 포함하지 않는다.


## 고주로 간격과 준비 연속성 보완

고주로의 앞차 차체 간 최소 간격은 8 m에서 4 m로 조정한다. 앞 TTC 2초,
뒤 간격 10 m / TTC 3초 / 뒤차 허용 감속 3 m/s²는 유지한다. 자유 속도와 현재
차로 선행차 속도의 차이, 목표 차로 선행차 속도, 시간 이득 및 좌/우 선택 우선순위는
그대로다. 일반 KEEP/FOLLOW, AVOID, STOP, 회전교차로 설정을 변경하지 않는다.

이미 발행 중인 미확정 LANE_CHANGE 준비는 앞차 관측이 잠깐 사라져도 마지막 유효
source 관측부터 최대 `min(0.3, source_max_age_s)`초 유지한다. 새 준비를 만들거나
과거 READY를 보관하는 유예가 아니다. ego/객체 신선도, source/target, 참조선 epoch,
목표 차로 관측, 정적 장애물/보행자/정지 및 필수 합류 우선순위는 계속 확인한다.
새로운 유효 선행차가 속도 이득을 없애거나 유예가 만료되면 준비를 취소한다.
Frenet은 EXECUTE 시점에 최신 입력의 후보를 다시 인증해야 한다.

진입 전 뒤차 허용 감속 검사와 정속 충돌 외삽의 불일치를 후보 내부에서 보완한다.
확인된 동일 방향 목표 차로 모델이 있고 현재 차체 전체가 뒤에 분리되어 있는 객체만
반응 후보가 된다. 실제 후보의 목표 차로 점유 시작 후 **1초까지 기존 속도 불확실성
전체의 정속 예측**을 유지한다. 그 시점의 빠른 속도 끝점과 실제 ego 후보의 남은
후미 진행 속도 하한으로 뒤 간격을 유지하는 최소 필요 감속을 계산한다. 3 m/s²를
넘거나 준비 차로의 미해결 분기/끝을 넘어가면 기존 엄격한 예측으로 돌아간다.

반응 예측은 최소 필요 감속부터 최대 허용 감속까지의 점유 구간을 유지한다. 느린 끝점은
최대 허용 감속으로 정지할 수도 있으며, 빠른 끝점은 ego 속도 하한까지 감속한다.
측정 OBB와 차로 곡선의 중간 knot를 포함하는 공용 점유 sweep을 그대로 사용한다.
충돌 검사와 뒤 간격/TTC는 같은 점유·속도 구간을 소비하며, 이미 반응한 미래 시점마다
1초 반응 지연을 다시 더하지 않는다. 현재 접촉, 반응 전 충돌, 나란히 달리는 차량,
UNKNOWN 운동 상태와 실제 끼어들기를 제외하는 정책은 추가하지 않는다. COMMIT 후 기존의
진행 소유권과 후행 차량 정책은 유지한다.

이는 대회 차량이 반응한다는 **운용 예측 가정**이며 실제 감속을 측정했다는 뜻이 아니다.
고정 bag으로 새 주변차 반응이나 폐루프 충돌 회피를 입증할 수 없다. MORAI에서 좁은
간격, 무반응/늦은 반응 뒤차, 현재 접촉, 차로 변경 취소와 완료 인계를 추가로 확인한다.


이번 보완 검증:

- native 회귀/사전 검사 20개가 통과했다. Behavior 34개 assertion과 현재 충돌/근접 뒤차/
  UNKNOWN 운동 상태/큰 속도 불확실성/분기 끝/반응 전 거절 및 안전한 반응 후보를 포함한다.
  두 공유 라이브러리는 `--no-undefined` 링크와 `ldd -r`을 통과했고,
  roundabout shadow 도구의 동적 로드/usage 반환도 별도로 확인했다. 지도 asset gate 11개가 통과했다.
- `highway_merge_diag(20261023-050536/050728/050910).bag`의 진입 전 485개 고정 입력을
  production core로 재생했다. 050728 기록의 첫 MERGE READY는 약 30.74초였고,
  수정 후 고정 입력에서는 15.55초에 READY가 가능했다. 해당 후보는 앞 차체 간격
  4.24 m, 뒤 간격 13.85 m, 뒤 TTC 8.40초, 필요 뒤 감속 0.62 m/s²였다.
