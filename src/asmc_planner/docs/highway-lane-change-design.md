# 고주로 선택적 차선변경 설계

상태: **고주로 전용 첫 구현 연결, 오프라인 검증 완료 후 MORAI 검증 대상**.
기존 `highway_merge:=true` 실행에서 `planner.highway_merge.lane_change.enabled`가
켜진 경우에만 선택 판단을 활성화한다. 현재 상한 70 km/h는 유지한다.
아래 90–100 km/h는 후속 검증 목표다. 구현 범위와 시험은
[첫 구현 검증 기록](highway-lane-change-stage1.md)을 따른다.

## 목적과 동작

현재 차로의 앞차 때문에 진행이 느리고, 인접 차로에서 안전하게 시간을 줄일 수
있을 때 한 차로만 변경한다. 출발 차로로 돌아가는 추월 동작은 기본으로 넣지 않는다.
변경한 차로에서 KEEP/FOLLOW를 계속하고, 차로 감소에서는 그 활성 차로를 기준으로
필수 합류를 판단한다. 선택적 변경을 거절한 것만으로 제동하거나 정지하지 않는다.

### 판단 시작 조건

- 현재 앞차의 ID/점유와 속도가 신선한 관측에서 안정적이고, 실제 FOLLOW의
  속도를 제한하고 있어야 한다. 단지 먼 곳에 느린 차가 보인다는 이유로 요청하지 않는다.
- `자유 주행 목표속도 - 앞차 속도 >= 10 km/h`를 탐색 시작 조건으로 둔다.
  자유 주행 목표는 설정 상한, 곡률, 미션·교통 제한 중 가장 낮은 값이다.
  예를 들어 곡선에서 50 km/h가 적절한데 앞차도 50이면 상한 100과 비교하지 않는다.
- 일시적인 측정 오차로 요청하지 않도록 서로 다른 관측에서 확인한다.
  첫 구현은 `confirmation_s: 1.0` 동안 새 객체 source stamp에서만 확인한다.
  입력 공백·시각 역행·앞차 또는 참조선 epoch 변경은 누적을 초기화한다.
- 인접한 같은 방향 차로만 검토한다. 도색 횡단 허용, 차체 포함, 후속 연결,
  입력 freshness를 먼저 확인한다. STOP/AVOID/다른 합류·변경 실행 중에는 중복 요청하지 않는다.

목표 차로의 앞 45 m·뒤 30 m는 관측 범위 계약이며 빈 공간 조건이 아니다.
Behavior는 그 범위와 입력 신선도, 목표 차로의 선행차 속도를 확인해 이득 있는 요청을
만든다. 실제 변경 시점의 앞뒤 간격과 모든 측정 OBB의 충돌은 Frenet이 검사한다.
객체가 있다는 이유만으로 요청을 막거나, 합성 시야 광선으로 센서 검출률을 보증하지 않는다.
관측되지 않은 후방 차량의 도달 가능성은 각 후보의 실제 완료 시각·전진 거리로 계속 검사한다.

객체와 차량 상태는 같은 판단 시각에 각각 freshness를 검사한다. 서로 다른 주기로
전달되는 두 source stamp의 대소관계는 신선도 조건이 아니다. 실제 stale/future 입력은
계속 거절한다. 실행되지 않은 PREPARE의 취소는 새 1초 확인을 요구하며, 실행 후 8초
cooldown과 구분한다. 같은 준비된 차로 내 링크 변경은 요청된 참조선 변경이 아니다.

### 최종 실행 조건

10 km/h 차이는 자동 승인 조건이 아니다. Frenet이 만든 실제 후보에 대해 기존
MERGE의 차체 충돌, 도로·도색, 곡률·횡가속도·jerk, 진입/완료 시각 기반 앞뒤 gap,
TTC와 후행 요구 감속도 검사를 재사용한다. 선택적 변경의 성공을 옆차의 양보나
급제동에 의존시키지 않는다. 고정 ±5 m/s 같은 새 오차를 추가하지 않고 기존 관측 이력의
속도 추정·불확실성 정책을 검증해서 공유한다.

안전 후보 사이에서 같은 후속 지점까지의 `예상 소요시간(유지) - 예상 소요시간(변경)`을
비교한다. 실제 가속, 앞차 추종, 변경 후 안정화, 끝 합류의 대기·감속을 포함한다.
양쪽 모두 변경 시간 동안 전진하므로 변경 소요시간 전체를 다시 벌점으로 빼지 않는다.
순 시간 이득과 변경 횟수 비용으로 작은 이득의 왕복 변경을 억제하고, 안전 제약을
시간 비용과 맞바꾸지 않는다.

300 m를 80 대신 90 km/h로 가는 이상적 이득은 약 1.5초, 100이면 약 2.7초다.
짧은 구간의 작은 속도 차이는 합류를 한 번 더 어렵게 만들면서까지 변경할 이유가
약할 수 있다. 이득 임계값과 확인 시간은 기존 bag 판단 재생으로 조정한 뒤 고정한다.

## 구조: 기존 Behavior → Frenet → Execution 유지

| 소유자 | 책임 |
|---|---|
| Behavior | 앞차로 인한 손실, 인접 차로 후보, 후속 합류 경로·남은 거리 판단. 필요할 때만 PREPARE 요청 |
| Frenet | 요청된 차로로 가는 제한된 횡·종 후보 생성, 공통 안전검사와 비용 비교, READY 증거 생성 |
| Execution | 최신 후보 재검사 후 COMMIT, 실행 소유권 유지, 참조선과 다음 KEEP/FOLLOW 경로의 원자적 인계 |

별도 판단 노드나 제어 발행자를 만들지 않는다. 정상 KEEP에서 변경 궤적을 항상 생성하지
않는다. 좌우 검토가 필요해도 준비 단계에서 제한된 후보 수만 평가한다.

요청의 내부 계약은 command/epoch, 기동 이유(선택/필수), source/target lane sequence,
활성 reference epoch, 합법적인 변경 구간, 후속 공통 차로, 입력 관측 시각을 포함한다.
후보의 READY는 같은 요청·참조선·관측에만 유효하다. 단순한 좌우 방향이나 target_d만으로
완료·후속 차로 주행을 표현하지 않는다. 공용 메시지 변경이 필요하면 별도 계약 검증을 한다.

1. PREPARE 동안 원래 차로의 KEEP/FOLLOW가 전진을 담당한다. 변경 후보 실패를
   현재 차로 주행 실패로 취급하지 않는다. 차로 끝에서 필요한 제동은 필수 합류 정책이다.
2. 최신 입력과 실제 도달 시각으로 READY를 확인하고 EXECUTE에서 다시 검사한다.
3. COMMIT한 공간 연결의 목표를 고정한다. 종방향 속도는 최신 상황에 맞춰 갱신한다.
   들어가던 중 뒷차가 가까워졌다고 출발 차로 대기점으로 복귀하거나 무조건 정지하지 않는다.
   실제 충돌 위험이면 안전한 전진·제동 대안을 공통 검사하며 안전을 보장할 수 없으면 실패를 알린다.
4. 차체 포함·횡오차·헤딩·횡속도 안정화와 경로 연속성을 확인한 뒤 새 참조선,
   ego/객체 좌표, 선행차 판단, 다음 주행 경로, COMPLETED를 함께 인계한다.
   미션 진행도는 공식 route_s, 주행 좌표는 채택한 차로의 station을 사용한다.
5. 새 차로에서 KEEP/FOLLOW한다. 모드 변경을 기다리며 기존 참조선으로 되돌아가지 않는다.

### 목표 차로 인계와 중단 복구

목표 차로에 실제 차체가 포함되고 횡오차·헤딩·횡속도가 설정 시간 동안 안정화된
경우, 현재 주기의 변경 경로와 목표 차로 FOLLOW 경로는 미래 속도가 다를 수 있다.
두 경로를 같은 시간 인덱스로만 비교하면 선행차에 맞춰 감속하는 정상 FOLLOW를
거절하고 이전 참조선을 계속 유지하게 된다. 유한한 목표 차로 인계에서는 기존 시간
연속성 검사 외에 **같은 물리적 이동거리에서 위치·헤딩·곡률 연속성**을 검사한다.
시작 속도·가속도 허용차는 그대로 유지한다. 목표 경로는 기존 Plan의 운동학·충돌
검사와 도로·도색 검사를 모두 통과해야 한다. 공식 미션 참조선 복귀는 기존 검사를 유지한다.

긴급정지로 COMMIT된 선택적 변경이 중단되면 Behavior의 동결 요청을 폐기한다.
Execution은 이미 시작한 공간 연결과 출발·목표 차로를 복구 문맥으로 보존한다.
긴급정지 명령이 우선하며, 해제 후에는 최신 관측으로 기존 전진/FOLLOW/복귀 후보를
다시 검사한다. 이 동안 새 선택적 변경은 만들지 않는다. 실제 출발 차로 복귀 또는
목표 차로 안정화와 참조선 인계가 끝나야 복구 소유권을 해제한다. 취소된 명령을
성공으로 바꾸거나 새 명령에 과거 READY를 전달하지 않는다.

출발 차로가 맞지 않아 거절된 새 요청의 대체 KEEP/FOLLOW는 **현재 활성 차로에
실제 차체가 정렬된 경우에만** 발행한다. 이 조건이 없으면 LEFT_CHANGE 표시를
유지하면서 옛 오른쪽 참조선으로 돌아가는 경로가 발행될 수 있다.

### 합류 접근 중 왼쪽 변경

합류 관측이 시작됐다는 이유만으로 모든 선택적 변경을 막지 않는다. HD map에서
왼쪽 인접 관계가 확인되고, 준비된 두 차로가 동일한 공통 후속 차로로 연결되는
왼쪽 변경은 합류 진행으로 인정한다. 기존 앞차 속도 손실·시간 이득·새 관측 확인과
실제 후보의 모든 안전 검사는 유지한다. 변경 완료 지점 뒤에는 기존 안정화 시간과
차체 길이만큼 거리를 남기며, 그 뒤에 다시 완전 정지할 거리까지 중복 확보하지 않는다.
일반 오른쪽 변경은 기존 제동거리 여유를 유지하고 합류 접근 중에는 새로 시작하지 않는다.

준비 중인 필수 MERGE는 위 조건의 왼쪽 요청으로 교체할 수 있지만, 이미 COMMIT된
필수 합류는 계속 소유권을 유지한다. 남은 거리가 변경·안정화에 부족하거나 도색·차체·
관측 범위·충돌 검사를 통과하지 못하면 왼쪽 변경도 거절한다.

## 실제 재사용 범위와 필요한 일반화

- `MakeHighwayTransitionGeometry`, `SampleHighwayTransitionPath`,
  `RetimeCartesianGeometry`와 `EvaluateHighwayMergeCandidate`의 형상·시간화·안전검사를 공유한다.
- `LaneReferenceExecution`의 준비/commit/연속성 검사를 공유한다.
- `HighwayReferenceExecution`은 기존 두 MERGE와 명시된 세 고주로 경로의 core·참조선을
  시작 시 검증·준비한다. 요청 시 현재 source와 준비된 target을 `LaneReferenceExecution`으로
  결속한다. 기존 두 MERGE의 기존 경로는 유지한다.
- 기존 `Maneuver/LaneChange`는 예전 참조선의 target_d를 유지하는
  `HOLD_TARGET_LANE`에서 끝난다. 새 참조선 인계가 없으므로 Behavior 점수만 켜서
  사용하면 안 된다. 새 고주로 LANE_CHANGE는 공유 실행부로 연결하고 동일 기능을 복제하지 않는다.
- 회전교차로와 AVOID는 이 일반화의 첫 적용 대상에서 제외한다.

## 차로 감소와 지도 확인 결과

현재 compact HD map의 link ID 끝자리 기준이다. 차로 번호만으로 후속 경로를 추정하지 않는다.

| 병렬 경로 | 후속 연결 |
|---|---|
| 409 → 420 → 408 → 445 | 153 또는 432 |
| 410 → 430 → 434 → 422 | 153 또는 432 |
| 418 → 431 → 435 → 423 | 153 또는 432 |
| 공통 미션 경로 | 153 → 451 → 446 |

현재 지도에서 432에는 successor가 없다. 각 차로에서 최종 153으로 이어지는
경로를 명시적으로 선택하고 연결부 형상과 합류 교통을 검증해야 한다.
423→153 연결이 있으므로 왼쪽 차로를 무조건 막을 이유도 없지만, 그냥 첫 successor나
평행한 432를 따라가면 된다고 가정할 수도 없다.

이미 목표 차로를 주행하는 차에 기존 445 출발 합류를 다시 실행시키지 않는다.
활성 차로가 후속 공통 영역으로 어떻게 이어지는지에 따라 필수 합류 요청을 정한다.
그래프 연결만으로 주변 차량과의 합류가 승인되는 것은 아니다.

끝에서 멀어지는 선택적 변경은 변경·안정화·필수 합류 및 제동 여유가 남은 합법 구간에
들어갈 때만 허용한다. 고정된 마지막 100 m 대신 실제 후보 속도와 소요시간으로
latest-start를 계산한다. 100 km/h에서 4–5초 변경만 해도 약 111–139 m를 간다.
필수 합류를 준비해야 할 시점에는 선택적 변경을 새로 시작하지 않는다.

## 90–100 km/h와 검증 순서

현재 Main 기본 ROI는 전방 50 m, 후방 30 m다. 100 km/h에서 3 m/s² 정지거리는
반응 지연을 빼도 약 129 m다. ego 80, 뒤차 100 km/h이면 5초 동안 약 28 m를
따라잡는다. 따라서 현재 객체 목록이 비었다는 이유만으로 100 km/h 변경을 승인할 수 없다.
실제 유효 관측거리·가림, 제동, 제어 추종 범위를 확인해야 하며 상한 변경은 별도로 한다.

1. **실행 일반화부터:** 고정 MERGE를 공통 실행부로 옮기고 기존 두 합류의
   안전검사와 참조선 인계 회귀를 유지한다. 선택 정책은 비활성 상태로 차로 409/410/418 각각의 후속 경로,
   432 막다른 연결, 차체·도색·이음부를 오프라인 preflight로 검사한다.
2. **판단 연결:** 느린 앞차의 지속 확인, 인접 차로 관측, 시간 이득, 끝 구간 veto를
   Behavior에 연결한다. 기존 bag으로 요청·거절 이유, 요청 횟수, 변경 금지 구간을 재생한다.
3. **현재 속도로 MORAI:** 빈 차로 변경, 빠른 뒤차, 목표 차로 선행차, 변경 도중 입력
   공백, 끝 합류, 반복 요청, 완료 직후 KEEP/FOLLOW와 차선 유지를 확인한다.
4. **속도 확대:** 같은 수락 기준으로 70→80→90→100 km/h를 단계 검증한다.
   기존 저속 bag은 100 km/h 폐루프 추종이나 새 궤적에서의 주변차 반응을 검증하지 못한다.

진행을 막는 기준은 충돌·차선 이탈·지속 정지·참조선 인계 실패다. 경미한 감속이나
아직 주행을 막지 않는 UNKNOWN 분류 과제는 별도로 남기고 이번 구현 범위를 늘리지 않는다.

## 현재 옆차 예측 과제와 개발 순서 (2026-10-18)

`15:01:45` bag의 56.84–57.98초에는 옆뒤 객체 21273 때문에 KEEP 경로가
24프레임 실패했다. 해당 객체를 제거한 고정 입력 대조에서는 24프레임 모두
경로를 생성했다. 차로 기준 횡속도 약 0.83 m/s를 장기 침범으로 외삽하는 것이
직접 원인이다. 이후 관측에서는 그 차량이 옆 차로를 유지했다.

단순 문턱 상향은 해결 증거가 없다. `provisional_lateral_speed_mps`를
0.25→0.5→0.75→1.0→1.25→1.5→2.0으로 바꾼 같은 시점의 대조에서도
횡이동 예측은 유지됐다. 위치 이력의 횡속도 약 0.99 m/s와 속도 입력이
일치한다고 판단하기 때문이다. 검출 중심과 속도가 같은 관측에서 파생되므로
이는 독립적인 침범 증거가 아닐 수 있다. 기울어진 OBB도 미래 점유에 영향을 준다.
원시 cloud/영상과 물리적 차체 정답 없이 관측 변화의 인지 원인까지 확정하지 않는다.

후속 검증은 자기 차로 유지와 침범 예측을 구분하고, 차로 경계에 대한 점유 변화와
박스 형상 변화를 분리해 평가해야 한다. 현재 OBB 충돌을 무시하거나 옆차의
횡속도를 일괄 0으로 바꾸는 정책은 채택하지 않는다. 후보는 실제로 발행하는
경로와 후속 안전 동작을 같은 기준으로 검사해야 한다.

이 과제 때문에 공통 LANE_CHANGE 실행부의 구조 작업과 오프라인 검증을 미루지
않는다. 기존 MERGE 실행·참조선 인계를 먼저 일반화하고 선택 판단을 연결한다.
새 기능의 주행 수락과 90–100 km/h 상향 전에는 옆차 유지·실제 끼어들기·빠른 뒤차
시나리오에서 감속과 충돌 안전을 함께 검증한다. 현재 속도 상한은 유지한다.


## 고주로 주변 차량의 차로 유지 예측

대회에서 주변 차량이 고주로 차선 변경을 하지 않는다는 운영 조건에 따라
`planner.highway_merge.traffic_lane_keeping: true`를 사용한다. 운영 조건이 달라지면
false로 내려 기존 관측 기반 예측으로 복구한다. HD map과 센서 producer는 변경하지 않는다.

- 준비된 세 차로의 불변 참조선을 공유한다. 후보마다 지도를 생성하거나 새 planner를 만들지 않는다.
- 차량과 이동이 관측으로 지지된 UNKNOWN은 새 관측 3회 이상, 기존 motion-fit 시간 이상,
  최근 위치의 동일 차로 포함과 진행 방향을 확인한다. 모호한 분기·교차 이동은 원래 예측을 유지한다.
- 도로 접선 방향 속도로 전진하고 현재 횡위치를 유지한다. 차로 곡선과 명시된 후속 연결을 따른다.
  현재 중심점은 지도 중심으로 당기지 않으며 측정 OBB corner, 크기, 현재 겹침을 보존한다.
  미래 형상은 지도 진행 방향의 변화만큼 원래 corner를 강체 회전하며 재구성하거나 축소하지 않는다.
- 보행자·정적 객체·정지 판정 객체와 확인 전 새 ID에는 적용하지 않는다. UNKNOWN의 가짜 속도는
  실제 진행 방향 위치 변화가 지지하지 않으면 차로 주행으로 승격하지 않는다.
- KEEP/FOLLOW와 고주로 MERGE/LANE_CHANGE가 같은 예측을 소비한다. STOP/AVOID와 회전교차로의
  기존 경로에서는 활성화하지 않는다.
- 곡선에서 속도 구간의 양 끝 위치만 연결하면 중간 점유를 놓칠 수 있다. 해당 구간의 참조선
  절점을 포함한 swept hull과 횡 offset 보간 오차 상한을 사용한다. 첫 미확정 후속 분기 또는 알려진 참조선 끝 이후에는
  확인된 구간의 끝 접선으로 전진하며 우리 미션의 후속 차로를 NPC 경로로 선택하지 않는다.
  분기 뒤 여러 후속 차로가 현재 관측 위치와 겹치면 차로 유지 모델을 보류한다.

기존 bag의 ego 운동을 고정한 shadow 검증은 PREPARE/READY와 가상 COMMIT 조건까지 평가한다.
그 이후의 실제 변경·추종·인계는 native 실행 시험과 MORAI 주행으로 따로 확인한다.


같은 차로의 뒤 차량은 현재 비충돌·완전 후방 위치·전진 방향을 확인한 다음,
확인된 지도 참조선이 ego 참조선과 일치하는 동안 기존 추종 책임 정책을 사용한다.
부분 OBB가 도색 경계를 걸친다는 이유만으로 다른 차로 차량으로 바꾸지 않는다.
다른 차로 모델, 현재 충돌/마진 침범, ego의 차로 이탈과 변경 진입의 앞뒤 간격은
계속 엄격하게 검사한다. 이 역할 판정은 목표 차로 진입 승인을 대체하지 않는다.

## READY 이후 실행 지연 방지

고주로 MERGE/LANE_CHANGE의 준비 확인과 현재 출발 허가를 구분한다.
기존 FSM의 PREPARE → READY → EXECUTE → COMMITTED 계약은 유지한다.

- 진입 후보를 현재 차로 유지 계획보다 먼저 검사한다. 직전 성공 후보의 **목표 속도만**
  탐색 순서의 첫 항목으로 사용한다. 공간 연결부와 도달 시각은 현재 ego에서 새로 만들며,
  최신 객체의 OBB·앞뒤 간격·TTC·뒤차 요구 감속·관측 범위·운동 한계·도로/도색을 다시 검사한다.
- 계산 시간 초과는 현재 `ready=false`, `candidate_valid=false`다. 이전 후보 토큰도 epoch가
  바뀌어 무효다. 마지막 안전 확인 및 이미 발행한 READY는 최대
  `min(confirmation_gap_s, source_max_age_s)` 동안만 기록으로 남긴다. 시간 초과는 확인 횟수를
  늘리지 않는다. 동일 객체 관측도 중복 확인하지 않는다.
- 실제 안전성 거절로 진행 가능한 후보를 찾지 못한 경우, 오래되거나 역전된 입력,
  관측 공백, 취소/새 명령 바인딩, 참조선 교체는
  준비 확인을 폐기한다. 이후 성공해도 필요한 독립 관측 수를 다시 채운다.
- 같은 명령에 이미 READY를 발행했고 EXECUTE를 받았다면, 새 안전 검사가 완료된 그 주기에
  커밋할 수 있다. 그때만 source 유지 계획을 생략한다. 반환된 `output_requires_commit` 경로는
  변환·최종 입력 신선도·CommandExecutionManager 커밋이 모두 성공해야 발행한다.
  하나라도 실패하면 SAFE_STOP을 발행하며 미커밋 횡이동 경로를 내보내지 않는다.
- 진입 후보 탐색 예산은 기존 30 ms다. 아직 출발할 수 없을 때는 source 유지 계획이 필요하므로
  그 bounded 탐색에 별도의 동일 예산을 준다. 선택적 변경의 source KEEP/FOLLOW는 기존 생성기를
  그대로 사용한다. **30 ms는 전체 callback의 실행 시간 상한이 아니다.** 후보 검사와 source 계획을
  모두 수행하는 준비 주기, 최종 도로 검사 등은 이를 초과할 수 있다. 입력 신선도 검사는 최종
  발행 직전에도 적용한다. 실제 부하에서 주기와 제어 stale 여부를 함께 검증해야 한다.

`highway_readiness_test`는 시간 초과 후 재확인, 실제 새 충돌, 만료·취소·중복 관측,
현재 위치에서의 후보 재생성, 커밋이 필요한 출력 구분을 검사한다.
`highway_lane_change_execution_test`는 양쪽 준비 차로에서 동일 주기 출발과 완료 인계를 검사한다.
STOP/AVOID/회전교차로의 생성·확인 정책, 센서·HD-map producer와 간격/속도 파라미터는 바꾸지 않는다.

## 실행 중 추종과 복귀 — 좌우 공통

선택적 LEFT/RIGHT CHANGE는 같은 `PlanHighwayTransition` 실행부를 사용한다.
이미 승인한 변경은 안전한 진행 후보가 있는 동안 유지한다. 앞차에 접근해 높은
순항속도 후보가 실패해도 변경 실패로 단정하지 않는다. 실제 공간 연결 경로의
호길이에서 기존 `GenerateFollowingCandidates`와 필요한 경우 FOLLOW 복구 생성기를
사용해 추종 속도를 만들고, 해당 속도를 실제 발행할 경로와 함께 다시 검사한다.
단순히 검사에서만 감속을 가정하고 가속 경로를 발행하지 않는다.

선행 객체는 기울어진 ego 축이 아니라 실제 연결 경로와 측정 OBB의 겹침으로
찾는다. 연결 경로에 영향을 주는 앞차 중 기존 간격 피드백상 더 제한적인 차를
선택하며, 최종 충돌 검사는 나머지 객체도 포함한다. VEHICLE과 이동 상태가 있는
UNKNOWN은 속도 계획에 사용할 수 있다. UNKNOWN 정적 객체의 충돌 검사는 유지한다.
이 대상 기준은 목표 참조선으로 인계할 다음 KEEP/FOLLOW에도 적용한다.

진행 후보를 찾지 못했을 때만 원래 차로 복귀 후보를 검사한다. 진입률 50% 같은
새 임계값을 두지 않는다. 현재 위치·헤딩·곡률 경계조건에서 기존 공간 연결 생성기로
원래 차로를 향하는 경로를 만들고, 동일한 속도·운동학·전체 객체·도로·도색 검사와
복귀 완료 후 주행 구간 검사를 통과해야 한다. 차체가 이미 목표 차로에 완전히
들어간 경우에는 일반적인 복귀를 시작하지 않는다. 계산 시간 초과만으로 변경이
위험해졌다고 간주해 복귀하지 않는다. 실제 충돌 거절이 확인된 뒤에는 기존 유지 경로의
제한된 계산 예산을 복귀와 공유해, 전진 탐색의 시간 소진이 복귀까지 막지 않게 한다.

검증된 복귀를 선택한 뒤에는 목표 간격이 잠깐 열렸다는 이유로 다시 횡방향을
뒤집지 않는다. 복귀 경로도 매 주기 새 입력으로 검사하고, 새 위험으로 복귀가
막히면 전진 대안을 다시 검토한다. 복귀 궤적 발행과 실제 복귀 완료는 다르다.
실제 차체가 원래 차로 안에 들어오고 기존 횡오차·헤딩·횡속도 조건과 안정화 시간을
만족할 때까지 LANE_CHANGE 실행 잠금을 유지한다.

안전하게 복귀한 선택적 변경은 FAILED로 종료하며 목표 차로 채택이나 끝 합류 완료로
보고하지 않는다. Behavior가 이 종료를 받아 새 KEEP/FOLLOW 명령을 보내기 전까지도
같은 source 참조선에서 현재 입력으로 새 주행 경로를 생성한다. 이 인계 구간에서
실패 latch 때문에 무조건 1점 STOP을 발행하거나 과거 궤적 시각을 갱신해 재사용하지 않는다.
실제 충돌 또는 stale 입력을 안전하다고 간주하는 예외는 추가하지 않는다.

검증: `highway_lane_change_recovery_test`는 좌우 각각 변경 중 목표 앞차 추종,
원래 차로 복귀, 복귀 유지·실제 정렬 완료, 목표 차로 점유 후 급복귀 방지,
현재 차체 충돌 및 계산 시간 초과를 검사한다. `highway_lane_change_execution_test`는
좌→좌→우→우→좌→좌의 실제 참조선 채택과 후속 필수 합류를 검사한다.

오프라인 검증 범위:

- 지도 native preflight를 포함한 23개 회귀 실행 파일과 지도 자산 Python 검사 11개.
- 좌우 복구 시험 100개 assertion 및 연속된 좌/우 참조선 채택·끝 합류 검사.
- 실제 `HighwayReferencePort`, 입력 변환, 명령 수용 관리자와 피드백 생성 코드를
  사용한 native 인계 검사. ROS의 시계·메시지 필드·발행은 가벼운 대역을 사용하므로
  ROS master/transport 검증으로 간주하지 않는다. FAILED 중에도 신선한 source 경로를
  생성하고 stale 입력에서는 이를 거부하는지 확인한다.
- 실제 `RunV2<PlanningPort>` 인스턴스와 변경된 adapter 파일의 C++ 타입 검사.
  두 core 공유 라이브러리는 `--no-undefined` 링크와 `ldd -r` 검사를 수행한다.
- 기존 3개 bag의 ego/객체 입력을 고정한 재계획 비교. 이 재생은 수정된 경로를 따라
  ego/NPC가 반응하는 폐루프 성공률이나 새 영상 장면의 해결을 보증하지 않는다.

전체 catkin/ROS 실행과 MORAI 폐루프 주행은 적용 환경에서 확인해야 한다.
클래스와 공유 라이브러리 경계도 변경되므로 planner core·adapter·실행 파일을 함께
재빌드하고, 좌우 변경의 추종·복귀·복귀 후 KEEP/FOLLOW 인계를 확인한다.


### 검증된 고주로 동작 복구와 계산 재사용

후보 생성·비용·진입 승인 정책은 주행 기준 `b6c62fd`와 동일하게 유지한다.
이후 추가됐던 두 초기 연결 길이, 1·2초 준비 후보, 탐색 순서 회전,
관측 범위 밖 뒤차에 대한 전체 발행 구간 TTC·요구 감속도 검사는 적용하지 않는다.
원래 존재하던 완료 시점의 후방 관측 거리 검사는 기준 동작 그대로 남는다.
이는 관측되지 않은 뒤차를 실제 검출 객체로 만들거나 센서 신뢰도를 보증하는 정책이 아니다.

고주로 KEEP/FOLLOW의 충돌 필터는 한 번의 후보 묶음 안에서만 객체 예측 형상을
재사용한다. 키는 추적 ID가 아닌 불변 객체 배열의 위치와 정확한 예측 시각 비트다.
차체 형상·객체 형상·속도 구간·시간 표본·여유 거리·후행차 책임·제동 증명은
기존 검사를 그대로 사용한다. 새 관측이나 다음 계획 주기로 결과를 넘기지 않는다.
캐시 한도에 도달하면 원래 예측 함수를 호출하며 객체나 표본을 생략하지 않는다.
일반 STOP/AVOID/회전교차로는 이 재사용 옵션을 활성화하지 않는다.


열린 참조선의 힌트 기반 투영은 기존 거리 조건을 만족하는 station 구간만 이분 탐색한다.
기존 점 순서, 동률 처리, Newton 보정, 비정상 힌트의 전체 탐색 대체 동작은 유지한다.
폐루프 참조선은 원래 순회 구현을 유지한다.

`highway_prediction_reuse_test`는 직선·곡선, 속도 불확실성, 같은 ID의 서로 다른
객체, 정적·동적·회전 객체, 후행차 책임, 제동 대안, 캐시 한도 소진을 포함해
재사용 전후 후보의 충돌 판정과 차단 객체·표본이 동일한지 비교한다.
`reference_projection_window_test`는 원래 전체 순회를 기준으로 경계값·동률·비정상
힌트와 폐루프 투영 결과가 동일한지 검사한다.

고정 입력 bag 비교는 궤적을 바꾼 뒤의 NPC 반응이나 실제 제어 추종을 재현하지 않는다.
오프라인 결과와 MORAI 폐루프 완주 검증을 구분한다.

검증 기록: 기존 정상 주행 4개와 최근 주행 3개 bag의 피드백 시각에 맞춘
7,374개 입력에서 `b6c62fd`와 선택 궤적의 모든 Cartesian 표본, 후보·차단 객체·
승인 결과가 일치했다. 계산 시간만 제외하고 비교했으며, 시간 초과가 결과 비교를
가리지 않도록 이 동일성 검사에서만 메모리상의 탐색 제한을 1,000ms로 두었다.
실제 설정의 30ms 제한은 변경하지 않았다. 같은 로컬 환경에서 전체 평균 CPU 시간은
28.77→25.41ms로 약 11.7% 감소했다. 일부 bag의 상위 지연은 개선되지 않았으므로
모든 계획 주기의 시간 제한 충족이나 불필요한 감속의 전면 해결을 의미하지 않는다.

기존 첫 bag 약 15~17초에는 `planning_time_budget`와
`no_safe_corridor_maintenance`가 함께 나타나 정지 궤적으로 대체된 구간이 있었다.
반면 다른 감속에는 선택 경로의 곡률에 따른 횡가속도 제한이나 실제 후보 충돌
판정도 포함된다. 이 수정은 후보·비용·안전 정책을 바꾸어 이들을 모두 제거하지 않는다.
전체 ROS/catkin 빌드와 MORAI의 좌우 변경·완료 후 KEEP/FOLLOW 인계는 적용 환경에서
별도로 확인한다.
