# 고주로 진입 1차 구현: 일반 주행 연결

> 2026-10-26 main 통합: 현재 실행은 [통합 안내](main-integration-20261026.md)를 따른다.
> 아래 날짜별 Main/nested workspace 기록과 구 입력 전환 옵션은 당시 검증 이력이다.
> 현행 입력은 asmc_lidar의 typed observation이며 별도 MORAI 변환기를 시작하지 않는다.


## 범위와 소유권

`feature/highway-transition-contract`의 일반 `ProductionRuntime`에 고주로 진입을
연결한다. Behavior가 구간과 기동을 선택하고, Frenet은 요청받은 실제 후보를
검사하며, 기존 Execution이 READY/EXECUTE/COMMITTED/COMPLETED를 관리한다.
새 판단 노드나 별도 명령 발행자는 없다. KEEP 때 합류 후보를 상시 생성하지 않는다.

기존 `FindHighwayMergeGap`의 별도 ego 도착 가정은 제거하고 실제 Cartesian 후보를
받는 `EvaluateHighwayMergeCandidate`로 교체했다. 회전교차로 실행기는 유지한다.

| 항목 | 이번 구현 |
|---|---|
| 첫 진입 | `highway_merge_1`, 공식 route_s 1113.35–1274.73 m |
| 후속 두 합류 | `highway_merge_2_3`, 1424.45–1583.76 m, 두 checkpoint |
| 횡경로 | 요청된 HD-map 목표 차로까지 연결한 실제 경로를 검사 |
| 참조선 | 미션 route_s 유지, 목표 차로 안정화 후 주행 참조선 원자적 인계 |
| 다른 차로에서 계속 주행 | 인계 후 일반 KEEP/FOLLOW가 새 참조선을 사용 |
| 필수 차선변경·선택적 추월·자동 차로 sequence 선택 | 후속 구현 |

## 준비·승인·실행

1. 초기화 때 기존 Frenet의 `drivable.json`, 도색선, raster와 공식 경로를 읽는다.
   목표 lane sequence의 존재·연결·방향, 완료점의 전체 차체 포함을 검사한다.
   Behavior의 지도·route·v2 인터페이스 및 source/target link 존재도 확인한다.
   오류면 고주로 실행을 시작하지 않는다. 지도 생성·수정은 하지 않는다.
2. 속도 기반 제동거리와 관찰거리를 고려해 Behavior가 MERGE_HIGHWAY/PREPARE를
   요청한다. 접근 구간은 감속 중 활성화 경계가 움직여도 유지한다.
3. PREPARE는 HD-map의 원래 차로와 접근 predecessor를 따라 전진한다.
   원래 global path가 목표 차로에 닿는 좌표를 중간 대기점으로 쓰지 않는다.
   원래 차로의 마지막 전체 차체 포함·도로·도색 경계에서 stop_buffer만큼
   앞을 최후 정지 한계로 계산한다. 공유 successor는 원래 차로에 포함하지 않는다.
   기존 KEEP 속도 envelope와 STOP의 거리 기반 종방향 생성기로 가속·유지·감속
   후보를 함께 만든다. 도로/교통 속도 상한까지의 진척을 비용으로 비교하며
   고정된 30 km/h 접근 선호나 현재 속도 이하의 상한을 두지 않는다. 모든 후보는
   마지막 원래 차로 경계 앞에서 실제 제동할 수 있는 후속 경로까지 검사한다.
   차로 중앙 정렬이 막히면 현재 차로 내 횡오차를 유지하는 대안도 검사한다.
   원래 차로와 목표 차로 폴리곤이 taper에서 겹치는 것만으로 원래 차로 접근을
   금지하지 않는다. 원래 차로 중심선 identity와 최후 정지 한계, 기존 runtime
   전체 차체 도로 검사, 모든 객체 충돌 검사를 유지한다. 차로 변경의 승인과
   COMMIT/인계 조건은 별도이며 접근 경로가 스스로 승인하지 않는다.
   일반 STOP의 실행·파라미터·생성 기본 동작은 유지한다.
4. 진입 후보는 최대 다섯 속도 schedule을 사용한다. 실제 측정 상태에서 생성한
   경로 전체의 운동학·도로·객체 충돌 및 본선 앞/뒤 bumper gap·TTC·후행 요구
   감속도를 검사한다. 완료 후 2초 진행까지 포함하지 못하면 승인하지 않는다.
5. 서로 다른 신선한 객체 관측 세 번을 요구한다. 같은 관측을 반복 계획한 횟수는
   확인 횟수를 늘리지 않는다. READY 후 EXECUTE가 와도 최신 입력으로 재검사한다.
   이전 후보 epoch나 stale/future/reversed stamp로는 COMMIT할 수 없다.
6. 진입 후에는 현재 기동의 소유권을 유지하고 충돌 검사를 계속한다. 후방 gap을
   새로 승인받기 위해 진입 전 대기점으로 되돌아가지 않는다. 막히면 가능한
   조향 포함 제동을 검사한다. 안전한 제동 후보도 없으면 기존 SAFE_STOP 경로로
   실패를 알린다. 어떤 상황에서도 충돌 회피가 가능하다는 보장은 아니다.
7. 실제 전체 차체가 목표 차로 안에 들어가고 위치·heading·횡속도 조건을
   0.5초 유지하면 새 참조선에서 이후 주행 경로를 만든다. 실행 중 경로와
   1초 구간의 위치·heading·곡률·속도·가속도 연결, 입력 freshness, 메시지
   변환을 모두 확인한 뒤 참조선·ego/object 좌표·선행차·다음 궤적과 COMPLETED를
   함께 인계한다. 이후 일반 KEEP/FOLLOW는 새 차로를 사용한다.

## 초기 정책과 한계

### 고주로 차로 참조선의 입력 점 간격 정규화 (2026-10-18)

고주로 `HighwayReferenceExecution`이 준비하는 목표 차로와 공통 차로 참조선은
연결된 전체 중심선을 먼저 균일한 호길이 격자로 재표본화한다. 기존
`reference.resample_ds`를 최대 간격으로 사용하며 두 물리적 끝점을 보존한다.
링크별로 격자를 다시 시작하지 않는다. 이후 기존 10 m 평활화·최종 재표본화·
곡률 계산과 전체 차체 도로 포함·도색 검사는 그대로 적용한다.

원본은 대부분 1 m 간격이지만 422 끝에는 약 0.098 m의 짧은 구간이 있었다.
입력 점들을 먼저 같은 비중으로 이동평균하면 점 밀도 변화가 작은 위치·헤딩
울렁임을 남겨 곡률 피크로 증폭됐다. 고주로 목표 경로의 마지막 연결부 피크는
첫 구간 0.04268→0.01933/m, 두 번째 구간 0.05365→0.01691/m로 줄었다.
제한값을 올리거나 곡률값을 잘라낸 결과가 아니라 생성된 참조선의 변화다.

새 입력 계약은 `LaneReferenceSampling::UNIFORM_ARC_LENGTH`를 명시한 호출에만
적용한다. 기존 4인자 호출은 이전 결과를 유지한다. 지도 패키지·데이터·메시지,
공식 글로벌 참조선, 공통 `BuildRefLine`, 일반 STOP·AVOID·회전교차로 실행 및
속도 상한 70 km/h는 변경하지 않는다. 작업은 초기화/준비 때 수행하며 20 Hz
계획 루프에 재표본화 작업을 추가하지 않는다. 표본 수는 기존 예산으로 제한한다.

`highway_reference_sampling_test`는 동일 선형에 공선 점만 추가했을 때 위치와
곡률이 유지되는지, 기존 호출의 결과가 같은지, 실제 지도 준비와 차체·도색·
연결 관계 검사가 유지되는지 검사한다. 새로운 폐루프 추종은 MORAI에서 확인한다.
native 회귀 11개와 지도·런치 preflight를 통과했다. 기준 `6e4039c` 대비
기존 두 bag의 KEEP/FOLLOW 고정 입력 920/977프레임에서 추가 실패는 없었고,
일반 STOP·회전교차로·AVOID 기준 출력은 각각 14/210/168샘플 해시가 같았다.
ROS 전체 빌드·transport와 수정 후 MORAI 폐루프 주행은 이 검증에 포함되지 않는다.

### 고주로 초기 상태의 조향 포함 제동 복구 (2026-10-17)

KEEP→MERGE 전환 첫 기록은 50.47 km/h, 측정 횡가속도 약 2.86 m/s²로
일반 계획 한계 2.6 m/s²를 이미 넘었다. 이후 fail-safe 제동이 측정 가속도
−4~−5 m/s²로 남으면서 일반 fallback의 시작 가속도 한계 3 m/s²도 넘었다.
객체 없이 같은 ego 상태만 재생해도 접근 경로가 탈락하므로 별도의 초기 상태 문제다.

- 정상 후보와 기존 제동 fallback이 실패했을 때만 고주로 접근 및 고주로
  KEEP/FOLLOW에서 같은 명시적 복구 제동을 검사한다. 정상 후보가 있으면 사용하지 않는다.
- 측정 속도·가속도·곡률을 0이나 정상 한계로 바꾸지 않는다. 이미 강한 제동 중이면
  jerk 한계로 일반 제동 수준까지 풀고 제동을 이어간다. 역주행을 요구하는 저속
  경계나 과도한 양의 가속도는 복구하지 않는다.
- 현재 차로의 횡위치와 초기 곡률을 연결한 완전 정지 경로를 생성한다. 이미 초과한
  횡가속도는 이 전용 제동 경로에서만 일시 허용하고, 경로 전체 최대 곡률에 맞는
  속도로 감속한 뒤에는 다시 초과하지 않는지 확인한다. 초기 초과량이 잠시 더 커질
  수 있으며, 이를 일반 후보의 한계 상향이나 고속 주행 허용으로 쓰지 않는다.
- 최대 곡률, 전체 차체 도로 포함, 객체 충돌과 정지 후 점유 검사를 유지한다.
  이 경로는 합류 후보·READY·COMMIT 증거가 아니다. COMMITTED 합류, 일반 STOP,
  AVOID, 회전교차로에는 이 opt-in 정책을 적용하지 않는다.

기준 `758841e` 대비 같은 입력의 오프라인 결과:

| 검사 | 이전 → 수정 후 |
|---|---|
| 첫 MERGE 접근 28프레임, 객체 제거 대조 | 경로 실패 11 → 0 |
| 같은 28프레임, 기록된 객체 포함 | 경로 실패 23 → 20, 충돌 검사 유지 |
| 최신 bag 고주로 KEEP/FOLLOW 977프레임 | 실패 20 → 10, 추가 실패 없음 |
| 직전 bag 고주로 KEEP/FOLLOW 792프레임 | 실패 21 → 21, 추가 실패 없음 |
| 원래 유효했던 KEEP/FOLLOW 프레임 | 두 bag 모두 속도 결과 동일 |
| 일반 STOP / 회전교차로 / AVOID 기준 출력 | 각각 14 / 210 / 168 샘플 해시 동일 |

객체를 포함한 첫 실패도 모두 사라졌다는 뜻은 아니다. 제동 경로와 교통의 충돌
예측은 계속 거절하며, 실제 앞·옆 차량 때문에 감속한 두 번째 합류 직후의 판단도
유지한다. 기록된 ego를 고정한 재생이므로 새 제동을 실제로 추종한 결과는 아니다.
`initial_state_recovery_test`와 합류·인계·FOLLOW·STOP·AVOID·회전교차로의 native
회귀 10개를 통과했다. ROS 전체 빌드/transport와 MORAI 폐루프 수락은 별도다.

UNKNOWN의 속도/정지 판정은 이번 변경에서 보류한다. 다음 선택적 차선변경은
[설계와 구현 순서](highway-lane-change-design.md)를 따른다.

### 참조선과 독립적인 고주로 속도 및 FOLLOW 간격 회복 (2026-10-17)

- 고주로 source/target lane graph에 포함되는 현재 `source_link_id`와 유효한
  지도, KEEP/FOLLOW 요청으로 고주로 순항 정책을 선택한다. 글로벌 참조선으로
  인계해도 동일 도로에서는 고주로 상한을 유지한다. 미등록 차로/지도 미준비,
  일반도로, STOP/AVOID/EMERGENCY에는 이 승격을 적용하지 않는다.
- 초기 목표속도 계산과 후보의 속도 envelope/곡률 검사에 같은 정책을 전달한다.
  기존 고주로 횡가속도 여유·감속 계수와 실현 가능한 양의 가속도 1.5 m/s²를
  사용한다. 상위의 더 낮은 요청·속도 상한과 물리·충돌 검사는 유지한다.
  dormant core의 인계 준비에도 선택된 지도 차로의 실제 link ID를 전달한다.
- FOLLOW의 정확한 종료 간격 후보가 정상적이면 기존 후보를 그대로 사용한다.
  모든 종방향 후보가 운동학에서 탈락하고, 현재 간격이 목표 간격보다 짧아
  감속이 필요한 경우에만 기존 jerk-limited 속도 적분기를 추가로 사용한다.
  목표 간격 `min_gap + time_gap * leader_speed`를 한 horizon 안에 강제로
  완성하지 않고 현재 상태에서 점진적으로 회복한다. 종료 간격·속도 오차는
  기존 종방향 비용으로 평가한다. 모든 후보는 동일한 곡률·충돌 검사를 받는다.
- `13:18:39` bag의 첫 실패 입력은 간격 약 12.1 m, 목표 약 27.4 m였다.
  기존 56개 후보가 모두 가속도·jerk 한계를 넘었다. 이 입력과 정상/위험 입력을
  native 회귀로 보존하며 bag 원본·재생 결과는 커밋하지 않는다. 오프라인 재생은
  기록된 ego/객체 입력에 대한 계획 검증이며 새 폐루프 주행을 대신하지 않는다.

후속 LANE_CHANGE는 출발 차로로 되돌아오는 추월 규칙을 기본으로 두지 않는다.
변경 차로를 유지할 수 있으며, 차로 감소 전 마지막 공통 차로로 연결될 수 있는지와
그 방향에서 멀어지는 변경을 금지할 남은 거리를 별도로 판단한다. 현재 문서의
mission reference return은 같은 공통 차로에서 참조선 소유권을 인계하는 뜻이다.

### 관측 ID 연속성과 고주로 일반 주행 예측 (2026-10-17)

- Main의 연관 비용 전에 이전 속도·객체 크기·센서 간격으로 도달 가능한
  위치인지 검사한다. 초기 3회 연관은 기존 속도 초기화를 허용한다.
  다른 검출로 넘어간 ID가 Kalman·카메라 분류를 그대로 계승하는 것을 줄인다.
- Main MotionClassifier는 관측 위치와 이전 속도가 일치하지 않거나 관측
  시각/age가 역행하면 동적 판정·속도·재획득 이력을 새로 시작한다.
  중복 source stamp는 확인 횟수를 늘리지 않는다. 원본 속도·현재 OBB는 보존한다.
- Frenet의 관측 이력과 회전교차로 차체/회전 신뢰도에도 위치 연속성을 검사한다.
  ID가 같다는 이유로 과거 차체·출발 승인을 새 점유에 넘기지 않는다.
  정상 가시성 변화는 차체 크기와 기존 0.35 m edge 허용량 안에서 허용한다.
- 명시적으로 준비된 고주로 차로의 KEEP/FOLLOW는 MERGE와 같은 관측 기반
  종속도·작은 횡속도 보정을 사용한다. 각 객체가 포함된 HD-map 차로 방향을
  사용하며 ego의 목표 차로 방향으로 주변 차량을 강제로 정렬하지 않는다.
  위치 변화로 지지되는 느린 끼어들기와 큰 횡속도는 계속 예측한다.
- 일반 주행에 합류 승인용 속도 오차 hull을 추가하지 않는다. 현재 OBB,
  충돌 여유, 다른 모드의 생성기·비용 및 회전교차로 승인 조건은 유지한다.
  이후 절의 "다른 maneuver 예측 유지"는 위 고주로 KEEP/FOLLOW 보완을 제외한다.

오프라인 검증: Main 동정적 판정 로직 21개(native 경계 대체), 관측/회전
예측·합류·참조선 인계 회귀, 지도/런치 preflight를 확인했다. 기존 회전교차로
842프레임과 AVOID/STOP 기준 출력은 유지됐다. 신규 bag의 FOLLOW 두 실패
시점에서 전진 후보를 회복했다. Main의 raw clustering/Kalman 전체 재실행과
ROS transport 및 MORAI 폐루프 수락을 대신하는 결과는 아니다.

실행 인자는 그대로다. 이번 수정은 실제 입력 생산자인 nested Main도 포함하므로
[공통 실행 문서](../../../docs/operations/commands.md)의 두 workspace를 모두
다시 빌드하고 관련 노드를 재시작한다. 플래너만 빌드하면 Main 보완은 적용되지 않는다.
차로 축소부의 필수 합류 순서와 불완전 차체 관측에 따른 회전교차로 출발 지연은
별도 수락 과제로 남아 있다.

### 참조선 인계 연결

`HighwayReferenceExecution`은 기존 PlanningPort 안에서 미리 초기화한 core와
참조선을 보관한다. 별도 Behavior나 제어 발행자가 아니다. 정상 KEEP 중에는
합류 후보를 만들지 않으며 기존 `highway_merge:=true`로만 이 경로를 연다.

- MERGE 후보는 HD-map 목표 참조선까지의 공간 다항식 연결과 그 차로의 후속
  구간으로 구성한다. 같은 후보의 실제 차체가 목표 영역에 진입하고 정렬되는
  시각을 공통 gap 검사기에 전달한다. COMMIT 때 선택한 연결 종점을 유지해
  재계획할 때마다 완료점을 앞으로 미루지 않는다.
- 목표 차로 정렬 후 새 core의 KEEP/FOLLOW 경로를 사전 생성한다. 이전 실행
  경로의 종단 속도 의도를 준비 중 core에 전달하되 새 곡률·선행차 제한은
  계속 적용한다. 준비용 core에 뒤처진 속도 프로파일이 누적되어 인계를
  방해하지 않도록 한다. 일반 주행 core의 속도 프로파일은 초기화하지 않는다.
- 인계 시 Behavior에 immutable lane/reference epoch와 완료 zone을 같은
  in-process snapshot으로 전달한다. 신호·미션 거리는 원래 route_s, ego와
  주행 객체/선행차/AVOID는 활성 차로 좌표를 사용한다. 같은 zone의 MERGE를
  다시 요청하지 않으며 이후 차로 전환도 최신 활성 차로에서 이어간다.
- 각 zone에 명시된 마지막 공통 차로에서 정렬·freshness·후속 경로·연속성을
  다시 검사한 뒤 원래 mission core로 복귀한다. 조건을 만족하지 못하면
  유한 참조선의 끝을 외삽하지 않고 기존 공간 STOP으로 감속한다. 일반적인
  차로 감소 정책이나 선택적 추월의 자동 목표 선택은 다음 단계다.
- 생산용 참조선의 도로 포함 검사는 기존 Frenet과 동일한 pinned 0.2m 래스터의
  전체 차체 검사다. 첫 합류의 409→420 이음부에는 벡터 폴리곤 사이 수 μm
  크기 틈이 있어 엄밀한 벡터 union과 판정이 달랐다. 지도·래스터를 수정하거나
  gap을 면적 tolerance로 지우지 않는다. 벡터 지도용 독립 API/시험은 원래의
  엄밀한 포함 검사를 유지한다. 실선 접촉 검사도 별도로 유지한다.

조정값은 `planner.highway_merge.reference_handover`에 모았다. 기본 연속성
한계는 1초 비교 구간의 위치 0.35m, heading 0.05rad, 곡률 0.03/m, 속도
0.5m/s, 가속도 1m/s²다. 실제 차량 추종 오차·조향·gap 확보는 MORAI에서
추가 수락해야 하며 오프라인 이상 추종 결과를 실주행 성공률로 해석하지 않는다.

출발 전 검사는 기존 명령 그대로 새 참조선/core의 준비까지 검사한다.

```bash
python3 tools/planning/check_highway_merge.py
roslaunch asmc_planner autonomy_no_bridges_v2.launch highway_merge:=true
```

작은 진단 bag을 추출한 후 새 후보 형상만 재평가하려면 다음 옵션을 쓴다.
기록된 ego는 고정되어 있어 새로운 차선변경의 실제 추종을 재현하지 않는다.

```bash
rosrun asmc_planner highway_merge_shadow /tmp/highway_frames.json \
  src/asmc_planner/config/frenet/params.yaml --reference-handover
```

회귀 대상은 `highway_reference_execution_test`(두 차로 인계, 변경 입력 거절,
완료 전이 거절, KEEP 유지, 공통 차로 mission 복귀, 유한 끝 제동),
`highway_reference_feature_test`(새 차로 선행차/좌표와 완료 zone 억제),
`merge_gap_test`(실제 진입 시각, 완료 후 2초, 앞/뒤 gap와 실행 중 물리 충돌),
기존 참조선·STOP·FOLLOW·AVOID·회전교차로 테스트다.

`config/frenet/params.yaml`의 `planner/highway_merge`에 정책을 모았다.
고주로 MERGE의 설정 상한은 **70 km/h**(`planner.highway_merge.speed_cap_mps` =
19.4444 m/s)다. 공통 `planner.curve_speed.target_vel`은 main의 **58 km/h**를
유지하며, 명시적으로 활성화한 HIGHWAY MERGE와 그 동작으로 채택한 고주로
참조선에만 자체 상한을 사용한다.
고주로의 곡률 속도 여유·프로파일 감속 계수는 `curve_lateral_accel_safety_factor: 0.8`,
`curve_comfortable_decel_factor: 0.5`로 리베이스 전 값을 유지한다. main의 일반 주행
계수0.95·0.65를 합류 후보에 그대로 적용하면 두 번째 구간의 정지 출발 시험에서
진행이 지나치게 느려지는 것을 확인했기 때문이다. 외부 속도·물리 한계·충돌 검사는 유지한다. 고주로 접근 중에는
설정한 고주로 정책이 진입로 지도의 명목 속도를 대신하고, 교차로 감속·STOP 및
곡률/횡가속도 제한은 계속 적용한다. 일반 도로의 Behavior 지도 속도는 유지한다.
앞/뒤 최소 gap은 8/10 m, TTC는 2/3초, 후행 요구 감속도는 3 m/s²다.
거리·TTC·실제 궤적 충돌을 모두 검사하므로 간격 숫자 하나만으로 승인하지 않는다.
후행 요구 감속도에는 1초 반응 지연을 포함한다.

`speed_error_mps: 1.0`은 새 객체에 쓰는 초기 예측 가정이며, 검증된 센서
최대 오차가 아니다. 같은 방향 차량은 고주로 MERGE에서만 최대 12개/0.8초의 source-time 이력에서
속도 관측의 중앙값·MAD와 위치의 Theil–Sen 초기값/이상치 제외 회귀를 사용한다.
중심점 한 번의 점프 때문에 추정 전체를 폐기하고 큰 오차로 되돌아가지 않는다.
관측 산포·위치 회귀 잔차·두 속도 추정의 차이에서 객체별 오차를 계산한다.
`speed_error_floor_mps: 0.25`는 모델의 잔여 오차 가정이고,
객체별 오차는 현재 검사하는 전체 경로에서 거리 오차로 계속 누적한다.
미래 시간이 지났다는 이유만으로 추정 오차를 줄이지 않는다.
`speed_error_correlation_s: 0.3`은 미확정 횡속도 가설의 관측 창에 사용한다.
초기 가정 이상으로 관측이 흔들리면 관측 오차를 유지하며 강제로 축소하지 않는다.

객체 중심이 속한 주행 가능 HD-map 차로의 방향으로 종·횡속도를 분해한다.
우리 목표 차로의 접선을 옆 차로 객체에 강제로 적용하지 않는다. 속도와 반대
방향이거나 포함 차로가 없는 관측에는 기존 raw 예측과 초기 오차 가정을 유지한다.
차로 방향의 종속도만 보정한다. 작은 횡속도(0.25 m/s와 기존 motion tracking의 방향 분해능 0.05 rad를
속도로 환산한 값 중 큰 값 이하)가
연속 위치 변화와 모순되면 0.3초 동안 그 관측을 유지한 뒤 차로 방향으로
이어지는 가설을 사용한다. 큰 횡속도 또는 잡음 산포보다 큰 위치 변화가 뒷받침하는 작은 횡이동은
계속 예측한다. 두 단계 모두 종속도 불확실성을 포함한다. OBB corner는 수정하지
않으며 실제 차체/즉시 접촉·측면 침범·역주행 검사를 유지한다.

진입 전 뒤차 gap/TTC/요구 감속 조건은 유지한다. COMMIT 후 실제 차체가 목표
차로에 자리 잡으면 같은 차로의 평행 뒤차에 일반 차로 주행과 같은 후방 추종
책임을 적용한다. 아직 횡이동 중이면 뒤차가 1초 반응 뒤 기존 3 m/s² 이내로
대응 가능한 경우에만 이 연속 주행 정책을 허용하고, 그 경우도 자차가 목표
차로에 완전히 들어간 이후의 단순 추돌 외삽에만 적용한다. 현재 접촉·진입 중
실제 경로 교차·끼어들기·정적/역주행 객체·다시 차로를 벗어나는 후보는 제외한다.

고주로 양의 가속 계획은 `forward_accel_mps2: 1.5`를 사용한다. 기록된 MORAI
주행의 가속 응답 약 1.5 m/s²와 제어기 상한 2.0 m/s²를 고려한 설정이며 제동
한계는 바꾸지 않는다. 이미 그보다 큰 측정 가속도에서 시작하면 기존 jerk 한계로
풀어준다. 이 값이 모든 속도/조건의 가속 능력을 보증하는 것은 아니다.
인계 뒤 활성 고주로 차로의 KEEP/FOLLOW도 고주로 70 km/h 상한을 받는다.
일반도로의 58 km/h cruise 설정은 활성 고주로 차로를 덮어쓰지 않으며,
미션 참조선으로 복귀하면 일반도로 정책을 사용한다. 신호·선행차·곡률 제한은 유지한다.

접근 속도 후보는 현재 허용 상한·그 절반·그 1/4·최소 서행 속도로 제한한다.
공통 비용은 상한까지의 속도 오차와 진행량을 평가하므로 낮은 속도가 기본
선호값이 아니다. 각 후보는 충돌/차체/제동 가능성 검사를 통과한 뒤 속도·진행·
가속도·jerk 비용으로 비교한다. 낮은 후보를 없애 가속만 강제하지 않는다.

예측은 최대 15초, 후보는 최대 다섯 속도 schedule, 충돌 샘플은 최대 12,000개다.
상대 이동량 0.25 m 또는 0.1초 중 더 촘촘한 간격으로 충돌을 검사하고 샘플 사이
이동 여유를 적용한다. 후보 탐색은 30 ms 예산을 사용하며 미완료 검사는 승인하지
않는다. 이 값은 hard real-time WCET 보장이 아니다. 먼저 접근/제동 궤적을 만들어
두므로 진입 탐색 실패가 전체 STOP 후보 재탐색을 촉발하지 않는다.

현재 객체 배열에는 가림/미관측 영역의 명시적 free-space 정보가 없다.
신선한 빈 배열도 센서 가시범위를 증명하지 않는다. 처음 MORAI 검증은 감지 범위가
확인된 통제 조건에서 수행해야 하며, 가림·후방 탐지 실패·높은 속도 오차는 별도
수락 과제다. 이번 단계는 고속 주행 안전 검증 완료를 의미하지 않는다.

호스트:

```bash
git fetch origin

```

ROS 컨테이너:

```bash
cd /root/ws
source /opt/ros/noetic/setup.bash
catkin_make -DCATKIN_ENABLE_TESTING=ON
source devel/setup.bash
python3 tools/planning/check_highway_merge.py

```

`check_highway_merge.py`는 파일 존재뿐 아니라 Behavior route/link ID·중심선 일치, launch 인수
전달, 실제 native map/reference 초기화를 검사한다. 실패하면 주행을 시작하기 전에
해당 경로·설정을 복구한다. metadata hash만 바꿔 통과시키지 않는다.

이번 일반 주행 연결에는 별도의 HD-map publisher나 `/data`의 공식 경로 원본
생성이 필요 없다. 앞 단계 `reference_handover_trial.launch`의 준비 명령과 다르다.

## MORAI 실행

UDP bridge·camera.launch·asmc_lidar는 [현재 실행 순서](../../../docs/operations/commands.md)를 따른다.
Main의 제거된 start_yolo 인자는 사용하지 않는다.
일반 주행 터미널 5를 다음으로 실행한다. 별도 trial 노드와 동시에 띄우지 않는다.

```bash
roslaunch asmc_planner autonomy_no_bridges_v2.launch \
  highway_merge:=true
```

`highway_merge`의 기본값은 false다. 생략하면 기존 일반 주행의 고주로 정책으로
동작한다. 이 명령은 별도 camera.launch가 세 모델을 실행하는 구성이므로 신호등 중복을 막는다.
대시보드는 함께 시작하며 별도 dashboard.launch는 실행하지 않는다.
재밍 BBox 변환기도 포함한다. 카메라는 현재 v3 보정·해상도에 맞는 설정 해시로 검증한다.
공용 message/MD5, 센서 필터와 MPC는 변경하지 않았다.

## 기존 bag의 소용량 오프라인 검사

ROS 환경 또는 `rosbags`가 설치된 분석 환경에서 객체/상태만 추출한다.
원본 point cloud나 이미지를 복사하지 않는다. 각 객체 도착 시 마지막으로 수신한
차량 상태를 사용하며, 원래 planning timer나 새 제어의 반응을 복원하지 않는다.

```bash
./devel/lib/asmc_planner/highway_merge_preflight \
  src/asmc_planner/config/frenet/params.yaml /tmp/highway_reference.json
python3 tools/planning/extract_highway_shadow.py \
  /root/ws/diagnostics/perception_ab_diagnostics.bag \
  /tmp/highway_reference.json /tmp/highway_frames.json
./devel/lib/asmc_planner/highway_merge_shadow \
  /tmp/highway_frames.json src/asmc_planner/config/frenet/params.yaml \
  > /tmp/highway_shadow.log
```

객체 토픽이 없는 기존 state/control bag으로는 실제 gap을 재평가할 수 없다.
`maintenance=false`는 기록된 현재 상태에서 안전한 접근/제동 궤적도 찾지 못했다는
뜻이다. 과거에 이미 합류한 고정 ego를 PREPARE로 다시 평가한 결과를 새 정책이
실제 그 지점까지 진입했다는 증거로 해석하지 않는다.

## 확인 범위

실제 private HD-map v5와 공식 경로의 native 초기화, 설정·차로 연결 부정 시험,
실제 후보의 앞/뒤/나란한 객체·유효 시각·탐색 한계, 두 zone의 정지/이동 출발과
완료, ROS ProductionRuntime의 요청·승인·실행·KEEP 전이를 검증한다.
ROS 통합 시험은 실제 HD-map 중심선으로 만든 통제된 Behavior map subset과 이상적
궤적 추종을 사용한다. 실제 전체 Behavior JSON과 route 파일도 별도 출발 전 검사로 확인했다.

개발 환경의 ROS 코드는 실제 Noetic 1.17.4 SDK와 frozen 생성 메시지로 빌드했다.
호스트 GCC 13의 SDK 빌드이며 사용자 Docker의 GCC 9 전체 catkin 빌드와 동일하지 않다.
MPC/MORAI 추종, 실제 차량이 있는 합류와 센서 가시범위는 주행 검증이 남아 있다.

| 검사 | 결과 |
|---|---|
| 실제 전체 자산 preflight | Behavior link_set/node_set/route, HD-map·raster·공식 경로, 두 launch 인수 전달, native 초기화 통과 |
| 지도 라이브러리 차이 | 실제 원본 지도와 두 zone 준비가 Boost 1.71 / 1.89에서 통과 |
| 파일·런치·지도 불일치 부정 시험 | 9개 통과 |
| native 실제 지도·잘못된 설정/연결 시험 | 7개 통과 |
| 고주로 실행 | 두 zone × 정지/이동 출발 네 조건에서 최신 승인·COMMIT·후방 차체 통과·KEEP 완료 통과 |
| 실제 ROS 통합 | ProductionRuntime의 PREPARE/READY/EXECUTE/COMMITTED/COMPLETED/KEEP 전이 및 subtype 확인 통과 |
| 기존 기능 회귀 | STOP, FOLLOW, KEEP, AVOID 추종/다중 장애물, 회전교차로, 곡률 연속성, 제동 기억, EMERGENCY 통과 |
| 기존 bag shadow | perception_ab_diagnostics에서 912개 객체 도착 프레임, 약 2.51 MB JSON 추출. 활성 고주로 694개 프레임에서 후보/대기 사유 확인 |

Shadow는 고정된 기록 ego에 PREPARE를 재적용하므로 실제 합류 성공률을 계산하지
않는다. 기록 ego가 이미 진입한 상태에서 PREPARE의 접근 제동이 불가능한 프레임도
포함된다. 프레임 개수는 서로 독립적인 시험 시나리오 수가 아니다.

**연산 지연은 남은 수락 항목이다.** 호스트의 반복 replay에서 30 ms 예산 초과가
여러 번 관찰됐고 일부 호출은 약 0.5초까지 지연됐다. 단계별 CPU 계측 replay에서는
준비 context 1.6 ms 이하, 접근/제동 최대 35.7 ms, 후보 탐색 최대 54.6 ms였으나,
이 한 계측 결과로 앞선 outlier 원인이 해결됐다고 판정하지 않는다. 도구는 wall/CPU
시간을 함께 기록한다. 검사 종료 시 예산을 다시 확인하고, 실제 ROS 확정 직전에도
입력 age를 재검사해 오래된 후보를 승인하지 않는다. 예산 초과 시 진입 대기로
처리하는 기능을 확인했으며, 목표 머신의 궤적 발행 간격·최대 지연과 진입 지연은
MORAI 수락 시험에 남긴다. 기본 비활성인 이유이며 실제 교통에서의 안정성 완료를
의미하지 않는다.

## 2026-10-17 실제 추종 지연에 대한 연결 경로 복구

고주로 참조선 전환은 COMMIT 시 선택한 공간 곡선을 저장한다. 다음 계획에서는
현재 속도·가속도로 종방향 시간표를 새로 계산하면서 이 곡선을 먼저 사용한다.
현재 위치·헤딩·곡률이 `transition_tracking` 허용 범위에 있을 때만 유지하며,
위치 오차와 차체 회전에 따른 최대 모서리 변위를 차체의 네 방향에 추가해
도로·도색·모든 객체의 충돌 검사를 다시 수행한다. 이전의 시간 궤적이나 안전
승인을 그대로 재발행하지 않는다.

곡선을 사용할 수 없으면 현재 위치·헤딩·곡률에서 기존 완료 위치까지 다시
연결한다. 이 연결도 실패하면 현재 속도와 횡이동량으로 계산한 거리, 그 거리의
1.5배를 순서대로 검사한다. 새 완료 위치는 기존 위치보다 앞이고 지도에 설정한
합류 종료 위치 이내여야 한다. 안전한 후보가 선택된 경우에만 곡선과 완료 위치를
갱신한다. 차선 내 안정화와 참조선 인계의 완료 조건은 변경하지 않는다.

정상 추종 중 완료 위치를 매 주기 앞으로 미루거나, 이미 지나간 완료 위치를
현재 위치 2m 앞으로 옮겨 강제로 차선 변경하는 동작을 제거했다. 모든 복구는
같은 COMMITTED transaction 안에서 수행하며, 최신 입력의 시간 검사와 기존
30ms 탐색 예산을 유지한다. 실제 겹침·도로 이탈·운동학 제한으로 안전한 연결이
없으면 기존 제동 경로를 사용한다. 일반 STOP/AVOID/FOLLOW와 회전교차로 경로는
수정하지 않는다.

`highway_transition_recovery_test`는 첫 실패 주행의 실제 추종 지연 상태,
기존 완료 위치를 지나 정지한 차량의 복구, 완료 위치의 무한 이동 방지,
새 객체에 의한 차단, 오래된 입력 거절을 검사한다. 기존 두 고주로 구간의
참조선 인계 시험과 bag 고정 입력 비교를 함께 수행한다. 고정 입력 재생은
새 궤적을 실제 차가 추종했을 때의 완주를 증명하지 않는다.

이 연결 경로 복구 단계에서는 먼 미래의 운동학 검사로 인한 보수적 감속을
별도 과제로 남겼다. 아래 공통 후보 평가 변경에서 실제 발행 구간과 운동학
검사 구간을 일치시킨다. 속도 상한·앞뒤 간격·센서 오차 값은 유지한다.

## 2026-10-17 인계 후 KEEP/FOLLOW의 후방 교통 역할

일반 KEEP/FOLLOW 요청은 현재 참조선의 차로 반폭을 충돌 정책에 명시한다.
현재 차체와 안전마진이 떨어져 있고, OBB 전체가 뒤에 있으며, 같은 참조 차로
안에서 전진하는 객체를 후방 추종 객체로 구분한다. 이 객체의 등속 추돌 예측은
앞 차량의 정지 장애물로 사용하지 않는다. 뒤차가 앞차에 맞춰 간격을 조절하는
정상 추종 상황에 대한 정책이며 뒤차의 실제 감속을 보증하는 예측 모델은 아니다.

모든 객체의 현재 차체·안전마진은 계속 검사한다. 처음부터 옆 차로에 있거나
옆에서 진입하는 객체, 후방 객체가 차로를 벗어난 뒤 다시 진입하는 예측은
기존 충돌 검사를 유지한다. 자차 후보가 현재 참조 차로를 벗어나면 후방 추종
정책을 적용하지 않는다. 차로 밖으로 계속 멀어지는 후방 객체는 진입 객체로
취급하지 않는다. 참조선 끝이나 투영 실패 등으로 이 조건을 확인할 수 없으면
기존 검사를 적용한다. 입력 객체·속도·OBB와 장기 예측 시간은 수정하지 않는다.

후방 역할은 공통 시작 위치에서 한 번 계산하고 각 후보의 차체 영역을 별도로
확인한다. 정상 후보와 KEEP continuity 후보에 같은 정책을 전달한다.
STOP·EMERGENCY·AVOID·회전교차로·고주로 합류 및 차선 변경은 기본 충돌 정책을
유지하며, 합류 전 뒤차 간격 검사는 그대로다. 고주로의 보수적인 저속 후보
선택은 이 변경의 대상이 아니다.

`following_rear_collision_test`는 추종·현재 접촉·전방 장애물·끼어들기·재진입·
곡선·자차 차로 이탈과 production KEEP/FOLLOW 연결을 검사한다. bag 재계산은
기록된 자차 위치가 고정된 오프라인 검증이므로 수정 후 실제 제어·후방 차량
반응과 완주 여부는 MORAI 주행에서 확인해야 한다.

## 원래 차로 접근과 횡방향 예측 회귀

- 고주로 위치 이력 fit은 객체 중심이 속한 HD-map 차로의 접선 방향 속도만 보정한다.
  현재 라이다 횡속도를 유지하되 작은 값이 위치 이력과 모순되면 위의 짧은
  관측 가설로 제한한다. 짧은 OBB 중심 흔들림으로 새로운 장기 차로 침범을 만들지 않는다. 실제 횡이동·역주행·횡단 객체와 초기 물리
  겹침은 계속 검사한다. 원본 객체 메시지나 다른 maneuver의 예측은 변경하지 않는다.
- source 접근은 source 참조선의 local s/d에서 생성한다. 원래 미션 s를
  다른 차로의 local s로 사용하지 않는다. 정상 STOP 생성기는 그대로 공유한다.
- 접근 후보는 공통 `TrajectoryRequest`의 속도 유지·공간 정지·공간 횡방향
  요청으로 생성한다. 최대 세 속도 × 세 시간 × 중앙/현재 횡오차이며,
  정지 계열에는 현재 위치를 포함한 최대 네 정지 위치를 추가한다.
  움직이는 상태에서 불가능한 현재 위치 정지는 생성기가 제외한다. 현재 속도 이하라는
  제한과 첫 유효 후보 선택은 제거했다. 안전 후보의 선택은 아래 접근 비용을
  사용하며 기존 30ms 탐색 예산을 유지한다.
- `highway_source_approach_test`는 기록된 짧은 위치 흔들림을 여러 도로 방향에
  재현하고, 실제 횡단 속도 보존·정적 객체·승인 없는 원래 차로 전진과 마지막
  정지·전체 차체 도로 포함·기동 소유권을 확인한다. 오프라인 이상 추종 시험과
  고정 자차 bag 재계산은 실제 MORAI의 폐루프 추종 검증을 대신하지 않는다.


## 공통 후보 평가와 정지 가능한 전진

고주로 PREPARE는 `GenerateRequestedCandidates`를 통해 일반 STOP과 동일한
공간 정지 생성기와 일반 KEEP의 속도 envelope 생성기, 공통 운동학·충돌
검사 및 `SelectBestPath`를 사용한다. 먼 정지 목표만으로 매 주기 가속도를
풀었다가 다시 가속하는 현상을 방지하도록 두 계열을 같은 비용으로 비교한다.
모드는 source 참조선, 마지막 정지 경계, 공간 횡방향 형상만 지정한다.
공간 후보의 d(s) 형상은 정지 상태에서도 보존하며 제동 연속 경로도 같은
형상을 따라간다. 일반 시간 다항식 후보의 변환과 기존 STOP 생성 기본값은
변경하지 않는다. 짧은 부분 접근 후보 생성은 요청에서 명시적으로 활성화한다.

접근 비용은 현재 도로/교통 상한을 목표로 시간 정규화한 속도 오차·가속도·jerk·
전진 부족·횡오차와 계획 길이를 비교한다. 고정 30km/h 선호 설정은 제거했다.
기존 STOP/AVOID 비용 및 공통 가중치는 변경하지 않는다. 후보의 안전 검사는
비용과 무관한 필수 조건이며 마지막 source 경계 전에 정지할 수 없는 후보는
선택하지 않는다. 합류 후보도 실제로 달성 가능한 가속도로 retiming한 뒤 승인한다.

일반 KEEP는 기존 8초 등속 연속 검사를 통과한 후보를 유지한다. 그 등속
연장 부분에서만 충돌한 후보에는 공통 jerk 제한 제동 연속 검사를 추가한다.
실제 발행할 구간과 제동 경로, 정지 후 예측 구간까지 충돌을 검사한다.
실행 구간 안에서 충돌한 후보를 시간 절단으로 되살리지 않는다. 제동 가능성은
기존 collision-braking fallback과 같은 감속 한계로 검사하며 더 강한 제동을
가정해 후보를 승인하지 않는다. 고주로
접근은 source 경계가 있으므로 등속 대안만으로 승인하지 않고 제동 연속과
전체 차체 도로 포함을 필수로 확인한다. 이 연속 경로는 안전 가능성 검사이며
현재 관측에서 매 주기 새로 계산하는 실제 실행 후보와 구분한다.

일반 STOP·AVOID·일반 LANE_CHANGE·회전교차로는 기존 충돌 정책이 기본값이다.
그 모드들의 예측 신뢰도·안전 여유·비용을 함께 바꾸지 않는다. 아직 MERGE나
FOLLOW 실행 문맥에서 내부 KEEP으로 위임한 경우에도 기존 정책을 유지하고,
FSM이 실제 KEEP으로 전환한 뒤 새 정책을 적용한다. 회전교차로
전용 코드와 승인 조건은 이번 변경에 포함하지 않는다.

고주로 진입은 참조선 연결과 앞뒤 간격 인증을 유지한다. 후보가 목표 차로
정렬과 완료 후 2초를 포함한 구간을 인증하면, 운동학 검사와 도로 검사도
정확히 그 발행 구간에 적용한다. 이후의 발행하지 않을 15초 끝부분 때문에
현재 유효한 연결을 탈락시키지 않는다. 완료 인증이 없는 후보의 미래를
임의로 잘라 승인하지 않는다.

참조선 전환 후보의 속도 envelope는 `RetimeCartesianGeometry`에서 실제
연결 경로의 누적 물리 호길이와 곡률로 계산한다. 원래 미션 s를 목표 차로의
이동 거리로 간주하면 전환 뒤 Cartesian 가속도가 달라져, 짧은 구간은
유효해도 차로 정렬 직후 후속 후보가 사라질 수 있다. 이 공통 retimer는
기존 속도 envelope와 종방향 생성기를 사용하고 공간 연결 형상은 유지한다.
참조선 인계·차선 내 안정화·후속 KEEP 연결 시험에서 두 구간의 연속성을
확인한다.

`stopping_continuation_test`는 먼 등속 충돌과 실제 제동 가능성, 근거리 충돌,
횡단·역주행 객체, 부족한 정지거리, 공간 형상 유지, 기존 안전 후보 보존,
접근 비용과 정지 상태에서의 속도 회복을 검사한다. 기존 모드의 동일 입력
궤적 비교와 bag 고정 입력 재계산을 함께 수행한다. 실제 제어 추종·교통 반응과
완주는 MORAI 폐루프 주행에서 별도로 확인한다.
